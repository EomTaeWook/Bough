# Bough

**한국어** | [English](README.en.md)

**Bough는 병합 충돌을 더 명확하게 이해하고 해결하기 위한 macOS·Windows용 Git GUI입니다.**

일상적인 Git 작업은 가볍고 빠르게 처리하고, 병합 충돌에서는 변경의 맥락과 선택 결과를 쉽게 파악할 수 있는 경험을 지향합니다.

## 왜 Bough인가요?

기존 Git GUI의 충돌 해결 화면에서는 다음과 같은 불편함이 있습니다.

- 충돌한 양쪽 변경이 어디에서 왔는지 직관적으로 알기 어렵습니다.
- 어떤 변경을 선택해야 할지 판단하는 데 필요한 맥락이 부족합니다.
- 선택한 내용이 최종 파일에 어떻게 반영되는지 즉시 확인하기 어렵습니다.
- 여러 저장소가 상단 탭에 쌓이는 방식은 현재 위치를 파악하고 저장소를 전환하기 불편합니다.

Bough는 충돌한 변경의 출처를 분명히 표시하고, 사용자가 선택한 결과를 최종 파일 미리보기에서 바로 확인할 수 있도록 설계합니다.

## 핵심 경험

- **명확한 변경 출처**: 브랜치, 커밋 등 각 변경이 만들어진 배경을 구분해 표시합니다.
- **읽기 쉬운 충돌 비교**: 충돌 구간과 주변 코드를 함께 보여 주어 판단에 필요한 맥락을 제공합니다.
- **즉각적인 결과 미리보기**: 선택한 변경이 최종 파일에 반영되는 모습을 실시간으로 확인합니다.
- **안전한 충돌 해결**: 결과를 검토한 뒤 파일에 반영하고 Git 작업을 이어갈 수 있도록 합니다.
- **명확한 저장소 탐색**: 상단 탭에 의존하지 않고 현재 저장소와 작업 맥락을 쉽게 파악하고 전환할 수 있도록 합니다.

## 주요 기능

- **저장소 복제**: 원격 URL 또는 로컬 경로에서 새 폴더로 복제하고 최근 목록에 등록해 열기
- **로컬 변경**: 변경 파일과 줄 번호가 있는 diff 확인, 스테이징·해제, 커밋, 변경 폐기·추적 중지·무시
- **히스토리와 참조**: 커밋 그래프와 파일 변경 탐색, 브랜치 생성·전환·삭제, 태그 생성
- **원격과 임시 보관**: Fetch·Pull·Push, 기본 Pull 방식 설정과 일회성 방식 선택, Stash 저장·적용·삭제
- **충돌 해결**: 병합·리베이스의 양쪽 변경 확인, 구간별·일괄 선택 또는 직접 편집, 결과 미리보기·저장·스테이징과 리베이스 계속

기능과 사용 흐름은 계속 개선하고 있습니다.

확장 화면과 작업 흐름은 [Design 기획 문서](Design/README.md)에 정리했습니다.

## 기술 방향

- **언어**: C# / .NET
- **플랫폼**: macOS, Windows
- **UI**: Avalonia

프로젝트는 개발 중입니다. 현재 기능과 확인되지 않은 동작은 [구현 현황](Docs/CurrentStatus.md)에 구분해 기록합니다. 개발 문서와 기획 문서는 각각 [Docs](Docs/README.md), [Design](Design/README.md)에서 볼 수 있습니다.

## 실행

.NET 10 SDK와 Git이 필요합니다.

```powershell
dotnet run --project Bough.App/Bough.App.csproj
```

왼쪽 **+ 저장소** 메뉴에서 기존 로컬 저장소를 추가하거나 원격 URL·로컬 경로의 저장소를 복제할 수 있습니다. 복제할 폴더 경로를 직접 입력하거나 찾아보기에서 빈 폴더를 고르면, 완료 후 최근 목록에 등록하고 엽니다. 저장소에 해결되지 않은 충돌이 있으면 충돌 구간별로 변경을 선택하고 최종 파일을 확인하거나 직접 편집한 뒤 **저장하고 스테이징**을 누릅니다. 현재 텍스트 충돌은 UTF-8 파일을 대상으로 합니다.

상단의 **History**를 누르면 모든 로컬·원격 참조의 커밋을 브랜치 그래프로 볼 수 있습니다. 커밋을 선택하면 작성자, 날짜, 메시지와 변경 파일이 상세 패널에 표시됩니다. 처음 200개를 표시하며 목록 아래로 스크롤하면 이전 기록을 이어서 불러옵니다. 커밋을 선택하거나 내용을 살펴보는 것만으로는 저장소가 변경되지 않습니다.

왼쪽 **Git 참조**에서 브랜치를 우클릭하면 로컬·원격 브랜치를 삭제할 수 있습니다. 삭제 전에 대상을 확인하며, 현재 체크아웃된 브랜치와 원격의 기본 브랜치는 삭제할 수 없습니다. 로컬 브랜치는 병합되지 않은 커밋이 있으면 삭제하지 않습니다. 원격 브랜치 삭제는 서버와 다른 사용자에게도 영향을 줍니다.

## 데이터 생성

`Excel/String.xlsx`는 문자열 원본으로 관리할 파일이고 앱은 `Datas/String.json`을 읽습니다. 현재 두 파일의 기존 항목이 완전히 동기화돼 있지 않으므로, 전체 변환기를 다시 실행하기 전에 [데이터 변환 도구 사용법](<Docs/데이터 변환 도구 사용법.md>)의 동기화 주의를 확인하세요.

`JsonToCSharp.exe`는 Git LFS로 관리합니다. 처음 저장소를 받은 뒤 실행 파일이 내려오지 않았다면 Git LFS를 설치하고 저장소 루트에서 `git lfs pull`을 실행하세요.

```powershell
cd ExportTools/ExcelToJson
./ExcelToJson.exe --no-pause
cd ../JsonToCSharp
./JsonToCSharp.exe --no-pause
```

현재 포함된 변환기 버전은 파일을 생성한 뒤에도 `Console.ReadKey` 예외와 함께 종료될 수 있습니다. 이 경우 완료 문구와 산출물 차이를 함께 확인해야 합니다. 화면 문구는 `StringTemplate`에서 읽으며, 운영체제 UI 언어가 한국어면 한국어, 그 외에는 영어를 사용합니다.
