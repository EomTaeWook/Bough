# 구현 현황

이 문서는 현재 코드에 반영된 범위와 남은 검증을 구분한다. 기능별 담당 범위와 실행 계약은 [구현 작업 지시](ImplementationPlan.md)를, 현재 작업 배분·검증 방침은 [AGENTS.md](../AGENTS.md)를 따른다.

## 2026-10-07 선택 커밋 취소(Revert)와 배포 준비

History 커밋 메뉴에서 선택 커밋의 변경을 취소하는 새 커밋을 만드는 Revert를 연결했다. Core는 일반·루트 커밋과 명시적인 병합 기준 부모, 시작 전 작업 상태 확인, 실행 직전 고정 저장소·브랜치·HEAD 확인을 담당한다. 기존 HistoryActionPresenter와 저장소별 FIFO를 사용하며 새 공통 변경 결과·큐·재시도 UI는 추가하지 않는다.

충돌 시 진행 중인 Revert를 유지하고 기존 충돌 해결·저장·스테이징 후 계속하거나 영향 확인 후 중단하는 MainWindow 연결을 반영했다. 저장소 진입·새로 고침·변경 완료에서 상태를 읽고, 중단 확인 시 고정한 초안 뒤에 추가된 편집은 보존한다. REVERT_HEAD는 취소 대상이며 충돌 stage 3의 원본으로 표현하지 않는다. Git 명령의 결과와 후속 조회 오류를 구분하고 대체된 화면에는 늦은 결과를 적용하지 않는다. 신규 한영 문구 40키를 Excel·JSON에 ID3143~3182로 반영했다.

Revert 이전 소스로 생성했던 beta.6 실행 파일은 게시하지 않았다. 최종 소스 `0a0ee0b`를 로컬 커밋한 뒤 Windows x64 자체 포함 단일 실행 파일을 `dotnet publish`로 생성했다. 첫 생성의 메뉴 클릭 연결 오류를 수정해 재생성했으며, 게시에 필요한 커밋·태그 푸시 승인은 대기 중이다. 별도 빌드 검증·테스트·임시 저장소·UI 실행·diff check·리소스 대조는 수행하지 않았다.

## 2026-10-07 초안·늦은 응답 보호와 후속 조회 오류 구분

충돌 저장 요청은 기존 FIFO의 고정 파일·본문으로 실행한다. 요청 뒤 추가한 편집은 저장한 본문과 구분해 남기고, 현재 파일이 충돌 목록에서 사라지거나 남은 충돌이 없어져도 자동 파일 이동·창 닫기로 교체하지 않는다. 명시 이동·닫기의 버리기 확인에는 기존 조회 수명·본문·창 인스턴스를 사용한다. 별도 초안 버전과 파일 선택 세대는 추가하지 않았다.

원격 완료의 각 await 뒤와 MainWindow의 자식 Load/Bind 시작 전, 늦은 오류 표시 전에 기존 요청 버전·저장소 인스턴스를 독립 검사한다. 기존 원격 완료·진행창 계약은 유지하며 새 결과 계층·조회 API·재시도 UI는 제거했다. 원격 후속 오류를 별도 진행창까지 반환하는 개선은 이번 범위에 포함하지 않는다.

성공한 commit/amend 뒤 HEAD 조회가 실패하면 작은 `GitCommitResult`에 SHA와 원래 조회 오류를 담는다. 성공한 stash push 뒤 목록 조회 오류도 기존 `GitStashSaveResult.ReadError`로 전달한다. Presenter는 Git 성공을 유지하며 상세를 읽지 못한 결과에 안전하게 접근하고, Stash의 실패한 목록 조회를 최초 완료 흐름에서 반복하지 않는다.

현재 커밋은 SHA를 읽지 못해도 기존 `Committed(string)`로 완료를 전달한다. 성공과 갱신 오류는 기존 상태 영역에 표시하고 읽기는 기존 새로 고침으로 다시 수행한다. 별도 커밋 완료 이벤트·저장소별 재시도 상태·새 재시도 UI는 추가하지 않았다. Stash의 기존 성공 후 읽기 전용 재시도 계약은 유지했다.

참조 이름 변경 뒤 저장소 조회 실패는 기존 `GitReferenceRenameResult.ReadError`로 구분한다. 삭제·이름 변경의 후속 조회 실패가 성공 bool을 false로 바꾸지 않으며, History Reset·Detached checkout도 Git 성공 뒤 읽기 오류를 기존 상태 영역에 표시한다. 최신 메타데이터를 읽은 결과만 기존 `RepositoryChanged`로 전달하고, 읽지 못한 성공은 원래 저장소 루트의 History dirty 기록만 요청한다. 생성·전환 API 전체의 일반화와 공통 완료·재시도 계층은 이번 수정에서 제외했다.

소스와 한영 문자열에 반영했으며 빌드·테스트·UI 실행·diff check·리소스 대조는 수행하지 않았다. 릴리스 생성은 수행하지 않았다. 완료 변경의 커밋·푸시는 사용자가 명시적으로 요청한 게시 범위로 처리한다.

## 2026-10-07 원격 작업 영역 툴팁 제거

사용자가 Push 아래에 작은 빈 둥근 팝업이 나타나는 화면을 제보했다. 원격 View의 PushAvailabilityText는 안내할 내용이 없을 때 빈 문자열을 반환하고 기존 ToolTip 바인딩이 이 값을 그대로 전달했다. [Avalonia 12.1.3 ToolTipService](https://github.com/AvaloniaUI/Avalonia/blob/12.1.3/src/Avalonia.Controls/ToolTipService.cs)는 null 여부로 표시 대상을 판단하므로 빈 문자열도 팝업 표시 경로에 들어갈 수 있다. 캡처의 팝업이 이 인스턴스인지 실행으로 판정하지는 않았다.

처음에는 빈 문자열·공백 툴팁만 null로 바꾸도록 수정했다. 이후 사용자가 Pull의 기본 방식 안내도 공통적으로 표시하지 않도록 요청해 RemoteOperationsView의 Fetch·Pull·Push 본 버튼과 화살표, 해당 메뉴 항목, upstream·작업 상태·Push 가용성 안내의 툴팁 설정을 모두 제거했다. 앞선 빈 툴팁 정규화 전용 helper와 속성 변경 구독도 제거했다.

화면 상태 문자열·원격 실행·FIFO·메뉴·접근성·기존 지역화는 유지했다. Pull의 현재 기본 방식은 메뉴 표시와 접근성 이름에서 계속 확인할 수 있다. 다른 화면의 툴팁과 공유 문자열은 변경하지 않았다.

이번 소스 변경의 빌드·테스트·UI 실행·캡처·diff check·리소스 대조는 수행하지 않았다. 새 실행 파일·릴리스 생성 및 푸시는 수행하지 않는다.

## 2026-10-07 History 미리보기 순차 처리와 입력 응답성

사용자가 미리보기 로딩 중에도 Changes 파일 우클릭 메뉴를 바로 열 수 있도록 요청했다. 파일 선택 → 조회 → 미리보기 표시를 `HistoryPreviewPresenter`의 한 작업 흐름으로 옮겼다. `HistoryPreviewRequest`가 저장소·커밋 상세·상세 요청 세대·비교 부모·경로·선택을 고정하며 실행 중인 조회 하나와 최신 대기 요청 하나만 유지한다. 새 선택은 이전 조회를 취소하고 이전 종료 뒤 최신 대상으로 이어진다. 읽기 미리보기를 변경 명령의 FIFO 큐에 넣지 않는다.

Core의 파일 내용 조회 전체를 백그라운드에서 시작해 조회 준비·Git 프로세스 실행·내용 해석을 UI 스레드에서 분리했다. VM은 선택과 로딩·본문·사유 바인딩을 유지한다. 저장소·커밋·비교 부모·선택·요청이 바뀐 결과와 오류는 현재 미리보기에 적용하지 않는다.

View는 미리보기 바인딩 적용을 낮은 UI 우선순위로 예약한다. View 분리·모델 교체 때 진행 요청을 중단하며 재연결은 여전히 유효한 중단 요청만 이어서 처리한다. 이미 표시를 마친 미리보기는 재연결 때문에 다시 조회하지 않는다. Changes 목록의 오른쪽 클릭 입력부터 메뉴가 열린 동안 표시 적용을 보류하며 메뉴가 닫힌 뒤에도 대상과 요청을 재확인한다. 메뉴 준비는 기존 메모리의 행 모델·고정 컨텍스트만 사용하고 조회 완료를 기다리지 않는다. 기존 화면 구성·메뉴 동작·외부 Open 독립 수명·파일 히스토리 연결·제한 사유와 지역화는 유지했다.

`GitCommandRunner.RunBytesAsync`는 취소 정리에서 아직 실행 중인 프로세스를 종료한 뒤 취소 토큰 없이 종료를 비동기로 기다리도록 맞췄다. 이전 조회의 프로세스 정리가 끝난 후 다음 조회를 진행하기 위한 최소 변경이며 public API·stdin·Clone 시작 신호는 유지한다.

이번 반영은 소스 구현이다. 사용자 제보 환경의 지연 원인이나 체감 개선을 측정하지 않았으며 빌드·테스트·UI 실행·캡처·diff check·리소스 대조 등 추가 검증을 수행하지 않았다. 새 실행 파일·릴리스 생성과 푸시는 수행하지 않는다.

## 2026-10-07 파일 열기·우클릭 지연·날짜 타임라인

사용자가 Changes 파일 메뉴의 열기 무반응과 간헐적인 우클릭 지연을 제보했다. 기존 Open은 외부 프로그램이 아니라 파일 선택 때 이미 표시한 하단 미리보기를 다시 읽는 경로였다. 사용자가 선택한 기본 편집기·연결 프로그램 실행으로 메뉴 Open을 변경했다. 메뉴 시점 커밋의 임시 읽기 전용 스냅샷을 준비하며 삭제 파일은 고정된 비교 부모의 버전을 사용한다. 작업 파일·인덱스는 변경하지 않고 선택 기반 하단 미리보기는 유지했다.

Core `GitCommitFileActionService.PrepareSnapshotFileAsync`는 기존 원본 바이트·50MiB 내보내기 계약을 사용해 고유 임시 디렉터리의 일반 파일을 준비한다. `GitTemporarySnapshotFile`이 생성 위치를 반환하고 `HistoryExternalFilePresenter`가 취소·요청 버전·상세 대상 수명과 실행 전 대체 결과 정리를 조정한다. View는 Windows 기본 파일 연결 또는 macOS/Linux의 `open`/`xdg-open`을 사용한다. 외부로 전달한 파일은 프로그램의 지연 읽기를 위해 유지하며 전체 임시폴더 정리는 추가하지 않았다. 임시 준비와 연결 실행 오류 두 키를 Excel·JSON에 ID 3132~3133으로 병합하고 기존 GitErrorLocalizer·공통 상태 표시를 사용한다.

메뉴를 여는 `FileContextOpened`에서 동기 `File.Exists`와 작업 경로 계산을 제거했다. 각 항목은 메모리의 고정 행 모델과 현재 상세 수명으로 준비하고 탐색기 클릭에서 작업 파일 존재를 확인한다. 실제 지연 원인과 체감 개선은 측정하지 않았다. 전용 파일 히스토리의 상단 날짜 타임라인·양 끝 날짜·선택 위치 행 및 연결 코드는 제거했으며, 왼쪽 목록의 커밋 날짜와 diff·splitter·취소/닫기는 유지했다.

사용자의 우클릭 확인 발언은 곧 열기 실패 제보로 정정됐다. 릴리스 생성은 중단한 상태이며 새 실행 파일을 만들지 않았다. 이번 소스 변경의 빌드·테스트·UI 실행·추가 검증과 푸시는 수행하지 않았다.

## 2026-10-07 Changes 파일 메뉴 대상 전달 수정

사용자가 Changes 탭의 파일 우클릭에서 열기·탐색기·히스토리·내보내기·경로 복사가 모두 반응하지 않는다고 제보했다. 기존 `FileContextOpened`는 `ContextMenu.PlacementTarget`이 없으면 파일 대상 설정 전에 종료한다. [Avalonia 12.1.3 구현](https://github.com/AvaloniaUI/Avalonia/blob/12.1.3/src/Avalonia.Controls/ContextMenu.cs)은 일반 우클릭의 대상 컨트롤을 내부 Popup에 설정하고 공개 ContextMenu 속성에는 기록하지 않는다. 따라서 정상적으로 보이는 메뉴에 실행 대상이 전달되지 않는 공통 코드 결함을 확인했다.

파일 행 모델을 ContextMenu에 명시적으로 바인딩하고 메뉴를 열 때 각 항목에 고정 저장소·커밋·경로·삭제 상태·상세 요청·비교 부모를 전달하도록 수정했다. 열기·탐색기·히스토리·내보내기·경로 복사는 같은 항목별 컨텍스트를 소비한다. 공개 PlacementTarget 의존과 공유 파일 경로 필드, 메뉴 개수·인덱스 의존은 제거했다. 무효 대상은 메뉴를 비활성화하고 기존 지역화 오류를 표시하며 내보내기의 대기 뒤에도 같은 대상 수명을 확인한다. 전용 FileHistory 창 연결과 기존 Open·Changes 상태는 유지했다.

앞선 전용 파일 히스토리 기록은 창·Presenter 소스 구현이며 실제 파일 메뉴의 동작 완료를 확인한 기록이 아니다. 이번 공통 메뉴 수정도 빌드·앱 실행·추가 검증을 수행하지 않았고 수정된 실행 파일을 생성하지 않았다. 실행 결과가 확인된 상태로 표시하지 않는다. 자동 푸시는 사용자 최신 지시에 따라 중단했다.

## 2026-10-07 History 이동·Stash 완료 연결

커밋 이동의 `HistoryCommitSelectionResult`와 두 `SelectCommitAsync` overload, `ReportCommitSelectionResult` 연결을 완료했다. 요청 저장소·SHA·범위·원래 오류·요청 버전을 보존하며 성공·현재 범위에서 미발견·조회 실패·대체된 요청을 구분한다. 부모 SHA와 내부 이동은 결과를 소비하고 미발견·실패는 History 머리글과 공통 상태에 표시한다. MainWindow 태그는 고정 저장소·전체 범위로 한 번 진입한 뒤 현재 저장소·태그 요청의 결과만 같은 표시 API로 전달한다. 숨긴 History의 참조 변경 상태는 성공한 동일 버전의 조회에서만 해제한다.

선택 기반 미리보기와 명시적 Open의 수명을 분리하고 참조 전환 실패 뒤 저장소·요청 재확인도 반영했다. 기존 Changes 상세 오류와 전용 파일 히스토리는 유지했다.

Stash 창의 현재 요청 집합·Git 성공·미해결 갱신 오류를 분리하고 읽기 전용 갱신 재시도를 연결했다. 성공 뒤 조회 오류가 남은 창은 자동으로 닫지 않으며 읽기 재시도가 Git 보관을 다시 실행하지 않는다. `CompleteStashSaveAsync`는 원래 성공·영향 플래그·입력 오류를 보존한 결과를 반환한다. Save 전용 `RefreshStashSaveWorktreeAsync`는 상태가 없을 때만 한 번 조회하고 현재 적용한 동일 스냅샷을 반환한다. MainWindow도 같은 스냅샷으로 충돌 경로를 적용하고 현재 조회·적용 오류를 반환한다. 과거 큐 오류로 이번 조회 성공·실패를 판단하지 않는다. Apply/Pop/Drop 계약은 유지했다.

Unstaged 메뉴는 메뉴 시점의 저장소·파일 상태·경로를 고정해 변경 버리기·추적 중지·무시로 전달한다. 대상 무효 사유를 기존 지역화 오류로 표시하며 새 선택이나 다른 저장소의 동일 경로로 바꾸지 않는다. 기존 FIFO와 실행 전 Core 검증은 유지했다.

신규 한영 키는 Stash 네 키 ID 3125~3128과 `HistoryNavigationFound`, `HistoryNavigationNotFoundInScope`, `HistoryNavigationFailed` 세 키 ID 3129~3131을 Excel·JSON에 병합했다. 병합 중 이전 워크시트의 예약 XML 네임스페이스 접두사 표기를 수정하고 기존 셀 내용은 유지했다. 빌드·테스트·UI 실행·diff check·리소스 대조 등 추가 검증은 수행하지 않았다.

### History 상세 오류 상태 분리

선택 커밋 상세·변경 파일 조회 오류를 원래 예외로 보관하고 `HasDetailError`·`DetailErrorText`로 표시하도록 반영했다. Commit·Changes 탭에서 같은 상세 오류를 현재 언어의 GitErrorLocalizer로 표시한다. 목록·메뉴의 `ErrorText`가 상세 실패나 성공한 빈 결과 판정에 섞이지 않도록 분리했으며, 기존 로딩·응답 guard·성공 후 빈 상태 판정은 유지한다. 새 문자열이나 외부 API·DI 연결은 추가하지 않았다. 이번 변경은 빌드·테스트·UI 실행·diff check·리소스 대조 등 추가 검증을 수행하지 않았다.

## 2026-10-06 파일 히스토리와 기능 연결 검토

메인 History의 Changes 탭에서 선택 커밋 상세·변경 파일 로딩, 조회 오류, 성공한 빈 결과를 구분해 표시하도록 보완했다. 이전 요청의 완료가 현재 로딩 상태를 해제하지 않도록 요청·저장소·커밋·비교 부모 경계를 유지했다. 기존 `HistoryNoChanges`를 재사용하고 `HistoryLoadingChanges` 한영 키를 Excel·JSON에 추가했다. 이전 보조 패널의 `HistoryFileHistoryLoading`·`HistoryFileHistoryEmpty` 두 키는 추가하지 않았다. 이번 보완은 빌드·테스트·UI 실행·diff check·리소스 대조 등 추가 검증을 수행하지 않았다.

파일 우클릭 히스토리를 별도 창으로 연결했다. 메뉴 시점의 저장소·커밋·경로를 고정하고 창을 즉시 연 뒤 실제 파일 이력을 조회한다. 왼쪽 작성자·시각·SHA·메시지·상태·경로 목록, 날짜 위치 선택, 오른쪽 이전·현재 줄 번호와 추가·삭제 색상의 diff를 제공한다. 이름 변경 당시 경로, 첫 부모/루트 커밋 비교, 조회·빈 상태·오류·비내용 변경 안내와 조회 중단/닫기 취소/늦은 응답 폐기를 연결했다. 현재 목록은 최대 100개다. 한영 16키를 Excel·JSON에 반영했다. 기존 텍스트 보조 이력 패널은 제거했다.

사용자의 파일 히스토리 화면 표시 요청 범위에서 실행 파일을 생성하고 현재 Bough 저장소를 읽어 실제 화면 콘텐츠를 `Docs/images/file-history.png`에 렌더했다. 메뉴 조작·테스트·하네스·회귀 검증은 수행하지 않았다. 이번 기능은 기존 beta.5 배포본에는 포함되지 않는다.

기획 대비 주요 기능의 입력과 완료 경로를 읽어 [기능 진입과 완료 처리 검토](FeatureConnectionReview.md)에 기록했다. 당시 발견한 Stash·History 승인 범위와 충돌 대기 중 추가 초안 보호는 위 2026-10-07 기록에 반영했다. 폴더 열기 busy 무반응과 원격 후속 조회 실패의 진행창 전달 등의 보완은 남아 있다. 이 발견을 모두 수정하거나 실행 재현한 것으로 기록하지 않는다.

당시 Stash 보관 창의 실패 후 재시도·성공 후 갱신 실패 유지·읽기 전용 갱신 재시도와 Unstaged 메뉴의 무효 대상 안내를 작업자 1에게 배분하고, 작업자 3에게 Save 완료 오류 반환 연결을 맡겼다. 이 범위는 위 2026-10-07 기록의 구현에 반영했다. 내용 hunk 없는 변경 안내와 큰 파일 모달 수명 후보는 수정 범위에 포함하지 않았다.

작업자 2의 기능 연결 인계에서 Changes 표시 누락은 위 완료 범위로 분리했다. 커밋 이동 결과, 선택 해제 뒤 미리보기 무효화, 참조 전환 실패 후 저장소·요청 재확인을 작업자 2에게 배분하고 작업자 3에게 태그 이동의 전체 범위 연결을 맡겼다. 이 범위도 위 2026-10-07 기록에 반영했으며 전용 파일 히스토리는 유지했다. 원격 사전 조회 대체의 무음 가능성은 추정·후속 후보로 남긴다. 추가 검증은 수행하지 않았다.

## 2026-10-05 1차 마무리

아래는 소스·문자열 리소스·문서에 반영한 범위다. 사용자 지시에 따라 빌드·테스트·UI 실행·캡처·리소스 대조는 수행하지 않았다.

- **Console**: `ITerminalLauncher`를 통해 OS별 구현을 Singleton DI 등록한다. Windows는 Windows Terminal의 PowerShell과 독립 PowerShell 대체 실행, macOS는 Terminal, Linux는 기존 터미널 실행을 사용한다. 저장소 루트와 설정한 Git 실행 파일의 폴더만 연결하며 배포본 내부 경로를 추측하거나 사용자 환경·셸 프로필을 저장하지 않는다. Windows 시작 시 Git 버전을 표시한다.
- **추적 중지·무시**: 선택한 추적 파일의 경로를 루트 `.gitignore`에 추가하고 인덱스에서 제거한다. 확인과 실행을 저장소 FIFO 작업 하나로 묶고 실행 전에 파일·인덱스·무시 파일 상태를 다시 확인한다. 작업 파일은 보존하며 삭제는 스테이징하고 `.gitignore` 변경은 자동 스테이징하지 않는다. 중복 규칙과 부분 실패를 처리한다.
- **원격 작업 창**: 완료 후 단계·전송·경과 시간을 숨기고 짧은 결과와 실패 이유를 표시한다. 긴 Git 진단과 확인된 Pull 커밋·파일 요약은 접힌 자세히 영역에 둔다. 빠른 전진 불가 오류는 기존 Pull 메뉴의 병합·재배치를 안내하고 기본 전략을 자동으로 바꾸지 않는다. 진단의 민감 정보 제거를 유지한다.
- **충돌 일괄 선택**: 파일 상단에서 현재 파일의 남은 구간에 적용한다. 이미 고른 구간은 보존하고 실제로 바뀐 첫 구간으로 이동한다. 최종 결과에 선택 개수와 별도 저장·스테이징 완료 안내를 표시한다.
- **병합 메시지**: `MERGE_HEAD`가 남아 있을 때 Git의 `MERGE_MSG`를 커밋 입력란에 자동 채운다. 사용자 초안·자동 채움 뒤 편집·삭제한 내용·Amend를 보존하고, 병합 종료·취소 뒤에는 편집하지 않은 자동 메시지만 지운다. Git 메타데이터 위치는 Git으로 조회하며 기존 `--cleanup=verbatim` 정책을 유지한다.
- **작업 큐와 문서**: 내부 `RepositoryLane`을 `RepositoryOperationQueue`로 정리하고 저장소별 FIFO·저장소 간 독립 실행을 유지한다. 현재 아키텍처·코딩 규칙·사용자 흐름과 한영 문자열 원본·JSON을 갱신했다.

## 2026-10-05 Pull 진행 창 후속 정리

성공 후 자동으로 닫히는 Pull 창에서 커밋·변경 파일 요약을 제거했다. Core의 요약용 `rev-list`·`log`·`merge-base`·`diff` 조회와 ViewModel의 요약 상태도 제거하고, 작업 대상·진행 단계·전송 상태는 유지했다. 실패 시 짧은 이유와 접힌 Git 진단을 표시하며, 성공 후 상태 갱신과 자동 닫기·충돌 연결은 기존 흐름을 따른다. 관련 설계·아키텍처 문서를 갱신했으며 빌드·테스트·UI 검증은 미실시다.

## 2026-10-05 Windows Console 후속 정리

Windows Console은 Windows Terminal의 새 창에서 Git Bash를 우선 열도록 변경했다. 설정한 Git 배포본의 `bin/bash.exe`를 사용하며 Git 미지정 시 PATH와 기본 설치 위치를 기준으로 찾는다. 시작 명령은 저장소 루트·Git 경로와 `CHERE_INVOKING`을 전달하고 실제 Git Bash 프롬프트를 사용한다. Bash가 없으면 기존 PowerShell, Terminal 실행 실패 시 독립 콘솔로 이어진다. Windows 구현에만 탐색과 초기화를 두고 OS별 DI 계약을 유지했다. 빌드·테스트·터미널 실행 검증은 미실시다.

## 기존 반영된 기능

- Settings는 OS UI 언어와 독립된 한국어·영어 선택을 제공하며 기본값은 한국어다. `LanguageSelectionPresenter`가 사용자별 `language.json`에 저장한 뒤 공유 `StringHelper.LanguageChanged`를 전파해 즉시 적용한다. `LanguageChangeBinding`은 창·컨트롤 수명과 원격 패널의 주입 시점을 처리하고 라벨·메뉴·툴팁·접근성·목록 항목·키 기반 상태를 갱신한다. 입력·선택을 보존하고 Git을 다시 조회하지 않는다. 레거시 조합 작업 로그는 기존 문구를 보존하며 이번 언어 연결 변경은 검증 미실시다.

- 원격 URL 또는 로컬 경로에서 지정한 새 경로 또는 기존 빈 폴더로 저장소를 복제하고 최근 목록에 등록해 여는 흐름. 임시 bare 원격에서 새 경로·기존 빈 폴더의 실제 복제와 잘못된 목적지 거부를 확인했다.
- 복제 실패는 Git 진단의 고정 패턴을 근거로 인증·원격 권한·저장소 접근·연결·저장공간·로컬 쓰기·목적지 충돌을 분류한다. 근거가 없으면 일반 실패와 종료 코드를 표시하며 민감한 stderr·주소·헤더를 표시하거나 로그·예외 인수로 전달하지 않는다. 프로세스 시작 이후 목적지를 없음·빈 폴더·내용 있음·조회 실패로 구분해 안내하고 자동 삭제하지 않는다. 관련 13키를 Excel·JSON에 반영했으며 이번 변경은 검증 미실시다.
- Local Changes의 diff·줄 선택, 스테이징·해제, 커밋, 변경 폐기·추적 중지·무시와 Stash 작업.
- History의 커밋 그래프·상세·파일 탐색과 브랜치 생성·전환·삭제, 태그 생성과 로컬·원격 태그 삭제. 태그 삭제 후 숨겨진 History는 저장소별 참조 변경 상태를 기록하고 복귀 시 다시 읽도록 연결했다. 이번 MainWindow 연결은 검증 미실시다.
- History 기본 상세는 Commit·Changes 두 탭으로 유지한다. 파일 우클릭의 파일 트리에서 보기와 커밋 우클릭의 File Tree 항목·전용 구분선·클릭 연결을 제거했다. 파일 열기·탐색기·히스토리·다른 이름으로 저장·경로 복사는 유지한다. 기존 파일 트리 보조 화면과 조회 코드는 내부에 남아 있으나 현재 UI 진입 메뉴는 제공하지 않는다. 미리보기 제한 사유는 줄바꿈해 표시한다. 개별 파일 열기 실패 원인은 확정하지 않았으며 이번 변경은 검증 미실시다.

- 저장소별 FIFO Git 작업 큐, 한국어·영어 문자열 리소스, 밝음·어두움 테마.

- `ViewModels`에 섞여 있던 공통 명령은 `Commands`, 완료 인터페이스는 `Interfaces`, UI 스레드 연결은 `Threading`, 자식 화면 구성은 `Composition`, 최근 저장소 저장기·저장 형식은 `Persistence`, 그래프 행 계산기는 `Services`로 분리했다. 커밋·파일·참조·저장소·계정 항목은 기존 `ViewModels/Models`로 모으고 C#·AXAML의 참조를 갱신했다. 기존 실행 로직·명령 계약·DI 수명·저장 형식은 유지하며 이번 구조 정리는 검증 미실시다.
- [UI 간격과 동작 배치](../Design/UIConsistency.md): 담당 화면의 8/12/16px 간격, 32px 버튼, 확인창 버튼 배치와 위험 동작 메뉴 그룹을 정리했다. 사이드바·도구막대·참조·History·Local Changes·Stash·설정과 소유 대화상자를 포함한다. 구현 완료 보고 기준으로 반영하며 별도 검증은 미실시다.
- 저장소 선택을 상단의 현재 저장소 드롭다운으로 옮기고, 옆의 `+` 메뉴에서 기존 저장소 열기·복제 흐름을 연결했다. 저장소 미선택 시에는 중앙 시작 화면에도 두 버튼을 표시하며 Git Settings는 별도로 열 수 있다. 왼쪽은 현재 저장소의 참조 탐색과 공통 상태 영역에 사용한다. 목록에는 저장소 이름만 표시하며 `Source` 같은 상위 폴더 제목을 제거했다. 내부 그룹 모델, 경로 툴팁, 현재 저장소 강조, 제거 버튼의 hover·키보드 포커스 표시와 36px 스크롤바 여백을 유지했다. 이번 배치 변경은 검증 미실시다.

## 이전에 확인한 UI

- 저장소 목록은 최소 1080×700 창의 밝음·어두움 테마에서 스크롤, 키보드 포커스에 따른 제거 버튼 표시, 메뉴 두 항목과 임시 항목 제거를 확인했다. 캡처 당시 오른쪽 여백은 28px이며 최종 소스는 기존 36px을 유지한다.
- 복제 창은 기본 600×400과 최소 480×340에서 긴 오류를 끝까지 스크롤할 수 있고, 어두운 테마의 진행 문구·막대·버튼이 겹치지 않는 것을 확인했다. 캡처 후 기존 폴더에도 맞는 중립적인 목적지 안내 문구를 JSON·Excel에 반영했다.

## 남은 검증과 후속 정리

- 사용자가 제보한 종료 코드 128의 실제 원인은 주소 종류·경로 답변과 재현 없이 확정하지 않았다. 이번 변경은 실패 원인 표시와 목적지 안내를 개선한 것이며 제보 환경의 복제 성공을 확인했다는 뜻은 아니다.
- [저장소 복제](../Design/RepositoryClone.md)의 폴더 선택부터 실행 중 취소 또는 성공 뒤 최근 목록 등록·자동 열기까지 전체 흐름을 실제 UI에서 연속 조작하는 검증은 남아 있다. Core 실제 복제와 창 배치 검증은 완료했다. Git 프로세스 시작 후 실패·취소 때만 목적지의 현재 존재 여부를 표시하며, 해당 위치가 복제 전부터 존재했는지는 판별하지 않는다.
- Local Changes diff를 처음 열 때 텍스트가 자동 선택되지 않는지 실제 최신 앱 화면에서 확인해야 한다. 최신 DLL의 선택 상태와 복사 가능 여부는 확인했으나 작업자 세션에서 정상 창 캡처가 되지 않았다.
- Windows 외 플랫폼에서의 클론·터미널·경로 동작은 별도로 검증해야 한다.
- Conflict 파일 로드·일괄 선택, MainWindow 저장소 전환·공통 상태 문구, RemoteOperationsViewModel 내부 실행·문구 등에는 ViewModel 책임이 남아 있다. 1차 분리를 순수 MVP 완료로 표시하지 않는다.
