Staged 목록도 Ctrl/Shift 다중 선택과 Ctrl+A를 지원하도록 소스를 반영했다. 한 개 화살표와 우클릭 해제는 입력 시점 선택 집합을 고정해 기존 FIFO에서 일괄 해제하고 목록·미리보기를 한 번 갱신한다. 단일 파일·전체 해제와 작업 파일 내용은 기존 동작을 유지한다. 이 변경의 빌드·테스트·UI 실행 등 추가 검증은 수행하지 않았다.

태그 Push는 우클릭과 상단 기본 Push의 공용 선택 창에서 태그 하나·등록 원격을 확인해 전송한다. 원본 태그 객체 OID를 유지하며 같은 원격 객체는 이미 반영된 결과로 처리하고 다른 객체는 덮어쓰지 않는다. 상단의 실행 전 재조회에서 보낼 커밋이 없어진 경우도 기존 브랜치 FIFO 완료 후 연결한다. 선택 창·전송·상단 진입과 14키 공용 문구는 `b5e26f3`에 반영했다. 후속 정정으로 선택 원격에 이미 있는 태그를 전송 후보에서 제외하고 보낼 커밋 또는 확인된 미전송 태그가 있을 때만 상단 본문을 활성화했다. 원격별 조회 중·오류·빈 목록·대체된 결과를 구분하며 첫 Push와 명시적 다른 대상 선택은 유지한다. 기존 Presenter가 이전 후보 조회의 실제 종료 뒤 다음 조회를 시작하고, 상단과 우클릭의 전송 완료는 하나의 TagPushCompleted 알림으로 현재 upstream 원격의 후보를 갱신한다. 태그 창 동안 상단 읽기를 중단하고 종료를 기다리며 복귀 때 현재 요청만 다시 준비한다. 두 작업자의 구현·구독 해제·종료 연결 인계와 추가 7키(ID3270~3276) 병합을 완료했다. 빌드·테스트·UI·실제 원격 전송 등 추가 검증은 수행하지 않았다.

## v1.0.0 이후 소스 반영

공통 사이드바 상태를 최대 두 줄로 표시하고 자세히·전체 복사를 연결했다. 버튼 입력 시 실제 표시된 전체 메시지를 고정하며, 크기 조절 가능한 상세 창에서 읽기 전용 텍스트 선택·Ctrl+A/C와 복사·닫기를 제공한다. 복사 실패도 원문을 유지한 채 상세 창에서 안내한다. 기존 Git 조회·VM 오류 집계·진행·언어·테마를 유지하며 새 오류 계층은 추가하지 않았다.

관련 문구 2키는 Excel·JSON에 함께 반영했다. 빌드·테스트·UI·리소스 대조 등 추가 검증과 새 배포 파일 생성은 수행하지 않았다. 이미 게시한 v1.0.0 실행 파일에는 이 변경이 포함되지 않는다.

## 업데이트 화면의 최신 반영

- `2cf6628`: 설정 버튼 위의 진행 막대를 제거하고 기존 왼쪽 하단 3px 막대에서 다운로드 진행을 표시한다. 전체 크기를 알면 실제 비율, 모르면 무한 진행으로 표시한다.
- 다운로드 중 왼쪽 하단에 GitHub 릴리스 페이지 버튼을 표시한다. 종료 뒤에는 기존 Git·메인 진행 표시로 복귀하며 원격 팝업의 중복 진행 억제는 유지한다.
- `ae52f03`: 설정의 기존 릴리스 페이지 버튼을 **업데이트 후 재시작 바로 옆**으로 옮겼다. 조회 전에도 표시하고 공식 GitHub 릴리스 목록을 연다.
- 두 버튼은 정식 후보 존재나 조회 성공을 요구하지 않는다. 앱 내부 업데이트 후보는 계속 정식 릴리스만 사용한다.
- 기존 다운로드·취소·재시작·사용자 설정 저장 수명은 유지한다. 이 최신 UI 변경은 beta.8 배포 파일에 포함되지 않는다.

동작 계약은 [앱 업데이트](../Design/ApplicationUpdate.md), 표시 배치는 [UI 간격과 동작 배치](../Design/UIConsistency.md)를 따른다.

## 베타 허용 테스트와 제품 정책

- 제품의 앱 업데이트는 공식 정식 릴리스만 사용한다. 베타 허용 승인은 이번 격리 테스트를 위한 것이며 제품 채널 변경이 아니다. 베타 포함으로 제품 소스·문구·문서를 바꾼 해석을 정식 전용으로 바로잡았다.
- 승인된 베타 허용 격리 사본에서 7개 결과가 통과했다. 버전 선택 고정 응답과 실제 공식 beta.8 조회·103,728,744바이트 다운로드·공식 SHA-256 일치·임시 다운로드 정리 기록이다.
- 다운로드 테스트 환경은 독립 test apphost에 배포 환경 입력을 공급했다. 제품 UI·실제 단일 exe 설치 환경·정상 닫기·파일 교체·재시작을 확인한 결과가 아니다. 이번 정책 정정의 추가 빌드·테스트·HTTP 조회·설치·푸시·배포는 수행하지 않았다.
- 이후 별도로 승인된 격리 수동 업데이트에서는 사용자 입력으로 beta.7 앱의 정상 종료, 같은 경로의 exe 교체와 beta.8 재시작·정상 종료를 기록했다. 이 설치 시험은 로컬 후보 응답을 사용했으며, 위 실제 공식 HTTP 다운로드 시험과 한 번에 연결한 결과나 1.0.0 제품 실행·복원 확인은 아니다.

## 실행 경계와 현재 구조

Git·파일·충돌 규칙은 Core, 앱 제품 버전·업데이트는 App 배포 인프라가 소유한다. 기능별 Presenter가 요청·취소·기존 저장소별 FIFO와 완료 조회를 조정하고 ViewModel은 바인딩 상태를 보관한다. 메뉴 대상과 비동기 응답은 저장소·요청·선택 수명으로 고정한다. 이미 성공한 Git 변경은 후속 조회 실패 때문에 재실행하지 않는다.

일반 저장소 전환·일부 화면 조정과 표시 문구는 ViewModel에 남아 있다. 기본 기능을 정식 범위로 정한 사실이 순수 MVP 이행 완료나 모든 작성 규칙 준수를 뜻하지 않는다. 실제 책임은 [현재 아키텍처](AvaloniaMvpAdoption.md), 담당과 유지 계약은 [구현 작업 지시](ImplementationPlan.md)를 따른다.

## 현재 제공 범위의 제한

- Windows x64 단일 실행 파일 배포를 제공한다. macOS/Linux 배포·실행 확인은 포함하지 않는다.
- 텍스트 충돌 편집은 UTF-8 파일을 대상으로 한다. 일괄 처리는 분리할 수 없는 수동 편집 파일을 제외하고 이유를 표시한다.
- 서브모듈 자동 초기화·업데이트·함께 Pull/Push·자동 커밋은 제공하지 않는다.
- File Tree 진입, Blame/Timeline 파일 메뉴, Reset File to는 현재 제공 UI에서 제외한다. 남은 내부 API를 제공 기능으로 계산하지 않는다.
- 앱 내부 터미널과 LFS 실행 메뉴 등 후속 기획을 v1.0.0의 구현 완료 기능에 포함하지 않는다.

업데이트 화면 촬영은 실제 HTTP 조회·다운로드·브라우저 열기·설치·자동 Fetch를 실행한 기록이 아니다. 사용자 앱·설정·저장소 목록은 보존했다.

아래 항목은 미확인 상태 기록이며 새 검증 지시가 아니다.

- 앱 업데이트의 실제 조회·다운로드·정상 종료·교체·재실행·복원 전체 흐름.
- 자동 Fetch, 서브모듈 열기와 최신 충돌·메뉴·완료 흐름의 실제 사용자 환경 동작.
- 사용자가 제보한 Clone 종료 코드 128의 실제 원인. 실패 분류·목적지 안내 개선을 제보 환경의 복제 성공으로 표시하지 않는다.
- Clone 입력부터 취소 또는 성공 후 최근 등록·자동 열기까지의 최신 UI 연속 조작과 Local Changes 초기 diff 선택 상태.
- 최신 전체 코드의 회귀 확인과 Windows 외 플랫폼 동작.

일부 이전 Core 복제·UI 확인과 승인된 화면 촬영은 각 기록의 범위에 한정한다. 검토 당시 발견 목록은 [기능 연결 검토](FeatureConnectionReview.md), 변경 당시 상세는 Git 이력과 [기능 기획](../Design/README.md)을 참고한다. 빌드·테스트·UI·정적 검사·diff check·리소스 대조와 푸시는 [AGENTS.md](../AGENTS.md)의 현재 승인 방침을 따른다.
