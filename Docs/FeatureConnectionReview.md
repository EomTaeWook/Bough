# 기능 진입과 완료 처리 검토

2026-10-06 사용자 요청에 따라 현재 기획과 UI → 입력 처리 → Presenter → Core 연결을 읽었다. 이 문서는 소스에서 확인한 경로와 남은 보완을 기록하며 실행 성공이나 전수 검증을 보증하지 않는다. 빌드·테스트·하네스·UI 동작 검증·diff check·리소스 대조는 수행하지 않았다. 파일 히스토리 화면 제작만 별도의 사용자 요청 범위에서 진행했다.

## 반영한 기능

파일 우클릭 히스토리는 조회 결과를 텍스트로 표시하는 보조 패널에서 [파일 히스토리 전용 창](../Design/FileHistory.md)으로 바꿨다. 창을 즉시 열고 실제 파일 커밋 목록·선택 diff·줄 번호·날짜 위치 탐색을 제공하며 조회 실패도 창 안에서 표시한다. 메뉴 대상 고정과 Core의 명시적인 NUL 경계 변경을 함께 반영했다. 사용자가 제보한 저장소의 과거 무반응 원인을 실행 재현한 것은 아니다.

메인 History의 Changes 탭에는 커밋 상세·변경 파일 로딩과 조회 오류, 성공한 빈 변경 목록을 구분해 표시하도록 반영했다. 이전 요청의 완료가 새 저장소·커밋·비교 부모의 표시 상태를 해제하지 않도록 갱신 수명을 연결했다. 기존 `HistoryNoChanges`와 신규 `HistoryLoadingChanges`를 사용하며 이전 보조 이력 패널의 두 키는 추가하지 않았다. 이 변경은 소스 구현이며 실행 검증은 수행하지 않았다.

## 보완이 필요한 연결

확정은 해당 조건의 제어 흐름을 소스에서 읽었다는 뜻이다. 실제 사용자 환경에서 장애를 재현했다는 뜻은 아니다.

## 진입 위치 또는 지원 정책이 필요한 항목

- **충돌 창의 리베이스 계속**: 현재 실행 진입은 메인 배너에 있다. 충돌 창에는 같은 명령을 제공하지 않는다. 메인으로 돌아가 계속할 수 있으므로 전체 기능 누락과 구분한다. `Design/ConflictEntry.md`의 두 창 제공 문구와 최종 UI 계약을 정리해야 한다.
- **SSH 사용자명 URI**: Clone은 `user@host:path`는 허용하지만 사용자 정보가 있는 URI를 일괄 거부해 `ssh://user@host/path`도 막는다. 비밀번호·토큰 없는 SSH 사용자명을 지원할지 확정해야 한다. 이것을 사용자 제보 종료 코드 128의 원인으로 단정하지 않는다.
- **원격 브랜치 전환 준비 조회**: 같은 저장소에서 조회 버전이 대체되면 `PrepareRemoteBranchCheckoutAsync`의 false를 활성화 handler가 이유 없이 반환할 수 있다. false는 이미 현재·기존 로컬 전환 완료에도 사용된다. 실제 겹침 조건을 재현하지 않았으므로 결과 종류를 분리할 후속 후보로 기록한다.
- **서브모듈 초기화·업데이트**: 현재 참조 행은 상태 조회를 제공한다. 별도 명령·확인 계획을 즉시 제공 기능으로 확정한 것은 아니므로 안전한 쓰기 동작을 조회 행에 임의로 붙이지 않는다.

## 연결이 있는 제공 기능

저장소 열기·복제·최근 목록 등록, Local Changes Stage/Unstage/Commit/Amend/폐기/추적 중지/무시, Stash Save/Apply/Pop/Drop, Git 경로·작성자·계정·언어·테마·Pull 설정, 커밋 그래프·상세·추가 조회·파일 열기/내보내기, 참조 생성·전환·삭제·이름 변경, Fetch/Pull/Push/중단, 충돌 자동 진입·재진입·선택·Save/Stage 및 메인 리베이스 계속의 입력 연결을 읽었다. 연결 존재를 정상 실행 확인으로 표시하지 않는다.

사용자 요청으로 제거한 **File Tree 진입, Blame/Timeline 파일 메뉴, Reset File to**는 현재 제공 기능에서 제외한다. 내부 조회 API가 남아 있다는 이유로 메뉴를 복원하지 않는다. LFS 실행 메뉴와 코드만 복사 등 후속 계획도 현재 누락으로 집계하지 않는다.

## 규칙 검토에서 남은 별도 항목

- Commit/Amend 대기 중 인덱스·HEAD 변화 식별, 계정 선택 대기 중 원격 URL 고정과 저장소 전환 뒤 오류 보존 경계를 보완해야 한다.
- rebase 오류의 원문 진단 표시 인수와 원격 진단의 민감 필드 제거 범위를 정리해야 한다. 실제 비밀 노출을 재현한 것은 아니다.
- 태그 생성·rebase 계속의 busy 입력 정책, 열린 Clone·GitActionDialogs 및 일부 상태의 즉시 언어 변경 연결에 규칙 이행이 남아 있다.
- History 내보내기의 View 직접 조회·저장과 일부 ViewModel 조정은 MVP 경계의 미이행이다. 금지된 삼항 문법·분리되지 않은 독립 가드·enum 배치도 남아 있다. 현재 코드를 순수 MVP 또는 모든 규칙 준수 상태로 표시하지 않는다.

기능 변경과 규칙 정리의 후속 범위는 총괄이 소유권·API를 확정해 기존 담당자에게 배분한다. 위에 반영한 기능으로 기록한 항목 외의 보완 소스는 수정하지 않았다.
