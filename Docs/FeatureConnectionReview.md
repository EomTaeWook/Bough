# 기능 진입과 완료 처리 검토

2026-10-06 사용자 요청에 따라 현재 기획과 UI → 입력 처리 → Presenter → Core 연결을 읽었다. 이 문서는 소스에서 확인한 경로와 남은 보완을 기록하며 실행 성공이나 전수 검증을 보증하지 않는다. 빌드·테스트·하네스·UI 동작 검증·diff check·리소스 대조는 수행하지 않았다. 파일 히스토리 화면 제작만 별도의 사용자 요청 범위에서 진행했다.

## 반영한 기능

파일 우클릭 히스토리는 조회 결과를 텍스트로 표시하는 보조 패널에서 [파일 히스토리 전용 창](../Design/FileHistory.md)으로 바꿨다. 창을 즉시 열고 실제 파일 커밋 목록·선택 diff·줄 번호를 제공하며 조회 실패도 창 안에서 표시한다. 2026-10-07 사용자 요청으로 상단 날짜 타임라인·양 끝 날짜·선택 위치 행을 제거하고 커밋별 날짜는 왼쪽 목록에 유지했다. 메뉴 대상 고정과 Core의 명시적인 NUL 경계 변경은 보존한다. 사용자가 제보한 저장소의 과거 무반응 원인을 실행 재현한 것은 아니다.

메인 History의 Changes 탭에는 커밋 상세·변경 파일 로딩과 조회 오류, 성공한 빈 변경 목록을 구분해 표시하도록 반영했다. 이전 요청의 완료가 새 저장소·커밋·비교 부모의 표시 상태를 해제하지 않도록 갱신 수명을 연결했다. 기존 `HistoryNoChanges`와 신규 `HistoryLoadingChanges`를 사용하며 이전 보조 이력 패널의 두 키는 추가하지 않았다. 이 변경은 소스 구현이며 실행 검증은 수행하지 않았다.

2026-10-07에는 상세 조회의 원래 예외를 공용 목록·메뉴 오류와 분리해 보관하고 Commit·Changes의 `DetailErrorText` 표시로 연결했다. 성공한 빈 변경 목록 판정은 상세 오류만 참조한다. 상세 오류를 현재 언어로 다시 표시할 수 있으며 새 문자열은 추가하지 않았다. 추가 실행 검증은 수행하지 않았다.

커밋 이동은 저장소·SHA·조회 범위·요청 버전과 원래 오류를 담은 결과로 구분하도록 반영했다. 진행 중인 목록 읽기를 기다리고 필요한 페이지를 이어 조회하며 미발견과 조회 실패를 구분해 History 머리글과 공통 상태에 안내한다. 부모 SHA와 내부 이동, MainWindow 태그의 전체 범위 진입과 결과 소비를 연결했다. 선택 해제는 선택 기반 미리보기를 무효화하며 메뉴의 명시적 Open과 수명을 구분했다. 참조 전환 실패 뒤 재조회 완료에도 저장소와 요청 수명을 재확인한다. 이번 구현과 신규 한영 세 키 반영은 추가 검증을 수행하지 않았다.

Stash 창의 실패 후 재시도 성공은 현재 요청 집합을 기준으로 완료하고, Git 보관 성공 뒤 갱신 오류가 남으면 창을 유지한다. 고정 저장소의 읽기만 재시도하며 MainWindow는 입력 성공·오류·영향 플래그와 같은 작업 트리 스냅샷을 보존해 현재 갱신 오류를 반환한다. 과거 큐 오류는 이번 조회 실패로 사용하지 않는다. Unstaged 메뉴도 저장소·파일 대상을 고정하고 무효화 사유를 표시하도록 반영했다. 이번 교차 연결과 한영 네 키 반영은 추가 검증을 수행하지 않았다.

사용자가 Changes 파일 우클릭의 모든 항목이 무반응이라고 재제보했다. `ContextMenu.PlacementTarget`이 일반 우클릭에서 자동으로 채워진다고 가정해 파일 대상 설정을 건너뛰던 공통 코드를 수정했다. 파일 행을 메뉴에 명시적으로 바인딩하고 다섯 항목마다 고정 파일 컨텍스트를 전달하며 무효 대상은 기존 오류로 표시한다. 공유 파일 경로와 메뉴 인덱스 의존도 제거했다. 이 수정은 소스에 반영한 상태이며 새 실행 파일 생성·실행 검증은 수행하지 않았다.

간헐적인 우클릭 지연 제보 뒤에는 메뉴 열기의 동기 `File.Exists` 호출을 제거했다. 메뉴 준비는 메모리의 행 모델과 대상 수명만 사용하고, 탐색기의 작업 파일 존재 확인은 해당 항목 실행으로 옮겼다. 실제 지연 원인이나 개선 시간을 측정하지 않았다. '열기'는 사용자가 선택한 기본 편집기·연결 프로그램 실행으로 변경했다. Core가 고유 임시 읽기 전용 스냅샷을 준비하고 Presenter가 대상·요청 수명을 확인한 뒤 View가 외부 연결을 실행한다. 기존 하단 선택 미리보기는 유지했으며 작업 파일·인덱스를 쓰지 않는다. 오류 두 키도 공유 Excel·JSON에 반영했다. 이번 구현을 외부 편집기의 실제 실행 완료로 보고하지 않는다. 동작 계약은 [커밋 상세](../Design/CommitInspection.md), 소스 반영 상태는 [구현 현황](CurrentStatus.md)을 따른다.

미리보기 로딩 중 입력 응답성을 유지하기 위해 선택 → 백그라운드 조회 → 표시를 `HistoryPreviewPresenter`로 옮겼다. 실행 중인 조회 하나와 최신 대기 선택 하나를 유지하고 이전 취소·프로세스 종료 뒤 최신 파일을 읽는다. 결과는 낮은 UI 우선순위로 적용하며 오른쪽 클릭·파일 메뉴가 열린 동안 표시를 미루고 닫힌 뒤 현재 요청만 소비한다. 기존 화면·고정 메뉴 대상·외부 Open 수명을 유지한 소스 변경이며 실제 지연 해소나 메뉴 응답 시간을 실행 확인한 것은 아니다.

## 2026-10-07 규칙 재검토

현재 관리 소스를 규칙 기준으로 다시 읽었다. 확인된 경로와 발생 조건을 구분했으며 빌드·테스트·하네스·UI 실행·리소스 대조는 수행하지 않았다. 최근 수정한 파일 메뉴·외부 Open·Stash 상위 완료·태그 이동을 이전 상태로 재보고하지 않는다.

- 원격 완료의 각 await 뒤와 자식 Load/Bind 시작 전, 늦은 오류 표시 전에 기존 메인 요청·저장소 인스턴스를 검사하도록 수정했다. 별도 완료 결과·재시도 UI는 추가하지 않았다.
- 성공한 stash push·commit과 참조 이름 변경의 후속 목록·HEAD·저장소 읽기 오류를 변경 성공과 구분하도록 반영했다. 삭제·이름 변경과 History Reset·Detached checkout의 후속 읽기 오류는 성공 bool을 실패로 바꾸지 않고 기존 상태·새로 고침으로 처리한다. 다른 생성·전환 명령의 전체 이행은 이번 범위에 포함하지 않는다.
- 참조 삭제·이름 변경의 완료와 실패 후 복구 조회에서 저장소 바인딩·변경 요청·snapshot 요청을 독립 검사하도록 반영했다. 같은 root로 복귀해도 이전 요청을 현재 화면에 적용하지 않는다. 원래 FIFO 실행과 화면 적용 수명은 구분한다.
- History의 단일 실행·최신 대기·취소·백그라운드 미리보기 조정은 반영돼 있으나 Local Changes·Stash에는 같은 새 공통 실행 규칙의 이행이 남아 있다. 오래된 표시 폐기와 불필요한 조회 취소는 별도 책임이다.
- Stash 결과와 일부 History/References 상태는 번역 완료 문자열만 남아 재번역할 원본이 부족하다. 누락 키 fallback의 raw 키 반환, enum 위치, 삼항 연산자, Settings 독립 guard 결합과 첫 인수 줄바꿈도 명시적 작성 규칙의 잔여 항목이다.

충돌 저장 뒤 추가한 초안은 현재 파일이 목록에서 사라지거나 충돌이 0개가 되어도 자동 파일 로드·창 닫기로 교체하지 않도록 반영했다. 명시 이동·닫기는 본문과 창 수명을 확인한다. 원격 완료 오류를 별도 진행창까지 전달하는 개선·rebase 원문 진단 및 busy 입력 정책·열린 창 지역화는 별도 후속 범위로 남아 있다. 실제 타이밍 장애나 민감 정보 노출을 재현했다고 기록하지 않는다. 이번 소스 변경의 빌드·테스트·UI 실행·diff check·리소스 대조는 수행하지 않았다.

Push 아래 빈 팝업 제보 뒤 처음에는 내용 없는 툴팁을 null로 정규화했다. 이후 사용자 요청으로 Fetch·Pull·Push와 해당 메뉴·상태 영역의 툴팁을 모두 제거했고 정규화 전용 코드도 걷어냈다. 원격 실행·FIFO·접근성은 유지하며 UI 실행으로 팝업 해소를 확인한 것은 아니다.

## 보완이 필요한 연결

승인한 Stash 완료·무효 메뉴 대상과 History 이동·미리보기·참조 실패 경계는 위 구현에 반영했다. Changes 파일 메뉴의 공통 대상 전달도 소스를 수정했다. 기존 소스 연결 검토와 이번 수정은 실제 메뉴 동작 완료를 뜻하지 않는다. 아래 별도 후속 범위와 현재 구현 상태는 [구현 작업 지시](ImplementationPlan.md)와 [구현 현황](CurrentStatus.md)을 따른다.

확정은 해당 조건의 제어 흐름을 소스에서 읽었다는 뜻이다. 실제 사용자 환경에서 장애를 재현했다는 뜻은 아니다.

| --- | --- | --- | --- |
| 중간 | 상단 폴더 열기, 참조 조회·변경 중 | MainWindow 버튼은 저장소 존재만 검사하지만 `References.OpenFolderCommand`는 busy일 때 거부한다. 활성 버튼을 눌러도 handler가 설명 없이 끝날 수 있다. | 2·3: 폴더 열기와 참조 조회 busy를 분리하거나 활성 조건과 결과 표시를 일치시킨다. |

## 진입 위치 또는 지원 정책이 필요한 항목

- **충돌 창의 리베이스 계속**: 현재 실행 진입은 메인 배너에 있다. 충돌 창에는 같은 명령을 제공하지 않는다. 메인으로 돌아가 계속할 수 있으므로 전체 기능 누락과 구분한다. `Design/ConflictEntry.md`의 두 창 제공 문구와 최종 UI 계약을 정리해야 한다.
- **SSH 사용자명 URI**: Clone은 `user@host:path`는 허용하지만 사용자 정보가 있는 URI를 일괄 거부해 `ssh://user@host/path`도 막는다. 비밀번호·토큰 없는 SSH 사용자명을 지원할지 확정해야 한다. 이것을 사용자 제보 종료 코드 128의 원인으로 단정하지 않는다.
- **원격 브랜치 전환 준비 조회**: 같은 저장소에서 조회 버전이 대체되면 `PrepareRemoteBranchCheckoutAsync`의 false를 활성화 handler가 이유 없이 반환할 수 있다. false는 이미 현재·기존 로컬 전환 완료에도 사용된다. 실제 겹침 조건을 재현하지 않았으므로 결과 종류를 분리할 후속 후보로 기록한다.
- **서브모듈 초기화·업데이트**: 현재 참조 행은 상태 조회를 제공한다. 별도 명령·확인 계획을 즉시 제공 기능으로 확정한 것은 아니므로 안전한 쓰기 동작을 조회 행에 임의로 붙이지 않는다.

## 연결이 있는 제공 기능

저장소 열기·복제·최근 목록 등록, Local Changes Stage/Unstage/Commit/Amend/폐기/추적 중지/무시, Stash Save/Apply/Pop/Drop, Git 경로·작성자·계정·언어·테마·Pull 설정, 커밋 그래프·상세·추가 조회·파일 열기/내보내기, 참조 생성·전환·삭제·이름 변경, Fetch/Pull/Push/중단, 충돌 자동 진입·재진입·선택·Save/Stage 및 메인 리베이스 계속의 입력 연결을 읽었다. 연결 존재를 정상 실행 확인으로 표시하지 않는다.

사용자 요청으로 제거한 **File Tree 진입, Blame/Timeline 파일 메뉴, Reset File to**는 현재 제공 기능에서 제외한다. 내부 조회 API가 남아 있다는 이유로 메뉴를 복원하지 않는다. LFS 실행 메뉴와 코드만 복사 등 후속 계획도 현재 누락으로 집계하지 않는다.

## 규칙 검토에서 남은 별도 항목

- Commit/Amend 대기 중 인덱스·HEAD 변화 식별, 계정 선택 대기 중 원격 URL 고정과 저장소 전환 뒤 오류 보존 경계를 보완해야 한다.
- rebase 오류의 원문 진단 표시 인수와 원격 진단의 민감 필드 제거 범위를 정리해야 한다. 실제 비밀 노출을 재현한 것은 아니다.
- 태그 생성·rebase 계속의 busy 입력 정책, 열린 Clone·GitActionDialogs 및 일부 상태의 즉시 언어 변경 연결에 규칙 이행이 남아 있다.
- History 내보내기의 View 직접 조회·저장과 일부 ViewModel 조정은 MVP 경계의 미이행이다. 금지된 삼항 문법·분리되지 않은 독립 가드·enum 배치도 남아 있다. 현재 코드를 순수 MVP 또는 모든 규칙 준수 상태로 표시하지 않는다.

기능 변경과 규칙 정리의 후속 범위는 총괄이 소유권·API를 확정해 기존 담당자에게 배분한다. 위에 반영한 기능으로 기록한 항목 외의 보완 소스는 수정하지 않았다.
