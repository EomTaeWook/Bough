# 데스크톱 응용프로그램 아키텍처 기준

## 목적과 참조 문서

Bough를 Eidolon 같은 데스크톱 응용프로그램의 아키텍처 적용 기준 사례로 사용한다. 이 문서는 다른 앱에서 선택할 책임 경계와 프로젝트 매핑 항목을 소유한다. Bough 전체 코드가 이미 모든 규칙을 충족한다는 뜻은 아니며 구현·미결 상태는 [현재 아키텍처](AvaloniaMvpAdoption.md)와 [구현 현황](CurrentStatus.md)이 소유한다.

공통 C#·데이터·DI·문서 규칙은 [코딩 컨벤션](CodingConvention.md), 재사용 원본의 선택과 Bough 차이는 [재사용 적용](ReusableArchitectureAdoption.md)을 참고한다. 다른 프로젝트에서는 현재 사용자 지시와 해당 프로젝트 지침·구조·데이터 계약을 우선하고 채택한 내용을 자신의 적용 문서에 매핑한다.

## 책임별 대응

| 책임 | 적용 기준 | Bough 사례 |
| --- | --- | --- |
| 업무·외부 실행 | 도메인 규칙과 파일·네트워크·외부 프로세스 실행을 UI에서 분리한다. 실제 유스케이스 소유자가 결과·원본 오류를 반환한다. | Core의 Git·충돌·업데이트 서비스 |
| 사용자 요청 조정 | 실제 요청 순서·취소·결과 적용·작업 수명을 기능별 조정자가 맡는다. 기존 호출·Task 반환을 우선 사용한다. | 목적별 Presenter |
| 표시 상태 | 원본 값·선택·진행·입력 가능 여부·코드형 오류를 보관한다. 실행·저장·번역을 큰 화면 모델에 넣지 않는다. | 기존 ViewModel 바인딩과 화면 항목 |
| 화면 | 입력 전달·지역화·단위/서식·초점·스크롤·표시 구독을 맡는다. | AXAML·코드비하인드·StringHelper |
| 앱 구성과 수명 | 서비스 등록·주입과 화면 생성·분리·종료, 작업·파일 자원 인계를 연결한다. | App·Composition·Program |
| 저장 | 같은 개념의 데이터에 하나의 권위 소유자를 둔다. 인증·설정·목록 등 다른 보안·삭제 수명은 구분한다. | 기존 설정·저장소 목록 저장과 Core 파일 경계 |

기존 UI 프레임워크와 바인딩 타입은 유지한다. 책임 이동 없이 타입 이름만 바꾸거나 전달만 하는 Wrapper·Helper·중계 모델을 추가하지 않는다. 분리 여부는 파일 길이나 메서드 수가 아니라 실제 업무·데이터·실행 수명으로 결정한다.

## 요청과 작업 수명

- I/O와 내용 준비는 UI를 붙잡지 않는 경계에서 수행하고 UI는 await로 순서를 기다리면서 입력을 받는다. UI 스레드의 동기 대기로 순차 실행을 구현하지 않는다.
- 읽기·변경·표시 수명을 구분한다. 선택 미리보기는 최신 요청만 표시하고 이전 작업 취소·종료를 기다린다. 변경 명령의 직렬화가 필요하면 실제 충돌 자원별 실행 경계를 사용한다.
- 접수·실행 시작·실제 변경 성공·후속 조회/표시 완료를 구분한다. 실행 소유자는 필요한 전체 완료까지 기다리고 이미 확정한 변경을 조회 실패 때문에 다시 실행하지 않는다.
- 창·모델·대상·요청이 바뀌면 늦은 결과와 오류를 폐기한다. 화면 수명 취소와 사용자가 접수한 변경의 명시 취소는 같은 신호로 취급하지 않는다.
- 표시 구독은 생성·연결·분리·종료 경계에서 정리한다. 외부 편집기나 설치 담당에 넘긴 파일은 인계한 소비자의 수명을 따르며 View 분리만으로 먼저 삭제하지 않는다.

Bough의 저장소별 Git FIFO·root/SHA/OID·명령 이름을 다른 앱에 복사하지 않는다. 새 앱은 자신이 직렬화해야 하는 자원, 원래 기대값, 취소·부분 성공과 완료 계약을 정한다. 직렬화가 필요 없는 기능에는 새 큐를 만들지 않는다.

## 다른 앱에서 먼저 매핑할 항목

1. 업무별 서비스·원본 상태·저장 데이터와 실제 변경 권위자.
2. UI 프레임워크·바인딩·입력 연결, 화면·요청·작업 수명.
3. DI 구성 위치·자동/명시 등록·서비스/세션 수명과 실제 생성자 소비자.
4. 외부 입력·설정·현재 상태·내부 불변식의 검사 위치와 원래 기대값.
5. 변경 실행 경계, 원본 결과·오류, 다른 화면에 필요한 확정 결과와 읽기 완료.
6. 데이터 원본·생성물·현재 언어·표시 서식과 기존 사용자 데이터 보존.
7. 대상 플랫폼·배포 형식·버전·릴리스 원본·정상 종료·교체/복구 정책.
8. 현재 승인 범위, 남은 연결과 해당 프로젝트의 Git·검증·배포 권한.

원본이 없는 매핑을 Bough의 타입·상수·폴더·URL로 채우지 않는다. 결정되지 않은 정책은 대상 프로젝트에 `[TBD]`로 기록한다. Bough의 단일 파일 배포와 정식 릴리스 업데이트는 채택할 때 참고하는 구체 사례이며 모든 앱에 자동으로 도입하는 필수 기능은 아니다.

## 적용과 완료 보고

새 앱의 요청된 범위에서 선언·호출·상태·등록·저장·결과 연결까지 마친다. 기존 사용자 데이터·미커밋 변경·기능의 런타임 무결성 검사를 보존한다. 완료 보고에는 반영한 경계와 남은 연결, 검증 미실시·승인된 Git/배포 여부를 구분한다.

이 문서를 읽는 요청은 문서 적용 범위다. Bough의 [현재 검증 방침](../AGENTS.md#현재-검증-방침)을 임의로 재개하지 않으며 다른 앱도 자신의 최신 검증 지시를 따른다.
