# 데스크톱 응용프로그램 릴리스 정책

> 카탈로그: [개발 문서](README.md)
> 문서 종류: 공통 배포 정책
> 적용 대상: 단일 실행 파일 배포를 지원하는 데스크톱 응용프로그램

## 기본 배포 형식

- 릴리스의 기본 배포물은 플랫폼·아키텍처별 단일 실행 파일이다. 사용자가 명시적으로 다른 형식을 요청하면 그 요청을 따른다.
- 실행에 필요한 런타임, 관리·네이티브 라이브러리, 고정 데이터와 기본 설정을 실행 파일에 포함한다. 사용자가 DLL·JSON·설정 폴더를 따로 복사해야 하는 배포물을 기본으로 만들지 않는다.
- 필요한 정적 파일은 번들 또는 임베디드 리소스로 포함하고 그 방식에 맞는 로더를 사용한다. 외부 작업 디렉터리나 개발 저장소의 파일에 의존하지 않는다.
- 사용자별 설정, 작업 데이터와 실행 로그는 프로젝트의 기존 저장 정책을 따른다. 실행 중 생성되는 사용자 데이터를 릴리스 파일 안에 저장하려고 하지 않는다.
- 라이선스·저작권 고지는 실행 파일의 리소스와 릴리스 문서 등 적절한 전달 경로에 포함한다.
- 압축 파일을 제공하는 경우 실행에 필요한 배포물은 단일 실행 파일로 구성한다. 디버그 심볼은 기본 사용자 배포물과 분리한다.

## 앱 내부 업데이트를 제공하는 경우

- 업데이트 후보의 배포 채널과 공식 원본을 명시한다. Bough는 공식 GitHub의 게시된 정식 릴리스만 사용하며 초안·사전 릴리스는 제외한다.
- 릴리스 태그와 실행 파일의 실제 버전을 일치시키고 내부 업데이트가 선택하는 플랫폼·아키텍처별 파일명을 사용한다. Bough의 Windows x64 asset은 `Bough-{tag}-win-x64.exe` 또는 `Bough.exe`다.
- 게시된 asset의 SHA-256 digest로 다운로드 길이·내용을 확인한 뒤에만 자동 교체한다. 공식 digest가 없거나 일치하지 않으면 자동 교체를 차단하고 릴리스 페이지를 안내한다.
- 실행·대기 작업과 미저장 초안을 보호하는 정상 종료를 거쳐 교체한다. 기존 파일을 유지하거나 복원할 수 있게 하고 사용자 설정·작업 데이터는 기존 위치에 보존한다.

## .NET 적용

단일 파일·자체 포함 배포와 네이티브 라이브러리 포함을 설정한다. 필수 JSON·설정은 임베디드 리소스 등으로 포함하고 기존 로더 계약을 연결한다. 전체 콘텐츠를 자동 추출하는 호환 모드를 기본으로 사용하지 않는다. 설정 근거는 [Microsoft 단일 파일 배포 문서](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)를 따른다.

```xml
<PublishSingleFile>true</PublishSingleFile>
<SelfContained>true</SelfContained>
<IncludeNativeLibrariesForSelfExtract>true</IncludeNativeLibrariesForSelfExtract>
<DebugType>embedded</DebugType>
```

대상 RuntimeIdentifier, 트리밍과 압축 여부, 실제 데이터·설정 로더와 파일명은 호스트 프로젝트의 배포 문서에서 결정한다. 릴리스 설정 때문에 일반 개발 실행을 불필요하게 변경하지 않는다.

## 게시와 보고

- 실행 파일 생성과 업로드는 사용자가 요청한 배포 작업으로 수행한다. 사용자가 검증을 중단한 상태라면 별도 테스트·UI 검증·하네스·정적 검사·diff check를 임의로 재개하지 않는다.
- 코드 변경은 담당 구현 작업자에게 배분하고 공유 정책·릴리스 문서·다운로드 링크는 총괄이 관리한다.
- 릴리스에는 버전, 대상 플랫폼·아키텍처, 실행 파일명과 실제 다운로드 링크를 적는다. 게시 후 README의 다운로드·실행 안내를 함께 갱신한다.
- 게시된 버전의 배포 형식을 바꾸는 변경은 새 버전으로 제공한다. 기존 버전의 파일을 임의로 덮어쓰지 않는다.
