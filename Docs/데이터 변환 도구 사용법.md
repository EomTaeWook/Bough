# Excel·JSON·C# 데이터 변환 도구 사용법

이 문서는 현재 Bough 저장소에 있는 원본, [ExcelToJson 설정](../ExportTools/ExcelToJson/config.json), [JsonToCSharp 설정](../ExportTools/JsonToCSharp/config.json)과 산출물을 기준으로 한다. 저장소에는 Windows 실행 파일(`.exe`)만 포함되어 있으며 macOS에서 변환기를 실행하는 방법은 확인되지 않았다.

## 원본과 산출물

| 단계 | 현재 파일 | 역할 |
| --- | --- | --- |
| 원본 | [`Excel/String.xlsx`](../Excel/String.xlsx) | `Data`, `Define` 시트가 있는 문자열 테이블 |
| ExcelToJson 산출물 | [`ExportTools/Exported/ClassDefine/String.json`](../ExportTools/Exported/ClassDefine/String.json), [`ExportTools/Exported/Ref/enumRef.json`](../ExportTools/Exported/Ref/enumRef.json), [`Datas/String.json`](../Datas/String.json) | 필드 정의, 참조 정보, 앱에서 읽는 JSON |
| JsonToCSharp 산출물 | [`DataContainer/Generated`](../DataContainer/Generated/TemplateLoader.cs) | `StringTemplate`, `TemplateLoader` 등 생성 C# |

`DataContainer/Generated/*.cs`는 직접 수정하지 않는다. 앱의 [프로젝트 설정](../Bough.App/Bough.App.csproj)은 Debug 실행에서 JSON을 출력 `Datas` 폴더로 복사하고, Release 배포에서는 실행 파일에 포함한다. [TemplateDataLoader](../Bough.App/TemplateDataLoader.cs)는 Debug의 외부 파일 또는 내장 리소스를 기존 `TemplateLoader` 콜백으로 읽는다. 단일 파일 배포에는 별도 `Datas` 폴더가 필요하지 않다.

**원본·산출물 주의:** Excel·JSON의 전체 원본 동기화는 미결로 기록돼 있다. 기존 항목 보존이 정해지기 전에는 변환기를 저장소 원본에 곧바로 실행하지 않는다. JSON의 기존 키가 사라질 수 있다. 현재 신규·변경 문자열은 총괄이 원래 ID와 무관한 기존 항목을 보존하며 Excel·JSON에 함께 병합한다. 이 프로젝트 차이는 [재사용 규칙 적용](ReusableArchitectureAdoption.md)에 명시하며 생성 C#은 직접 수정하지 않는다. 과거 항목 수를 현재 총계로 사용하지 않는다.

검사·대조·빌드는 [현재 검증 방침](../AGENTS.md#현재-검증-방침)을 따른다. 현재는 생성 뒤 구문·참조·행 수·해시·출력·미러 비교나 빌드 검증을 하지 않는다. 원본 편집과 승인된 공식 생성은 요청 산출물 제작이며 별도의 검증 실행과 구분한다.

## 원본 소유권과 변경 범위

- 공유 Excel·JSON의 변경 소유자는 총괄이다. 작업자는 `Name/Kor/Eng`와 자리표시자 의미를 인계하며 같은 공유 파일을 동시에 편집하지 않는다.
- JSON·생성 C#에만 키나 필드를 임의 추가하지 않는다. 새로운 정의가 필요하면 실제 원본의 이름·타입·필수 여부·키를 먼저 읽고 기존 생성 계약을 사용한다. 기존 한영 값 변경은 ID와 자리표시자 의미를 보존한다.
- 현재 제한된 문자열 병합은 기존 JSON 항목을 잃지 않기 위한 원본·산출물 동시 적용이다. 생성 C# 편집이나 전체 원본 교체·새 Catalog·별도 캐시 도입의 허가가 아니다.
- OOXML 직접 편집이 필요하면 해당 셀과 관계만 변경하고 기존 ZIP·시트 구조를 보존한다. 저장 뒤 별도 대조·줄 끝 검사·PDF 미리보기 생성은 하지 않는다.
- 생성이 요청 범위에 포함되고 기존 항목 보존 조건이 갖춰지면 해당 원본 편집과 공식 생성 연결을 마친다. 원본만 바꿔놓고 산출물 반영 완료로 보고하지 않는다. 도구 실행이 막히면 원인과 미생성 범위를 인계한다.

## 실행 순서

두 설정 파일의 경로는 실행 파일 폴더를 기준으로 한 상대 경로다. 원본이나 설정을 바꿔 다시 생성할 때 저장소 루트의 PowerShell에서 다음 순서로 실행한다.

`JsonToCSharp.exe`는 Git LFS로 관리한다. 실행 파일 대신 LFS 포인터가 내려온 경우 Git LFS를 설치하고 저장소 루트에서 `git lfs pull`을 실행한다.

```powershell
Push-Location ExportTools/ExcelToJson
try {
    .\ExcelToJson.exe --no-pause
    $excelToJsonExitCode = $LASTEXITCODE
}
finally {
    Pop-Location
}
```

첫 단계의 실제 생성 성공 또는 도구 오류를 소비해 다음 생성 단계로 진행한다. 도구 오류가 있으면 원본·설정과 미생성 범위를 인계하고 완료로 보고하지 않는다. 별도 출력 대조·검증 실행을 추가하지 않는다.

```powershell
Push-Location ExportTools/JsonToCSharp
try {
    .\JsonToCSharp.exe --no-pause
    $jsonToCSharpExitCode = $LASTEXITCODE
}
finally {
    Pop-Location
}
```

현재 포함된 두 변환기를 임시 복사본에서 `--no-pause`와 함께 실행해도 파일 생성과 완료 문구 출력 후 `Console.ReadKey` 예외로 종료되는 것을 확인했다. 종료 코드만으로 생성 실패를 판정하지 말고, 로그의 변환 오류와 다음 산출물을 함께 확인한다.

## 설정과 생성 계약

[`ExcelToJson/config.json`](../ExportTools/ExcelToJson/config.json)의 현재 경로는 다음과 같다.

| 설정 | 값 | 저장소에서 가리키는 위치 |
| --- | --- | --- |
| `ReadPath` | `..\\..\\Excel\\` | `Excel/*.xlsx` |
| `OutputRefPath` | `..\\Exported\\` | `ExportTools/Exported` |
| `OutputTemplatePath` | `..\\..\\Datas` | `Datas/*.json` |
| `ReadAssemblyPath` | 빈 문자열 | enum 검사 DLL 경로가 설정되지 않음 |

[`JsonToCSharp/config.json`](../ExportTools/JsonToCSharp/config.json)은 `ExportTools/Exported`를 읽고 `DataContainer/Generated`에 C#을 생성한다. `ProjectPath`는 `DataContainer/DataContainer.csproj`, `Namespace`는 `DataContainer`다.

현재 `Excel/String.xlsx`의 `Data` 시트 열은 `Id`, `Name`, `Kor`, `Eng`이고 `Define` 시트 열은 `Name`, `Count`, `Required`, `Type`이다. `Define`의 현재 타입은 `Int32`와 `String`이다. 새 테이블을 만들 때는 실제 통합문서의 두 시트와 변환기 설정을 기준으로 구조를 맞춘다. 현재 파일에 없는 복합 필드나 참조 열의 형식을 추측해 추가하지 않는다.

생성 단계는 필드 정의·참조 정보, 런타임 JSON과 C# 템플릿의 기존 연결을 사용한다. Debug의 출력 `Datas`와 Release의 내장 JSON 로더를 바꾸는 작업은 해당 배포·로더 소유 범위에서 진행한다. 생성 후 일치 여부 검사나 실행 검증을 완료 조건으로 추가하지 않는다.

현재 `enumRef.json`은 비어 있고 `ExcelToJson/config.json`의 `ReadAssemblyPath`도 비어 있다. `ExportTools/ExcelToJson/DataContainer.dll` 파일은 존재하지만 설정에서 사용하지 않으므로, 이 파일만 보고 enum 검증 절차가 활성화됐다고 가정하지 않는다.
