# 브랜치 생성 창의 작업 큐

`GitActionDialogs.RequestNewBranchAsync`는 생성 순간의 이름을 `BranchCreationPresenter`에 전달한다. Presenter는 `Dignus.Collections.ArrayQueue`와 하나의 비동기 소비 루프로 요청을 FIFO 순서에 따라 꺼내 `submit`을 한 번씩 호출한다. `busy` 불리언으로 추가 입력을 조용히 버리거나 두 Git 명령을 동시에 실행하지 않는다. `async Task` 루프는 UI 스레드를 막거나 요청마다 별도 스레드를 만들지 않는다.

진행 상태는 소비 작업과 큐의 상태로 판단한다. 같은 입력을 연달아 눌러도 요청이 누락되지 않게 하고, **성공했다는 이유만으로 이미 큐에 넣은 요청을 폐기하지 않는다.** 입력 순서대로 처리한 뒤 오류가 없다면 창을 닫는다. 실패하면 오류를 창에 표시하고 다음 요청을 처리한다. 취소 버튼이나 창 닫기로 사용자가 명시적으로 취소한 대기 요청은 실행하지 않는다. 이미 시작한 Git 명령은 결과가 나올 때까지 기다리고 처리 중 이름과 대기 수를 표시한다. `busy` 플래그를 다시 만들지 않는다.

창이 닫힌 뒤 지연된 작업이 컨트롤을 갱신하지 않게 한다. 원격 추적 브랜치 생성과 커밋에서 브랜치 생성도 같은 `RequestNewBranchAsync` 경로를 사용하므로 별도의 큐를 만들지 않는다.
