# 서브모듈 저장소 열기

> 관련 화면: [Submodules](GitClientWorkflow.md#submodules), 담당: [구현 작업 지시](../Docs/ImplementationPlan.md#이번-작업-서브모듈-저장소-열기)

## 사용자 흐름

서브모듈의 받기와 올리기는 같은 **저장소 열기** 진입을 사용한다. 참조 트리의 서브모듈 행에서 해당 저장소로 이동한 뒤 기존 Fetch·Pull·Push 버튼을 사용한다. 메뉴 라벨은 기존 `RepositoryAddExistingAction`을 재사용한다.

- 서브모듈 행의 우클릭 메뉴에 **저장소 열기**를 제공한다. 키보드로 메뉴를 열어 같은 명령을 사용할 수 있게 한다.
- 경로와 기존 초기화·커밋 상태 표시를 유지한다. 클릭할 때 Git이나 디스크를 읽어 메뉴 표시를 지연시키지 않는다.
- 선택한 서브모듈이 실제 열린 뒤에는 일반 저장소와 같은 Local Changes·History·참조·원격 화면 및 최근 저장소 목록 흐름을 사용한다.
- Paper-Toss 안의 Blueprints를 열었다면 이후 받기·올리기는 Blueprints의 기존 명령으로 처리한다. Paper-Toss의 명령은 Paper-Toss에서 처리한다.

## 대상과 열기 수명

입력 시 상위 저장소와 서브모듈 상대 경로를 고정한다. Core가 현재 등록 경로와 실제 하위 저장소를 읽어 열 수 있는 절대 경로를 반환하며, 조회 준비·Git 실행·파일 접근은 백그라운드에서 수행한다.

빈 폴더에서 Git이 상위 저장소를 찾아 반환한 결과를 서브모듈 열기 성공으로 사용하지 않는다. `.git` 디렉터리와 gitfile 형식을 지원하고, 미초기화·경로 없음·잘못된 대상은 기존 오류 표시 경계에서 현재 언어로 안내한다. 실제 Fetch·Pull·Push와 체크아웃은 열린 저장소의 기존 명령이 맡는다.

MainWindow는 조회 전후와 기존 충돌 초안 확인 뒤에 현재 상위 저장소·메인 요청 수명을 독립 검사한다. 사용자가 다른 저장소로 이동하면 이전 열기 결과와 오류를 현재 화면에 적용하지 않는다. 조회 오류나 전환 거절로 상위 저장소를 비우거나 이전 선택을 강제로 교체하지 않는다.

## 담당과 인계

- 작업자 2: Reference View·ViewModel·기존 조회 Presenter와 해당 Core의 고정 대상·열기 경로 조회. 메뉴 입력과 실제 API·문자열 계약을 조기에 인계한다.
- 작업자 3: 실제 열기 요청을 받아 기존 충돌 초안 보호·저장소 전환·최근 등록·오류 표시 흐름에 연결한다. Core 검사를 다시 구현하거나 새 Git 큐를 만들지 않는다.
- 총괄: 두 작업자의 실제 API와 문자열 의존을 조정하고 필요한 Excel·JSON 병합 및 문서를 반영한다. 기존 소유권 밖의 파일은 동시에 편집하지 않는다.

현재는 작업 지시와 계약 단계다. 구현 완료·검증 여부는 [구현 현황](../Docs/CurrentStatus.md)을 따른다. 빌드·테스트·UI·임시 저장소·정적 검사·diff check·리소스 대조는 현재 중단 방침을 유지한다.
