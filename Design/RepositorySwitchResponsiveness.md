# 저장소 전환 응답성

## 현재 화면 흐름

`MainWindowViewModel.OpenRepositoryAsync`는 저장소 선택 직후 경로·로딩 상태와 기본 Local Changes 화면을 표시한다. 저장소 루트를 확인한 뒤 Local Changes·참조·원격·리베이스 상태를 영역별 비동기 조회로 시작한다. History와 Git Settings 상세는 해당 화면에서 필요할 때 읽는다. Stash 목록처럼 기본 화면에 당장 필요하지 않은 조회 때문에 저장소 전환 전체를 기다리지 않는다.

사용자가 로딩 중 다른 저장소를 선택하면 요청 버전을 올리고 이전 열기 요청을 취소한다. 자식 영역의 늦은 결과와 오류도 현재 요청 버전·저장소를 확인한 뒤 반영한다. 저장소를 바꾸거나 새로 [복제](RepositoryClone.md)해 열어도 같은 규칙을 적용한다.

## 유지할 품질 조건

- 선택 경로와 기본 화면을 먼저 보여 주고 느린 참조·원격 조회는 각 영역의 로딩 상태로 표시한다.
- 같은 전환에서 작업 트리·Stash 상태를 중복 조회하거나 파일·태그마다 불필요한 Git 프로세스를 만들지 않는다.
- 화면에서 보이지 않는 History·계정 상세를 첫 화면 준비의 필수 대기 작업으로 넣지 않는다.
- 이전 저장소의 완료·실패가 현재 화면을 덮지 않게 하고, 실행 중인 변경 명령은 [저장소별 작업 큐](../Docs/GitOperationQueue.md)의 취소·완료 계약을 따른다.

실제 소요 시간과 대규모 저장소의 지연은 별도 성능 검증에서 측정한다.
