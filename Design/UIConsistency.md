# UI 간격과 동작 배치 정리

## 이번 범위

현재 화면의 간격·버튼·메뉴·아이콘·색상·글씨를 통일한다. 저장소 선택과 열기·복제를 상단과 중앙 시작 화면으로 옮기는 흐름은 [화면과 동작](GitClientWorkflow.md)을 따른다. 기존 기능과 Git 실행·확인·큐·취소 흐름은 유지한다.

사용자 지시에 따라 UI 구현의 별도 빌드 검증·테스트·UI 동작 검증·diff check·리소스 대조는 수행하지 않는다. 각 작업자는 구현 내용과 검증 미실시를 간단히 보고한다. UI 완료 뒤 사용자 요청의 README 화면 캡처는 아래 범위로 진행한다.

## 공통 표현

- 관련 요소 사이 간격은 8px, 영역 내부 여백은 12px, 서로 다른 영역 사이 간격은 16px을 기본으로 사용한다. 기존 최소 크기와 조밀한 목록에 필요한 예외는 유지한다.
- 일반 버튼 높이는 32px을 기준으로 맞춘다. 확인창의 텍스트 버튼은 최소 너비 80px, 버튼 사이 간격 8px을 사용한다. 아이콘 전용 버튼의 기존 클릭 영역과 키보드 포커스 표시는 유지한다.
- 대화상자 하단은 오른쪽 정렬로 취소를 왼쪽, 최종 실행을 오른쪽에 둔다. 실행 버튼은 기존 테마의 주요 동작 표현을 사용한다. 오류·진행·긴 경로가 버튼 영역을 밀어내지 않게 한다.
- 메뉴의 일반 동작은 탐색·열기, 생성·전환·이름 변경, 복사 등 역할별로 모은다. 삭제·변경 버리기·초기화 같은 동작은 구분선 아래에 둔다. 빈 구분선이나 대상에 맞지 않는 항목만 남는 그룹을 만들지 않는다.
- 메뉴 이름에 새 말줄임표·대상 개수·부가 설명을 붙이지 않는다. 영향 설명은 기존 확인창과 툴팁을 사용한다. 사용자 문구를 바꿔야 하면 총괄에 문자열 계약을 전달한다.
- 테마 색과 기존 접근성 이름·툴팁·키보드 조작을 유지한다. 같은 목적의 아이콘은 크기와 정렬을 맞춘다.
- 본문·목록·입력·주요 버튼은 14px, 보조 설명·상태·메타데이터는 12px을 기본으로 사용한다. 글씨를 키울 때 행 높이도 함께 맞춘다. 참조 트리는 최소 32px 행 높이와 위아래 내부 여백 4px을 사용하고, 섹션 앞에 8px 간격을 두어 체크·추가 아이콘이 붙어 보이지 않게 한다. Local Changes diff는 14px 글씨·22px 줄 간격을 사용한다.
- 공통 벡터 아이콘은 `Bough.App/Assets/ActionIcons.axaml`에서 재사용한다. 일반 아이콘은 16px, 펼침 화살표는 10px이며 주요 동작은 아이콘과 라벨을 함께 표시한다. 아이콘·라벨 색은 소유 버튼 또는 메뉴의 선택·비활성 색을 따른다.
- 상단 버튼은 헤더와 같은 바탕을 쓰고 선택된 탐색은 강조색 글자와 하단 2px 밑줄로 표시한다. `+`·탐색·폴더 열기·콘솔 버튼에 별도의 밝은 카드 바탕을 만들지 않는다.
- Staged·Unstaged 머리글은 48px 높이를 사용한다. 스테이징·해제 버튼은 32px 클릭 영역 안의 16px 벡터 화살표로 표시하고 버튼 사이에 8px 간격을 둔다. 변경 폐기 버튼 앞에는 4px 여백을 더 둔다. 빈 목록의 머리글 높이도 같은 값을 사용한다.
- Local Changes의 파일 행은 상태 아이콘과 파일명을 한 줄로 표시한다. 수정은 연필, 추가·삭제는 원 안의 더하기·빼기로 구분하며 상태 설명은 아이콘 툴팁과 접근성 도움말에 둔다. 부분 스테이징·이름 변경·복사·미추적 등은 짧은 상태 문구도 행에 남긴다. 파일 선택·Ctrl/Shift 다중 선택·명령 대상은 기존 파일 모델을 그대로 사용한다.

## 담당별 작업

### 작업자 1: Local Changes·Stash·Git Settings

- 소유 화면의 제목, 입력 영역, 버튼 띠 간격과 정렬을 맞춘다.
- Local Changes와 Stash 우클릭 메뉴에서 일반 동작과 변경 버리기·삭제·추적 중지를 구분한다.
- 소유 대화상자의 취소·실행 버튼 배치를 통일한다. 파일 수, 영향 설명과 직접 편집한 내용은 유지한다.
- 공통 좌하단 결과 표시를 유지하며 개별 화면에 결과 바를 다시 추가하지 않는다.

### 작업자 2: History·Git 참조·공용 대화상자

- 참조 트리의 섹션 제목·아이콘·행 들여쓰기를 정돈하고 기존 접기·펼치기와 행 밀도를 유지한다.
- 브랜치·태그 메뉴의 일반 동작을 모으고 삭제를 마지막 그룹에 둔다. 태그 삭제는 한 메뉴·창 흐름을 유지한다.
- History 메뉴의 생성·복사·체크아웃과 초기화 동작을 구분한다.
- 기본 커밋 상세는 Commit·Changes 두 탭으로 둔다. 커밋·파일 우클릭 메뉴의 파일 트리 진입 항목은 제거한다. 파일 열기·탐색기·히스토리·저장·경로 복사 흐름을 유지한다.
- GitActionDialogs의 제목·본문·입력·오류 간격과 하단 버튼 위치·규격을 통일한다. 메뉴 인덱스와 이벤트의 대상 연결을 구현 변경에 맞춰 유지한다.

### 작업자 3: MainWindow·원격·충돌·복제 창

- 저장소 목록은 상단의 현재 저장소 드롭다운으로 옮기고 이름만 표시한다. 내부 그룹 모델은 유지하지만 `Source` 같은 상위 폴더 제목은 생략한다. 왼쪽은 현재 저장소의 참조 탐색과 공통 상태 영역에 사용한다.
- 상단 저장소 선택 영역 옆 `+` 메뉴에서 기존 저장소 열기·복제 창을 연다. 저장소 미선택 시 중앙 시작 화면에도 두 동작을 표시한다. Git Settings를 보고 있을 때는 시작 화면을 숨긴다. 버튼 간격 8px·최소 높이 32px 등 공통 정책을 유지한다.
- 목록 선택의 저장소 전환과 행의 제거 버튼을 유지한다. 제거 버튼은 hover·키보드 focus 때 표시하며 기존 36px 스크롤바 여백을 유지한다. 목록만 스크롤하고 경로는 항목 툴팁으로 제공한다.
- 상단 도구막대 버튼 높이, 아이콘 크기와 글자 간격을 맞춘다. 폴더 열기의 직접 실행과 기존 원격 메뉴를 유지한다.
- 소유 대화상자의 버튼 띠를 통일한다. 복제 창의 기본 600×400·최소 480×340과 오류 스크롤, 충돌 창의 선택 버튼·편집 영역을 유지한다.

## 작업 경계

공유 테마·리소스·문서·다른 담당자의 파일은 동시에 편집하지 않는다. 기존 담당 세션이 있으면 공용 변경과 소유권을 총괄을 통해 조정한다. 담당 세션을 사용할 수 없으면 [AGENTS.md](../AGENTS.md)에 따라 현재 세션이 필요한 화면·공통 리소스·문서를 직접 수정한다. 공유 문자열 Excel·JSON의 원본·산출물 계약은 유지한다. 화면별로 필요한 스타일만 정리하며 전면적인 UI 재작성으로 확대하지 않는다.

## UI 완료 후 README 갱신

- 총괄은 작업자 1·2·3의 UI 구현 완료 보고를 받은 뒤 작업자 3에게 촬영 시작을 전달한다.
- 최신 변경으로 캡처용 실행 파일을 생성하고 격리된 프로필·데모 저장소에서 밝은 테마의 제품 화면을 촬영한다. History·Local Changes·충돌 해결 화면을 기본 1360×850 크기로 준비한다.
- History는 그래프·참조·선택한 커밋 상세를, Local Changes는 파일 목록·줄 번호 diff·커밋 영역을, 충돌 창은 양쪽 출처·선택 버튼·최종 편집기를 보여 준다.
- 이미지는 `Docs/images/history.png`, `Docs/images/local-changes.png`, `Docs/images/conflict.png`에 반영한다. 로딩 중 상태, 사용자 비밀값과 실제 작업 경로를 노출하지 않는다.
- Windows 화면 복사가 차단되면 총괄 지시에 따라 Avalonia의 실제 화면 컨트롤을 RenderTargetBitmap으로 PNG에 저장한다. 세 화면 모두 시스템 제목표시줄을 제외한 앱 컨텐츠 이미지로 통일할 수 있다. 촬영용 코드는 임시 소스에서만 사용한다.
- 앱 실행·화면 이동은 촬영에 필요한 범위로 제한한다. 추가 테스트나 UI 동작 검증은 실행하지 않는다. 촬영 불가 시 원인과 미완료 상태를 보고한다.
- 작업자 3이 이미지를 전달하면 총괄이 한영 README의 이미지와 설명을 갱신하고 완료된 변경을 커밋·푸시한다.
