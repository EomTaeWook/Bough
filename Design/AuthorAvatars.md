# 히스토리 작성자 아바타

## 목적과 표시 위치

- All Commits의 각 커밋 행에 작은 작성자 아바타를 표시한다. 그래프 선과 커밋 점을 가리지 않는 위치에 두고, 행 높이와 메시지 정렬을 유지한다.
- 선택한 커밋의 **Commit** 상세 상단에는 작성자 정보 옆, 오른쪽에 더 큰 아바타를 표시한다. 작성자 이름·이메일·날짜, 커밋 해시와 메시지를 읽는 공간을 침범하지 않는다. 최소 동작은 상세 화면에서 작성자를 구분할 수 있는 아바타를 항상 보여 주는 것이다.
- 같은 이메일의 커밋은 같은 아바타를 사용한다. 이메일이 없으면 작성자 이름을 기준으로 안정적인 기본 아이콘을 만든다. 툴팁과 접근성 이름에는 작성자 이름을 제공한다.

## 이미지 선택

현재 앱이 그리는 5×5 무늬는 Bough 자체 식별 아이콘이며 Git 호스팅 서비스의 프로필 사진과 같다는 뜻이 아니다. Git 커밋에는 GitHub·GitLab 계정이나 프로필 사진이 들어 있지 않으므로 작성자 이름이나 저장소 원격 소유자만으로 프로필을 추정하지 않는다. 사진 출처를 툴팁이나 상세 정보에 **서비스 프로필 / Gravatar / 로컬 아이콘**으로 구분해 보여 준다.

1. 사진을 기다리는 동안에는 **로컬에서 생성한 식별 아이콘**을 바로 표시한다. 사용자 예시처럼 작성자마다 색·무늬가 일정한 identicon이나 이니셜을 사용한다. 이메일이 없으면 작성자 이름으로 만든다.
2. GitHub 저장소에서 커밋 SHA에 연결된 GitHub 작성자 계정을 확인할 수 있으면 그 계정의 `avatar_url` 사진을 우선한다. GitHub의 [커밋 조회 API](https://docs.github.com/en/rest/commits/commits#get-a-commit)는 공개 저장소의 커밋을 인증 없이 조회할 수 있고, 연결된 `author` 정보에 `avatar_url`을 제공한다. 로컬에서 아직 올리지 않은 커밋, 비공개 저장소의 인증 없는 조회, GitHub 계정과 연결되지 않은 커밋은 이 경로로 확인할 수 없다.
3. 사용자가 GitHub 사용자명과 자신의 **Git 커밋 작성자 이메일**을 명시적으로 연결했다면, 2번에서 계정을 확인할 수 없는 해당 이메일의 커밋에는 지정한 계정의 공개 `avatar_url`을 사용한다. 사용자명만으로 모든 작성자 또는 같은 이름의 커밋에 사진을 붙이지 않는다. 이 연결은 앱의 사용자별 로컬 설정에 저장하고 Git 저장소·문서·코드에 개인 이메일이나 사용자명을 하드코딩하지 않는다. Git 설정의 작성자 이메일을 기본 제안할 수 있지만 최종 연결 대상은 사용자가 확인한다. 이 연결은 GitHub 로그인·인증으로 표시하지 않는다. [GitHub 사용자 조회 API](https://docs.github.com/en/rest/users/users#get-a-user)
4. 앞선 방법으로 사진을 찾지 못한 경우 작성자 이메일에 등록된 Gravatar 사진을 조회한다. 이메일의 앞뒤 공백을 제거하고 소문자화한 뒤 SHA-256 식별자를 만들어 HTTPS로 요청한다. 사진이 없으면 `d=404` 결과를 받아 로컬 아이콘을 유지한다. 이메일 원문은 사진 URL에 넣지 않는다. [Gravatar 아바타 문서](https://docs.gravatar.com/sdk/images/), [식별자 문서](https://docs.gravatar.com/rest/hash/)

사진 우선순위는 **GitHub가 확인한 커밋 작성자 → 사용자가 명시적으로 연결한 자기 계정 → Gravatar → 로컬 아이콘**이다. 사진을 찾았다는 이유만으로 다른 계정의 사진을 작성자에게 붙이지 않는다. 임의의 이메일 검색으로 계정을 추측하지 않는다. 외부 사진 끄기 설정은 GitHub와 Gravatar 요청 모두에 적용한다.

## 로딩과 실패

- 히스토리 목록은 Git 데이터와 로컬 아이콘을 먼저 표시한다. 보이는 행의 사진부터 비동기로 읽고 같은 이메일의 조회 결과는 한 번만 받아 목록과 상세에서 재사용한다. 저장소·선택 커밋이 바뀐 뒤 이전 응답의 사진이 다른 작성자에게 표시되지 않게 한다.
- 네트워크 오류·사진 없음·이메일 없음은 히스토리 오류로 취급하지 않고 로컬 아이콘을 유지한다. 이미지 요청 시간·동시 수·캐시 양에 상한을 둔다. 외부 사진 사용은 기본으로 켜 두되 설정에서 끌 수 있게 하며, 끄면 요청을 보내지 않는다. 요청 URL·로그에는 이메일 원문을 남기지 않는다.
- **External author photos** 체크박스는 클릭 즉시 체크 상태가 바뀌고 목록의 보이는 행과 상세 아바타에 적용된다. 끄면 이미 표시된 외부 사진도 즉시 로컬 아이콘으로 돌아가고 진행 중 응답을 무시한다. 다시 켜면 현재 커밋의 사진을 요청한다. 저장소를 바꾸거나 앱을 다시 열어도 저장된 설정과 화면의 체크 상태가 일치한다. GitHub 사진을 조회할 때 목록과 상세 아바타 모두 커밋 해시와 현재 저장소의 GitHub 원격 주소를 전달한다. 사진이 없어서 로컬 아이콘이 유지되는 경우와 체크박스가 반응하지 않는 경우를 혼동하지 않게 한다.

## 검증 기준

- 작성자가 두 명 이상인 임시 저장소에서 커밋 목록과 상세의 아바타가 작성자별로 구분되고 같은 작성자는 같은 모습인지 확인한다.
- 사진이 등록된 이메일·등록되지 않은 이메일·이메일이 없는 커밋에서 각각 사진 또는 로컬 아이콘이 표시되고 히스토리 로딩·스크롤이 막히지 않아야 한다. 외부 네트워크가 차단되거나 외부 사진 설정을 끄면 로컬 아이콘이 유지된다.
- 계정을 연결하지 않은 상태에서 특정 서비스와 연결되었다는 문구를 표시하지 않는다.
