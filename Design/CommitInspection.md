# 커밋 상세와 파일 탐색

## 목적

History에서 커밋 그래프·목록은 위쪽, 선택 커밋의 Commit·Changes 상세는 아래쪽에 둔다. 커밋·파일 우클릭 메뉴에는 파일 트리 진입 항목을 제공하지 않는다. 두 영역의 높이는 실제 `GridSplitter`로 드래그해 조절하며 각각 독립적으로 스크롤한다. 아래 상세 안에서 사용하는 목록·미리보기 분할선은 이 바깥 스플리터 안에 맞춰 크기를 제한한다.

History에서 선택한 커밋의 내용과 변경 파일을 살펴보고, 그 시점의 파일을 열거나 후속 작업으로 이어진다. 첨부 화면은 정보 구성과 탐색 흐름의 참고 자료다. 기본 탭은 `Commit`, `Changes` 두 개다.

커밋이 한두 개뿐인 저장소에서는 위 목록을 창의 큰 비율로 비워 두지 않는다. 처음 열었을 때 목록의 실제 행 수에 맞춰 필요한 최소 높이만 주고 나머지는 아래 상세에 준다. 커밋이 많을 때는 목록을 적당한 높이까지 늘리고 목록 안에서 스크롤한다. 사용자가 스플리터를 직접 조절한 뒤에는 자동 높이 계산이 그 선택을 덮어쓰지 않는다. 저장소·범위 전환과 추가 로딩 때도 높이 변화 때문에 선택·스크롤·상세 내용이 튀지 않게 한다.

## Commit 탭

- 작성자 이름·이메일, 작성 시각과 시간대, 참조(브랜치·원격·태그), 전체 SHA, 부모 커밋 SHA, 전체 커밋 메시지를 표시한다. 작성자 사진은 표시하지 않는다. SHA와 부모 SHA는 복사할 수 있고 부모 SHA를 누르면 해당 커밋으로 이동한다. 메시지는 한 블록에서 텍스트를 선택해 복사할 수 있으며 별도 **Copy message** 버튼은 두지 않는다.
- 변경 파일별로 접고 펼 수 있는 unified diff를 제공한다. 파일 상태와 이전·현재 경로, hunk 헤더, 이전·현재 줄 번호, 추가·삭제·문맥 줄을 구분한다. **Expand all**은 현재 커밋의 모든 변경 파일 패널을 실제로 펼치고 diff를 읽어야 하며, **Collapse all**은 모두 접어야 한다. 개별 패널 조작과 두 버튼은 같은 펼침 상태를 공유한다. 긴 줄의 가로 스크롤을 제공한다.
- Commit 탭에서 **접힌 파일 패널 머리글**은 현재보다 낮고 촘촘하게 배치한다. 한 파일을 찾기 위해 여러 줄을 스크롤하지 않도록 목표 높이는 약 32~36px, 패널 사이 간격은 약 2~3px로 둔다. 파일 경로 텍스트와 펼침 화살표는 계속 읽고 누를 수 있어야 하며, 긴 경로는 줄임표와 전체 경로 툴팁을 제공한다. 펼친 diff의 내용 여백이나 Changes 탭과 File Tree 보조 화면의 파일 목록 높이까지 함께 줄이지 않는다.
- 보통 커밋은 첫 번째 부모와 비교한다. 루트 커밋은 빈 트리와 비교한다. 병합 커밋은 기본 비교 부모를 명시하고 다른 부모를 선택해 비교할 수 있게 한다. 비교 대상을 바꾸면 변경 파일 목록과 diff를 함께 갱신한다. [Git show 문서](https://git-scm.com/docs/git-show)
- 텍스트가 아닌 파일, LFS 포인터, 너무 큰 diff, 삭제된 파일, 변경 내역이 없는 커밋은 각각 이유가 드러나는 상태를 표시한다. 파일 내용을 텍스트로 해석할 수 없을 때 깨진 문자를 출력하지 않는다.

## Changes 탭

- 선택 커밋 상세와 변경 파일을 조회하는 동안 로딩 상태를 표시한다. 조회 실패는 Changes 탭에서도 현재 오류를 줄바꿈·스크롤 가능한 영역에 표시한다. 성공한 변경 파일 조회가 실제로 비었을 때만 `변경 없음`을 표시하며, 조회 중·실패를 빈 결과로 설명하지 않는다. 저장소·선택 커밋·비교 부모가 바뀌면 이전 요청이 새 로딩·오류·빈 결과 상태를 덮지 않는다.
- 상세·변경 파일 조회 오류는 목록·메뉴 오류와 분리해 보관하고 Commit·Changes 탭에서 표시한다. 상세 조회의 원래 오류를 현재 언어로 표시하며, 목록·메뉴 오류를 상세 조회 실패나 성공한 빈 결과 판정에 섞지 않는다.
- 파일 선택에 따라 시작한 하단 미리보기는 선택 해제 때 요청을 무효화하고 비운다. 늦은 내용과 오류는 같은 파일 선택인지도 확인한다. 우클릭 Open은 메뉴 시점의 고정 스냅샷을 기본 편집기·연결 프로그램으로 여는 별도 요청이다. 다른 파일의 선택 해제는 이 요청을 취소하지 않으며, 준비 중 저장소·커밋·비교 부모가 바뀌면 이전 대상을 실행하지 않는다. 이미 외부 프로그램으로 연 임시 파일은 메인 선택 변경으로 삭제하지 않는다.
- 부모 SHA 이동은 현재 History 조회 범위를 유지하고 성공·해당 범위에서 미발견·조회 실패·다른 요청으로 대체를 구분한다. 진행 중 조회를 건너뛴 결과를 미발견으로 단정하지 않는다. 미발견과 실패는 현재 화면과 공통 상태에 안내하고, 대체된 요청은 새 상태를 덮지 않는다.
- 이동 결과에는 저장소·SHA·범위·원래 오류와 요청 버전을 보존한다. 결과 표시는 한 API로 연결하고 목록·상세 오류와 별도의 이동 안내를 사용한다. 성공은 이전 이동 안내를 지우고 공통 상태에 표시한다. 미발견·실패 안내는 긴 내용을 스크롤할 수 있도록 머리글 아래에 표시하며 현재 요청으로 대체되면 이전 안내를 지운다.
- 상단에 선택 커밋의 작성자·짧은 SHA·작성 시각·메시지 첫 줄을 보여 준다. 검색창으로 변경 파일의 저장소 상대 경로를 찾는다.
- 추가·수정·삭제·이름 변경 등 상태를 파일마다 구분한다. 이름 변경은 이전 경로와 새 경로를 모두 확인할 수 있어야 한다. 파일 선택은 해당 파일의 diff 또는 내용 미리보기로 연결한다.
- 변경 파일 목록과 아래 파일 미리보기는 각각 자신의 영역 안에서 스크롤한다. 긴 파일을 선택해도 미리보기가 창 하단 밖으로 늘어나거나 내용이 잘려 사라지면 안 된다. 두 영역 사이의 가로 분할선으로 미리보기 높이를 조절할 수 있고, 창 크기가 바뀌어도 최소 높이를 지킨다.
- Git 출력은 기계 판독용 NUL 종료 형식을 우선 사용하고 UTF-8 경로를 보존한다. 검색과 선택은 화면에 보이는 경로와 실제 Git 경로가 일치해야 한다. [Git show 문서](https://git-scm.com/docs/git-show)

## File Tree 내부 구현

- 사용자 요청으로 커밋 우클릭의 File Tree와 파일 우클릭의 파일 트리에서 보기 진입 항목을 제거했다. 아래 내용은 내부에 남아 있는 보조 화면·조회 코드의 계약이며 현재 UI의 메뉴 흐름으로 제공하지 않는다.
- 선택 커밋의 트리를 폴더 계층으로 보여 준다. 검색, 폴더 접기·펼치기, 파일 선택을 제공한다. 파일을 선택하면 그 커밋의 파일 내용을 읽기 전용으로 연다. 같은 폴더의 조회가 이미 진행 중이면 그 결과를 기다리고, 조회 도중 폴더를 접어도 현재 커밋의 자식 목록은 보관해 다시 펼칠 수 있게 한다.
- File Tree의 트리와 아래 파일 미리보기에도 Changes 탭과 같은 크기 제약·독립 스크롤·높이 조절을 적용한다. 긴 줄은 가로 스크롤로 확인한다.
- 파일 트리 목록은 현재 작업 폴더가 아니라 **선택 커밋의 스냅샷**이다. 파일이 현재 디스크에 없어도 트리에서는 볼 수 있다. 서브모듈은 일반 파일처럼 내용을 열지 않고 gitlink와 대상 커밋을 표시한다. [Git ls-tree 문서](https://git-scm.com/docs/git-ls-tree)
- 텍스트 미리보기는 현재 Core 계약에 따라 최대 1MiB의 UTF-8 텍스트를 읽는다. 바이너리·용량 초과·지원하지 않는 인코딩·서브모듈 등은 기존 지역화된 사유를 미리보기 위에 줄바꿈해 표시한다. 파일 이름을 받은 재현 없이 특정 사용자의 열기 실패 원인을 이 제한으로 확정하지 않는다.

## 파일 우클릭 메뉴

메뉴는 파일이 가리키는 커밋과 저장소 상대 경로를 명확히 사용한다. 선택이 바뀌었거나 저장소가 전환되면 이전 메뉴의 비동기 결과를 적용하지 않는다.

| 메뉴 | 동작 |
| --- | --- |
| Open | 선택 커밋의 파일 스냅샷을 임시 파일로 준비해 OS 기본 편집기·연결 프로그램으로 연다. 현재 작업 파일을 대신 열지 않는다. 삭제 파일은 고정된 비교 부모의 이전 버전을 사용한다. |
| Show in File Explorer | 현재 작업 폴더의 파일 위치를 연다. 메뉴 표시는 파일 존재 조회를 기다리지 않으며 실행 시 같은 고정 대상의 존재를 확인한다. 없는 파일은 기존 오류로 안내한다. |
| History | [파일 히스토리 창](FileHistory.md)을 바로 연다. 왼쪽 커밋 목록에서 선택하고 오른쪽 줄 번호 diff를 표시한다. 이름 변경을 따라 당시 경로를 조회한다. |
| LFS | 저장소와 파일에 LFS가 적용될 때 가능한 명령만 표시한다. 실제 지원이 준비되기 전에는 실행 항목을 노출하지 않는다. |
| Save as… | 선택 커밋의 파일을 사용자가 고른 위치에 내보낸다. 기존 파일 덮어쓰기는 별도 확인한다. |
| Copy Path | 저장소 상대 경로를 복사한다. |

이 파일 메뉴에는 `Show in File Tree`, `Reset File to…`와 `Blame / Timeline`을 넣지 않는다. 커밋·브랜치 우클릭의 현재 브랜치 초기화는 [별도 동작](CommitActions.md)으로 유지한다.

메뉴를 여는 입력 경로는 메모리의 행 모델과 고정 대상만 사용한다. 동기 파일 존재 조회나 Git 실행으로 UI 스레드를 기다리게 하지 않는다. 실행 시 필요한 파일 조회는 메뉴 준비와 분리하고 결과를 소비하기 전에 같은 대상인지 확인한다. 사용자가 제보한 간헐적 지연의 실제 시간이나 원인은 실행 측정 없이 확정하지 않는다.

외부 열기의 Git 내용 조회와 임시 파일 쓰기는 Core, 준비 요청·대상 수명은 Presenter, 연결 프로그램 실행과 오류 표시는 View의 책임이다. 임시 파일은 요청마다 고유 위치의 일반 파일로 만들고 원래 확장자를 유지하며 읽기 전용으로 둔다. 원래 파일명을 우선 사용하고 OS에서 불가능한 문자·예약 이름만 안전하게 변환한다. 작업 트리·인덱스는 변경하지 않는다. 외부 프로그램의 지연 읽기를 위해 성공 직후 파일을 삭제하지 않으며 전체 임시폴더 정리는 이번 범위에 추가하지 않는다. 내용 조회·임시 파일 생성·연결 프로그램 실행 실패는 사용자에게 표시한다.

## 데이터와 화면 계약

- 조회 서비스는 커밋 메타데이터, 비교 부모, 변경 파일 상태·경로, 파일별 diff, 커밋 트리, 파일 내용을 분리해 제공한다. 큰 diff와 트리는 파일 또는 폴더 선택 시 지연 조회한다.
- 파일 목록·트리·diff는 Git 출력의 인코딩과 경계 형식을 지키며 한글·공백·특수 문자 경로를 보존한다. 화면에서 선택한 저장소, 커밋, 비교 부모가 응답 시점에도 같을 때만 결과를 적용한다.
- Dignus 자료구조는 이미 쓰는 패턴에 맞춰 추가 중심 조회와 그래프 구성에 활용한다. 동일 데이터를 배열로 다시 보관하는 중복 캐시는 만들지 않는다.
- 커밋 파일 조회는 읽기 전용이다. `Save as…`는 사용자가 고른 위치로 내보내며 작업 트리나 인덱스를 변경하지 않는다. Git 명령은 저장소 루트에서 인수 배열로 실행하며, 사용자 경로를 셸 문자열로 이어 붙이지 않는다.

## 검증

현재는 [AGENTS.md](../AGENTS.md)의 사용자 검증 중단 지침을 우선한다. 이번 메뉴 이동과 조회 조정은 코드에 반영했으며 아래 절차를 실행하지 않았다.

- 커밋·파일 우클릭 메뉴에 File Tree와 Show in File Tree 항목이 나타나지 않으며, 남은 생성·체크아웃·복사·초기화와 파일 동작이 유지되는지 확인한다.
- 임시 저장소에서 루트·일반·병합 커밋, 추가·수정·삭제·이름 변경, 한글·공백 경로를 선택해 목록과 diff가 실제 Git 결과에 맞는지 확인한다.
- 바이너리·큰 파일·서브모듈·현재 작업 폴더에 없는 파일은 올바른 상태 또는 비활성 메뉴를 보여 준다.
- 저장소·커밋·비교 부모를 빠르게 바꾸어도 이전 비동기 응답이 현재 상세 화면을 덮지 않는다.
- 긴 텍스트 파일을 Changes와 File Tree에서 각각 열어 마지막 줄까지 세로 스크롤로 확인하고, 긴 줄은 가로 스크롤로 확인한다. 창 높이를 줄이거나 아래 미리보기 크기를 조절해도 파일 목록과 미리보기 내용이 창 밖으로 잘리지 않는다.
- 변경 파일이 여러 개인 커밋에서 Expand all·Collapse all을 눌러 모든 파일 패널의 실제 표시 상태가 바뀌는지 확인한다. 개별 파일을 열고 닫은 뒤에도 두 버튼과 펼침 상태가 일치해야 한다.
- 파일 우클릭 메뉴에 `Reset File to…`와 `Blame / Timeline`이 나타나지 않으며, `History`와 `Save as…`는 정상 동작한다.
