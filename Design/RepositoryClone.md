# 저장소 복제

## 진입과 입력

왼쪽 저장소 목록 아래 **복제** 버튼에서 복제 창을 바로 연다. 헤더에는 저장소 제목만 표시하며, 기존 로컬 저장소는 옆의 **저장소 열기** 버튼으로 연다. 배치는 [화면과 동작](GitClientWorkflow.md)을 따른다. 복제 창에서 원격 URL 또는 로컬 저장소 경로와 **복제할 폴더 경로 하나**를 입력한다. 찾아보기에서 고른 폴더 자체가 복제 위치다. 직접 경로를 입력할 때는 아직 없는 새 폴더도 지정할 수 있다. 복제 전에는 현재 저장소와 최근 목록을 바꾸지 않는다.

HTTPS, SSH, Git 프로토콜, `file://`, Git의 `user@host:path` 형식과 로컬 디렉터리를 지원한다. URL의 사용자 정보·쿼리·조각에 자격 증명을 넣지 않게 안내한다. Bough가 토큰을 받거나 저장하지 않고 설정된 Git 실행 파일과 Git의 기존 인증 도우미·SSH를 사용한다. 목적지의 상위 폴더가 없거나 목적지가 루트·파일·비어 있지 않은 폴더이면 Git을 실행하지 않는다. **아직 없는 새 경로와 이미 존재하는 빈 폴더를 모두 복제 위치로 지원한다.**

## 실행과 결과

복제 요청은 **목적지 절대 경로를 키로 하는 저장소별 Git 작업 큐**에 넣는다. 실행 차례에 입력과 목적지를 다시 검사하고, 목적지의 상위 폴더에서 `git clone --progress -- <주소> <목적지>`를 인수 배열로 실행한다. 대기·실행·취소·실패 상태는 복제 창에 표시한다. Git의 진행 출력에 퍼센트가 있으면 현재 전송 단계의 수치로 표시하며 전체 파일 다운로드율로 설명하지 않는다. 진행 출력이 없더라도 실행 중임을 표시한다.

중단은 실행 중 Git 프로세스에 취소를 요청한다. **종료 코드 128만으로 목적지가 비어 있지 않다고 단정하지 않는다.** 실제 Git 실패에 대응하는 안정적인 오류 코드와 필요한 인수를 전달하고, 앱 표시 경계에서 현재 언어의 문구로 실패 이유를 알린다. 원인을 식별할 수 없으면 확인되지 않은 이유를 추정하지 않고 일반 실패 코드로 안내한다. 오류 화면과 로그에는 자격 증명이 포함된 URL이나 민감 정보가 들어갈 수 있는 Git stderr 원문을 그대로 노출하지 않는다.

Git 프로세스의 **실행 시작 신호를 받은 뒤** 실패하거나 취소된 경우에만 목적지 상태를 조회해 다음과 같이 후속 안내를 구분한다. 대기 중 취소나 실행 전 입력·목적지 검사 실패에는 잔여 파일 안내를 표시하지 않는다.

| 실행 이후 목적지 상태 | 후속 안내 |
| --- | --- |
| 목적지 없음 | 현재 목적지 경로가 존재하지 않음을 알린다. |
| 빈 폴더 | 현재 폴더가 비어 있으며 다시 복제를 시도할 수 있는 위치임을 알린다. 빈 폴더를 잔여 파일이 있는 위치처럼 설명하지 않는다. |
| 내용 남음 | 현재 목적지에 내용이 있음을 알리고 사용자가 직접 확인하도록 안내한다. |
| 조회 실패 | 목적지 상태를 확인할 수 없음을 알린다. 존재하지 않거나 비어 있다고 추정하지 않는다. |

이 후속 안내는 복제 실패 이유와 구분해 표시한다. 다른 프로세스가 만든 파일이나 폴더도 있을 수 있으므로, 현재 존재하는 내용을 Bough가 만들었다고 단정하지 않는다. **파일이나 폴더는 자동 삭제하지 않는다.** 성공하면 복제한 경로를 최근 저장소 목록에 등록하고 해당 저장소를 연다. 복제에는 성공했지만 열기에 실패하면 복제 결과와 열기 실패를 구분해 알린다.

저장소 전환 전에 충돌 해결 창에 미저장 편집이 있으면 기존 저장소 전환 확인 흐름을 따른다. 현재 저장소가 선택되지 않아도 복제 진입과 실행이 가능하다. 복제 창을 닫거나 입력 검증에 실패한 경우 현재 화면과 저장소 목록은 그대로 둔다.

## 관련 개발 문서

실패 이유와 목적지 상태의 코드·표시 경계는 [Git 오류 다국어 처리](../Docs/GitErrorLocalization.md)를 따른다. 구현 상태와 제보된 실패 원인의 확인 여부는 [구현 현황](../Docs/CurrentStatus.md), 작업 배분과 검증 실행 정책은 [AGENTS.md](../AGENTS.md)에서 관리한다.
