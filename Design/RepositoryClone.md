# 저장소 복제

## 진입과 입력

왼쪽 저장소 제목 옆 **+** 메뉴에서 기존 로컬 저장소 추가 또는 복제를 선택한다. 복제 창에서 원격 URL 또는 로컬 저장소 경로와 **복제할 폴더 경로 하나**를 입력한다. 찾아보기에서 고른 폴더 자체가 복제 위치다. 직접 경로를 입력할 때는 아직 없는 새 폴더도 지정할 수 있다. 복제 전에는 현재 저장소와 최근 목록을 바꾸지 않는다.

HTTPS, SSH, Git 프로토콜, `file://`, Git의 `user@host:path` 형식과 로컬 디렉터리를 지원한다. URL의 사용자 정보·쿼리·조각에 자격 증명을 넣지 않게 안내한다. Bough가 토큰을 받거나 저장하지 않고 설정된 Git 실행 파일과 Git의 기존 인증 도우미·SSH를 사용한다. 목적지의 상위 폴더가 없거나 목적지가 루트·파일·비어 있지 않은 폴더이면 Git을 실행하지 않는다. 이미 존재하는 빈 폴더는 복제 위치로 사용할 수 있다.

## 실행과 결과

복제 요청은 **목적지 절대 경로를 키로 하는 저장소별 Git 작업 큐**에 넣는다. 실행 차례에 입력과 목적지를 다시 검사하고, 목적지의 상위 폴더에서 `git clone --progress -- <주소> <목적지>`를 인수 배열로 실행한다. 대기·실행·취소·실패 상태는 복제 창에 표시한다. Git의 진행 출력에 퍼센트가 있으면 현재 전송 단계의 수치로 표시하며 전체 파일 다운로드율로 설명하지 않는다. 진행 출력이 없더라도 실행 중임을 표시한다.

중단은 실행 중 Git 프로세스에 취소를 요청한다. Git 프로세스가 실제로 시작한 뒤 실패하거나 취소되면 생성 위치가 현재 존재하는지 알려 주고 자동 삭제하지 않는다. 대기 중 취소나 실행 전 검증 실패에는 잔여 파일 안내를 표시하지 않는다. 다른 프로세스가 만든 폴더도 있을 수 있으므로, 표시한 파일을 Bough가 만들었다고 단정하지 않는다. 오류 화면과 로그에는 자격 증명이 포함된 URL이나 Git의 원문 오류 출력을 그대로 넣지 않는다. 성공하면 복제한 경로를 최근 저장소 목록에 등록하고 해당 저장소를 연다. 복제에는 성공했지만 열기에 실패하면 복제 결과와 열기 실패를 구분해 알린다.

저장소 전환 전에 충돌 해결 창에 미저장 편집이 있으면 기존 저장소 전환 확인 흐름을 따른다. 현재 저장소가 선택되지 않아도 복제 진입과 실행이 가능하다. 복제 창을 닫거나 입력 검증에 실패한 경우 현재 화면과 저장소 목록은 그대로 둔다.

## 검증 기준

- 임시 bare 원격을 새 경로와 이미 존재하는 빈 폴더에 각각 복제해 Git 참조, 최근 목록 등록과 자동 열기를 확인한다.
- 비어 있지 않은 목적지, 잘못된 주소와 경로, 자격 증명이 포함된 URL을 Git 실행 전에 거부한다.
- 실행 중 중단과 Git 실패에서 창의 결과 및 남은 파일 안내를 확인하고 기존 사용자 파일을 삭제하지 않는다.
- 저장소 전환과 작업 큐의 늦은 결과가 다른 저장소 화면을 덮지 않는지 확인한다.
