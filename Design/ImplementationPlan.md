# 구현 작업 지시

## 현재 개발 단계

기능과 화면이 계속 바뀌는 동안에는 **테스트 코드 작성·실행, 임시 저장소 시나리오 검증, 성능 측정, 반복 시각 검증을 보류**한다. 작업자는 담당 기능 구현과 작업자 간 연결 계약을 우선하고, 컴파일 오류를 확인할 필요가 있을 때만 빌드한다. 아래의 검증 기준은 기능 구성이 안정된 뒤 한 번에 확인할 목록이며 현재 작업을 멈추고 실행할 지시가 아니다. 완료 보고에는 구현 내용과 남은 연결 사항만 간단히 적는다.

## 공통 계약

- [화면과 동작](GitClientWorkflow.md), [커밋 상세와 파일 탐색](CommitInspection.md), [충돌 해결 창 진입](ConflictEntry.md)을 동작 기준으로 삼는다. [코딩 컨벤션](../Docs/CodingConvention.md)과 기존 Avalonia 테마를 따른다.
- 비동기 완료 뒤 stale 결과를 거르는 `if (previewVersion != _previewVersion || requestVersion != _requestVersion)` 같은 가드는 요청 버전과 미리보기 버전을 **각각 별도 `if`와 얼리 리턴**으로 쓴다. `StashViewModel`, `LocalChangesViewModel`뿐 아니라 각자 소유 파일의 같은 형태도 수정하면서 확인한다. 조건을 합친 헬퍼나 한 줄 가드로 숨기지 않는다.
- **가볍고 빠른 반응을 기능보다 앞선 품질 조건으로 둔다.** 첫 화면을 불필요한 Stash·원격·계정·사진 조회로 막지 않는다. 조회는 보이는 화면에 필요한 시점에 시작하고 같은 상태를 중복 읽지 않으며, Git 프로세스와 네트워크 요청을 제한된 묶음으로 사용한다. 스크롤·입력·스플리터 조작 중 UI 스레드를 기다리게 하지 않고, 늦은 응답은 버린다. 현재 기능 변경 단계의 성능 측정 보류는 유지하되 구현 선택에서 불필요한 작업을 늘리지 않는다.
- `CA1861` 지적 사항은 각 작업자의 소유 C# 파일에서 모두 정리한다. 리터럴 값만 있는 배열을 비변경 호출에 반복 전달할 때는 private `static readonly` 배열로 재사용한다. 저장소·브랜치·파일 경로처럼 매번 달라지는 인수를 포함한 배열이나 호출 대상의 변경 가능성이 있는 배열은 그대로 두며, CA1861 전체 비활성화나 무조건적인 배열 공유로 숫자만 맞추지 않는다. `DataContainer/Generated`는 수정하지 않는다.
- 저장소 간 전환과 Git 명령 실패를 상태로 표시한다. 비동기 요청이 이전 저장소의 결과를 현재 화면에 덮어쓰지 않게 한다.
- 오른쪽 내용과 목록에서 이미 확인되는 정상 상태는 하단에 반복하지 않는다. `해결되지 않은 충돌이 없습니다.`, `참조 목록을 새로 고쳤습니다.` 같은 성공·빈 상태 문구는 숨기고, 오류와 사용자가 대응해야 하는 상태는 표시한다. 상태 문구가 없으면 해당 하단 줄이 빈 공간을 차지하지 않게 한다.
- Git 출력에서 파일명과 커밋 메시지는 UTF-8로 읽고, 파일명 목록은 NUL 종료 형식으로 파싱한다. 명령 실행에는 `ProcessStartInfo.ArgumentList`를 사용한다.
- Dignus 컬렉션은 추가 중심 데이터와 그래프 구성에 적합한 곳에 활용한다. 같은 데이터를 배열과 큐에 중복 보관하지 않는다. 외부에 수정 가능한 내부 컬렉션을 그대로 노출하지 않는다.
- 각 작업자는 담당 서비스·View·ViewModel을 중심으로 구현한다. `MainWindow.axaml`, `MainWindow.axaml.cs`, `MainWindowViewModel.cs`와 충돌 해결 창의 최종 연결은 작업자 3이 맡는다. 작업자 1·2는 담당 ViewModel의 호출 계약을 작업자 3에게 전달하고 이 파일들을 동시에 수정하지 않는다. 총괄 PD는 기획 문서와 작업 지시·검증 기준만 관리한다.
- 생성 코드인 `DataContainer/Generated`는 직접 수정하지 않는다. 새로 만들거나 수정하는 사용자 표시용 고정 문구는 C#·AXAML에 한국어 또는 영어 리터럴로 넣지 않고 문자열 리소스로 관리한다. `Excel/String.xlsx` 원본을 수정하고 변환 절차에 따라 `Datas/String.json`을 갱신한다. 완료 전 담당 파일의 문자열 키가 실제 데이터에 모두 있는지, 남은 한국어 하드코딩이 없는지 확인한다.

## 작업자 1: Local Changes와 커밋

[저장소별 Git 작업 큐](GitOperationQueue.md)의 공통 조정자가 준비되면 Local Changes·Stash의 변경 명령 입구를 연결한다. 기존 `IsBusy`는 진행 상태용으로 유지하되 이미 입력된 요청을 조용히 버리지 않는다. 커밋·폐기 같은 비반복 작업도 입력 순서를 보존하고, 실행 차례에 저장소·파일·인덱스 상태가 달라졌다면 이유를 보여 주며 불가능한 Git 호출을 생략한다.

소유 영역: `Bough.Core/Git`의 작업 트리·Stash 서비스 및 모델, 커밋 상세의 읽기 전용 diff·트리·파일 내용·파일 이력 조회 서비스와 모델, `Bough.App/Views/LocalChangesView.*`, `Bough.App/ViewModels/LocalChangesViewModel.cs`와 필요한 보조 모델. Stash 명령과 UI는 작업자 1이 맡고, 작업자 2는 Stashes 탐색 목록과 진입점만 맡는다.

1. `git status --porcelain=v1 -z`로 Unstaged/Staged/Conflict/Untracked를 구분한다. 이름 변경과 한글·공백 경로를 포함한다.
2. 파일 선택 시 작업 트리 또는 인덱스 diff를 보여 준다. Local Changes의 단색 `PreviewText` 미리보기를 줄 종류별 표시로 바꿔 추가는 초록색, 삭제는 빨간색, hunk는 강조색으로 구분한다. `+++`·`---` 머리글과 미추적 파일의 원문을 내용 diff로 오인하지 않으며 긴 줄 스크롤·복사를 유지한다. 바이너리와 새 파일은 빈 diff로 오해하지 않도록 별도 상태를 보여 준다. 오른쪽 고정 커밋·Stash 열을 없애고 코드 미리보기에 그 너비를 돌린다. Local Changes 전체 너비의 하단에는 기본 높이가 낮고 높이 조절·접기가 가능한 커밋 영역을 두며, 접어도 메시지 초안은 보존한다.
   Local Changes의 왼쪽 파일 목록과 가운데 미리보기 사이를 드래그 가능한 세로 분할선으로 만들고, 최소 폭·키보드 조작·폭 복원·긴 경로 툴팁·좁은 폭의 버튼 배치를 확인한다.
3. 파일별·전체 Stage/Unstage를 구현하고 실행 후 상태를 다시 읽는다. Local Changes의 파일 목록은 **Staged 위, Unstaged 아래**로 배치하고, 파일 이동 뒤 선택과 미리보기를 이어서 보여 준다. Staged가 비면 위쪽의 빈 목록이 큰 높이를 차지하지 않게 한다. StageSelected와 StageAll의 새 파일 후보 중 10 MiB 이상은 실제 `git add` 전에 한 번의 확인 창에서 경로·크기를 보여 주고, 취소하면 아무것도 스테이징하지 않는다. 현재 `GitWorkingTreeService.StageAllAsync`의 파일별 `StageAsync` 반복으로 발생하는 Git 프로세스 수를 줄인다. 미해결 충돌을 제외한 대상 경로를 한 번 또는 명령 길이에 따라 제한된 묶음으로 `git add`에 전달한다. 많은 경로는 NUL 종료 pathspec 입력 등 안전한 방식으로 처리하고, 결과 상태는 마지막에 한 번 갱신한다. 충돌 파일이 있을 때만 Local Changes에 목록·파일 수·해결 창 다시 열기 동작을 노출한다. 충돌이 없으면 빈 패널을 숨기고 선택한 파일 경로를 작업자 2의 창 열기 계약에 전달한다.
   Staged 목록 아래의 선택·전체 스테이징 해제 버튼과 Unstaged 목록 아래의 선택·전체 스테이징 버튼은 [화면과 동작](GitClientWorkflow.md)의 배치대로 각각의 **목록 머리글 오른쪽**으로 옮긴다. 목록 최소 폭에서도 제목·버튼이 잘리지 않게 짧은 표기와 툴팁을 제공하고, 기존 명령을 재사용한다.
   Staged와 Unstaged 사이에는 실제 가로 `GridSplitter`를 두고 두 목록의 높이를 드래그로 조절하게 한다. 빈 목록은 머리글만 남기고 남는 높이를 파일이 있는 쪽에 준다. 양쪽에 파일이 있을 때는 최소 높이·독립 스크롤을 유지하고 `Staged`의 고정 `MaxHeight` 제한을 없앤다. 사용자가 조절한 크기는 저장소를 바꾸거나 화면을 다시 열어도 유지한다. 기존 `LocalChangesLayoutSettings`의 파일 목록 폭 저장값을 확장할 경우 기존 값도 읽을 수 있게 한다.
   Unstaged 목록은 Ctrl/Shift 클릭·Ctrl+A로 다중 선택하고 `변경 폐기…`를 선택 집합 전체에 한 번 실행한다. 선택 수를 버튼·메뉴에 표시하고, 확인 창에는 모든 상대 경로를 스크롤 가능한 목록으로 보여 주며 추적 파일의 unstaged 변경 복원과 미추적 파일 삭제를 구분한다. staged 변경은 보존한다. 확인 전과 실행 직전에 전체 대상의 상태·내용·저장소 경계를 검증하고 하나라도 바뀌면 전체 실행을 중단한다. 충돌 항목은 제외한다. 취소 시에는 갱신하지 않고, 성공 또는 부분 실패 후에는 한 번만 갱신하며 부분 실패 범위·경로를 표시한다. 일반 추적 파일을 가능한 한 묶어 Git 프로세스 수를 줄이되 이름 변경의 안전 검사는 유지한다. 선택하지 않은 파일이나 폴더를 건드리지 않는다.
   Unstaged 파일 행 우클릭에는 `변경 폐기…`와 미추적 파일 전용 `무시`를 제공한다. 선택된 행의 우클릭은 기존 다중 선택을 유지하고, 선택되지 않은 행의 우클릭은 그 행 하나로 대상을 바꾼다. `무시`에는 공유 규칙 `.gitignore`와 이 컴퓨터 전용 `.git/info/exclude`를 명확히 구분해 둔다. 여러 미추적 파일의 정확한 상대 경로 규칙을 한 번 확인하고 추가하며 Git ignore 특수 문자를 이스케이프한다. 무시 동작으로 파일을 삭제·스테이징하거나 추적 파일에 `git rm --cached`를 실행하지 않는다. 취소 시 변경·갱신 없음, 성공 시 상태를 한 번 갱신한다.
   Staged 머리글에는 `↓`, `↓↓` 두 동작을, Unstaged 머리글에는 `↑`, `↑↑`, `X` 세 동작을 직접 표시한다. 현재 적용된 `⋯` 메뉴는 클릭을 늘리고 파일 목록 위로 열리므로 제거한다. 우클릭 메뉴는 추가 진입점으로 유지한다. 최소 허용 폭에서는 제목을 줄임표로 처리하고 버튼 폭·간격을 조절해 클릭 영역이 겹치거나 잘리지 않게 한다. 각 버튼에 전체 이름 툴팁·접근성 이름을 제공한다.
4. 하단 커밋 영역에 별도 제목·설명 입력칸 대신 여러 줄 **커밋 메시지 칸 하나**, Amend 선택과 명시적 Commit 실행을 구현한다. 메시지 첫 줄은 히스토리 요약으로 사용하고 Amend에서는 기존 전체 메시지를 편집할 수 있게 한다. 커밋 전 메시지·스테이징 상태·작성자 설정을 검증하고 실패 메시지를 보여 준다. 현재 고정 폭 `190` 작업 열과 `CommitHint`의 높이 제한 때문에 한국어 안내 끝이 잘리는 문제를 고친다. 좁은 창에서도 안내 문구 전체와 Amend·Commit을 읽고 사용할 수 있도록 배치를 바꾼다.
   커밋 패널의 스플리터를 최대로 줄이면 `이전 커밋 수정`과 `커밋` 버튼이 잘리는 문제를 고친다. 현재 `LocalChangesView.axaml`의 커밋 행 최소 높이 `160`, `CommitMessageInput` 최소 높이 `72`, `LocalChangesView.axaml.cs`의 `CommitBodySizeChanged` 높이 계산과 `MinimumCommitHeight`/저장 높이 복원을 함께 확인한다. 버튼은 메시지 스크롤 영역에 가려지지 않게 패널 안에 고정하고, 입력칸이 남는 높이에 맞춰 줄어들며 내부 스크롤하게 한다. 좁은 너비에서 안내 문구가 줄바꿈돼도 실행 컨트롤의 클릭 영역이 남아야 한다. [화면과 동작](GitClientWorkflow.md)을 따른다.
5. 브랜치 전환·커밋 초기화 후 상위 화면에서 호출할 수 있는 새로 고침 계약을 노출한다. 최종 연결에 필요한 View 생성 방식, ViewModel 생성자, 서비스 API를 작업자 3에게 전달한다.
6. [원격 작업과 Stash](RemoteAndStash.md)에 따라 Local Changes 상단 작업 영역의 **Stash** 버튼이 별도 입력 창을 열게 한다. 상시 Stash 입력 폼을 제거하고 창에서 메시지·미추적 파일 포함·대상 요약·Save/Cancel·오류를 처리한다. Stash 미리보기·Apply·Pop·Drop을 유지하고 Drop에는 확인을 받는다. 작업자 2의 Stashes 탐색 화면과 연결할 계약을 전달한다.
   `StashViewModel.WorktreeChanged`의 `GetInvocationList().Cast<Func<Task>>()` 순회는 제거한다. Save·Apply·Pop·Drop의 결과와 갱신 범위를 명시적으로 구분해 호출자가 필요한 갱신을 순서대로 `await`할 수 있는 계약을 작업자 3과 정한다. Drop·취소·변경 전 실패에서 전체 작업 트리와 메인 창 상태를 다시 읽지 않는다. Apply/Pop 실패라도 실제 작업 파일·충돌 상태가 변했을 수 있으면 안전하게 반영한다. Stash 목록·작업 트리·충돌 상태의 중복 Git 조회를 줄인다.
   보관 창의 Cancel·창 닫기는 성공과 구분할 수 있는 결과를 작업자 3의 메인 창 활성화 처리에 전달한다. 실제 Git 변경이 없으면 보관 창을 닫는 과정에서 작업 트리·Stashes를 다시 읽지 않는다. 보관 성공의 기존 갱신은 유지한다.
7. [커밋 상세와 파일 탐색](CommitInspection.md)에 따라 커밋 메타데이터·비교 부모·변경 파일 상태·파일별 diff·커밋 트리·파일 내용·파일 History 조회 계약을 제공한다. Blame/Timeline 조회는 이 범위에서 제외한다. 조회 서비스 API와 모델을 작업자 2에게 전달하고 History 화면 파일은 수정하지 않는다.
8. [저장소 전환 응답성](RepositorySwitchResponsiveness.md)에 따라 Local Changes를 먼저 표시할 수 있게 Stashes 목록의 초기 조회와 작업 트리 상태 중복 조회를 분리한다. Stashes 화면·보관 창에서 필요한 시점에 목록을 읽는 계약을 작업자 3에게 전달한다.
9. [히스토리 작성자 아바타](AuthorAvatars.md)의 이미지 조회·캐시와 사용자별 GitHub 계정 연결 저장은 작업자 1이 맡는다. 소유 파일은 `Bough.App/Controls/AuthorPhotoService.cs`, `AuthorIdenticon.cs` 및 새 보조 서비스·설정 파일이다. 공개 GitHub 커밋에서 확인된 작성자 `avatar_url`을 우선하고, 지정된 작성자 이메일의 명시적 GitHub 사용자명 연결, Gravatar, 로컬 아이콘 순으로 처리한다. 다른 작성자에게 사진이 섞이지 않게 저장소·커밋·이메일 키를 구분하고, 기존 외부 사진 끄기·요청 제한을 유지한다. HistoryView·HistoryViewModel·GitSettingsView 파일은 수정하지 않고 필요한 바인딩 계약을 작업자 2에게 전달한다.
10. [GitHub 인증 계정 전환](GitHubAccountSwitching.md)의 서비스 계약을 새 `Bough.Core/Git` 파일에 구현한다. GCM 사용 가능 여부·계정 목록·추가 로그인·현재 저장소의 GitHub HTTPS 원격별 선택 계정을 읽고, 선택을 해당 저장소에만 저장하는 API를 작업자 2에게 제공한다. `GitSettingsView`·`GitSettingsViewModel`·기존 `GitSettingsService`는 수정하지 않는다. 인증 비밀값을 읽거나 출력하지 않고 계정 전환 때문에 다른 계정의 GCM 자격 증명을 지우지 않는다. 서비스 생성·DI 연결이 필요하면 작업자 3에게 계약을 전달한다.
11. [화면 테마](AppearanceTheme.md)의 공통 팔레트 계약을 작업자 3에게 받아 소유 중인 `LocalChangesView`, `StashView`, 보관·큰 파일·폐기 확인 창과 `DiffPreviewTextBlock`·`AuthorIdenticon`의 고정 색을 밝음/어두움 리소스로 전환한다. diff 추가·삭제·hunk와 단계 상태의 전경·배경을 두 테마에서 읽을 수 있게 한다. 설정 화면·App 리소스는 수정하지 않는다.

추후 안정화 검증 기준: 임시 저장소에서 새 파일·수정·삭제·이름 변경·충돌을 분류하고, Stage/Unstage 후 목록이 이동한다. 100개 이상 파일의 모두 스테이징 전후 소요 시간과 Git 프로세스 수를 비교해 파일 수만큼 프로세스를 만들지 않음을 확인한다. 한글·공백 경로, 삭제·이름 변경, 충돌 파일 제외도 확인한다. 목록·미리보기 경계를 드래그하거나 키보드로 조절할 수 있고, 화면 전환·재시작 뒤 폭이 복원되며, 가장 좁은 허용 폭에서도 경로 툴팁과 Stage/Unstage 버튼을 사용할 수 있다. 오른쪽 고정 입력 열 없이 코드 미리보기가 넓어지고, 전체 너비 하단 커밋 영역과 상단 Stash 버튼·입력 창을 사용할 수 있다. 충돌이 없으면 Local Changes의 빈 충돌 패널이 보이지 않고, 충돌 파일이 있으면 선택한 파일을 해결 창으로 보낼 수 있다. 한 칸에 입력한 여러 줄 메시지가 커밋에 그대로 저장되고 첫 줄이 History에 나타난다. 빈 메시지·스테이징 없음·Git 오류가 UI에 드러난다. Stash 보관·Apply·Pop·Drop 후 목록과 작업 파일 상태가 일치한다.

큰 파일 경고의 추후 검증 기준: 폐기 가능한 임시 저장소에서 기준 이하·이상인 새 파일과 이미 추적 중인 큰 파일을 준비한다. StageSelected와 StageAll에서 경고 대상·경로·크기를 확인하고, 취소 직후 인덱스가 그대로인지와 확인 후에만 대상이 스테이징되는지 검사한다. 큰 파일 여러 개와 한글 경로가 있어도 확인 창을 한 번만 열고 목록 끝까지 볼 수 있어야 한다.

## 작업자 2: 탐색, Git 설정, Terminal 진입점

[저장소별 Git 작업 큐](GitOperationQueue.md)의 공통 조정자가 준비되면 브랜치·태그·원격 작업과 저장소별 Git 설정 변경 명령 입구를 연결한다. 브랜치 전환도 입력 순서대로 FIFO 실행하며 명시적인 취소 없이 대기 요청을 교체·합치지 않는다. 읽기 조회를 큐에 넣어 화면 반응을 늦추지 않는다. 기존 `busy` 차단 경로는 실행 중 표시와 입력 처리로 구분한다.

소유 영역: 브랜치·원격·태그·stash·submodule 조회 서비스와 모델, 별도 탐색 View/ViewModel, Git 경로·작성자 설정 View/ViewModel, 터미널 실행 서비스, Fetch/Pull/Push의 Git 서비스와 `RemoteOperationsViewModel.cs`. 기존 History의 참조 표시·커밋 상세 탭·파일 메뉴·커밋 우클릭 메뉴를 위해 `HistoryView.axaml`, `HistoryReferenceItem.cs`, `HistoryViewModel.cs` 및 별도 Git 동작 서비스도 담당한다. 원격 작업 View·다이얼로그와 `MainWindow.*`·`MainWindowViewModel.cs`는 작업자 3에게 넘긴다.

참조 트리에서 정상 조회가 끝난 뒤 `참조 목록을 새로 고쳤습니다.` 상태 줄을 숨긴다. 오류·전환 실패 메시지는 계속 확인할 수 있어야 하며 표시할 메시지가 없으면 줄 높이도 없앤다.

1. Branches/Tags/Remotes/Stashes/Submodules를 조회하고 현재 브랜치를 표시한다. [화면과 동작](GitClientWorkflow.md)의 왼쪽 참조 탐색 트리처럼 브랜치 → 태그 → 원격 → 스태시 순서, 섹션 아이콘·화살표, `origin` 아래 추적 브랜치, 들여쓰기와 현재 브랜치 강조를 구현한다. 빈 스태시 섹션 머리글은 유지하고 서브모듈이 없으면 그 섹션만 숨긴다. 브랜치 섹션의 새 브랜치 버튼과 항목 우클릭 메뉴는 같은 입력 팝업을 열게 한다. 새 브랜치·추적 브랜치 상시 입력 폼은 트리에서 제거한다.
   태그 섹션에도 `+`와 섹션 우클릭 `태그 만들기…`를 두어 현재 `HEAD`에 로컬 일반 태그를 만든다. History 커밋 우클릭에서는 해당 커밋 해시를 고정해 같은 입력 창을 연다. 이름만 입력받고 대상은 읽기 전용으로 표시한다. Git 명령은 저장소 루트에서 인수 배열로 실행하며 기존 이름을 강제로 덮어쓰지 않는다. 오류는 입력 창에 남기고 성공 시 태그 트리·History 참조를 갱신하되 브랜치·작업 파일은 바꾸지 않는다. [화면과 동작](GitClientWorkflow.md) 및 [커밋·브랜치 우클릭 동작](CommitActions.md)을 따른다.
2. 로컬 브랜치 선택과 새 브랜치 생성 흐름을 구현한다. 새 브랜치 팝업은 이름만 입력받고 시작점은 읽기 전용으로 보여 준다. 브랜치 섹션 버튼에서는 `HEAD`, 특정 브랜치·커밋에서 열면 해당 참조가 시작점이다. 현재 `HEAD` 텍스트 입력칸은 제거한다. Create and switch·Cancel, 빈 이름과 Git 오류 처리, 성공 후 참조·History·Local Changes 갱신을 제공한다. 전환이 Git에 의해 거부되면 작업 트리를 건드리지 않고 오류를 보여 준다. 태그 선택은 History 커밋 이동을 위한 해시를 전달한다.
   로컬·원격 브랜치 행의 **단일 클릭은 선택만** 한다. **더블클릭·우클릭 메뉴·Enter**에서만 체크아웃을 실행한다. `macro-mode`에서 `master`를 선택한 뒤 전환 동작을 실행했는데 체크 표시가 그대로라면 Git 명령 실행 여부와 실패 이유를 확인할 수 있게 한다. 더블클릭이 중복 Git 실행이나 잘못된 `작업 중` 오류를 만들지 않게 하고, 이미 현재인 브랜치의 전환은 Git을 다시 실행하지 않는다. 원격 브랜치는 아래 추적 브랜치 규칙을 따른다. 섹션 접기·펼치기와 브랜치 추가 `+` 버튼은 각자의 기존 동작을 유지한다. 선택 강조와 실제 현재 브랜치 체크 표시를 구분하고, Git이 거부하면 원인을 브랜치 영역에 표시한다.
   현재 브랜치에서 다른 로컬 브랜치로 돌아가지 못한다는 보고가 있다. `ReferenceExplorerView`의 행 클릭과 우클릭 전환, `ReferenceExplorerViewModel.SwitchBranchAsync`, `GitReferenceService.SwitchBranchAsync`의 실제 Git 결과를 구분해 원인을 고친다. 파란 행 선택과 실제 현재 브랜치 체크 표시를 혼동하지 않게 하고, 실패 이유를 브랜치 영역에서 보이게 한다. 성공했는데 상위 화면이 이전 브랜치로 남는다면 작업자 3의 `OnReferenceRepositoryChanged` 연결 계약을 전달한다.
   재보고: `feature/matching-server`에서 `main`을 더블클릭해도, 우클릭 메뉴에서 전환해도 체크 표시가 그대로이고 오류도 보이지 않는다. 두 입력 경로를 각각 추적해 Git 명령 실행 여부와 결과를 확인한다. 작업 중 참조 새로 고침이 `_requestVersion`을 바꿔 전환 결과를 조용히 버리는 경로, 컨텍스트 메뉴의 대상 보관과 `CanRunMenuAction`의 조기 반환, `RefreshCoreAsync` 및 상위 화면 갱신을 점검한다. 사용자가 실제로 전환을 실행한 뒤에는 성공한 현재 브랜치를 표시하거나 실패 원인을 화면에 남겨야 한다. 진단만 남기지 말고 동작을 수정한다.
   재현 영상 `Bough 2026-09-24 11-21-55.mp4`에서는 약 4초에 `feature/UI로 전환할 수 없습니다. 다른 Git 작업이 진행 중입니다`가 뜬 뒤 약 6초에 `master` 전환이 완료되고, 약 8초에 다시 `macro-mode`로 바뀐다. 전환 명령 자체는 작동하지만 `_branchChangeInProgress` 동안 들어온 다음 사용자 명령이 버려져 무반응으로 보인다. 단일 클릭은 계속 선택만 한다. 더블클릭과 메뉴 명령은 현재 전환 중에도 FIFO 큐에 추가하고 차례대로 실행한다. `A→B→A`도 명시적인 취소 없이는 세 요청을 모두 처리한다. 대기 상태를 오류로 표시하지 말고 사용자가 알 수 있게 보여 준다. [화면과 동작](GitClientWorkflow.md)을 따른다.
   참조 트리의 세로 스크롤바가 오른쪽의 현재 브랜치 체크 표시 및 브랜치 추가 버튼과 겹친다는 보고를 반영한다. 스크롤바가 나타나도 모든 행의 우측 동작·상태 영역에 필요한 폭을 확보하고, 브랜치 이름은 남은 폭에서만 줄임표로 처리한다. 창과 왼쪽 패널을 좁혔을 때도 체크 표시와 `+` 버튼을 클릭·확인할 수 있어야 하며, 선택 강조와 스크롤바가 겹쳐 혼동을 주지 않아야 한다.
   원격 브랜치 체크아웃 창에서는 [화면과 동작](GitClientWorkflow.md)대로 **새 로컬 브랜치 이름**과 짧은 실행 버튼 **만들고 전환**을 사용한다. 원격 브랜치 추적의 의미는 버튼에 반복하지 않고 설명과 시작점에 둔다. 실행 버튼은 주요 동작으로, 취소는 보조 동작으로 테마에 맞게 구분한다. 긴 브랜치 이름에서도 버튼이 잘리거나 창 밖으로 밀리지 않아야 한다. 일반 로컬 브랜치 생성 팝업과 공용 다이얼로그를 사용하더라도 원격 체크아웃 문구는 구분한다. 기존 로컬 이름과 충돌하면 사용자의 선택 없이 덮어쓰거나 다른 이름으로 생성하지 않는다.
   [브랜치 생성 창의 작업 큐](BranchDialogQueue.md)에 따라 `RequestNewBranchAsync`의 `busy` 차단 흐름을 `Dignus.Collections.ArrayQueue`와 단일 `async Task` 소비 루프로 바꾼다. 클릭 시 이름을 요청에 복사해 순서대로 `submit`하고, 성공만을 이유로 대기 요청을 폐기하지 않는다. 명시적인 취소·창 닫기에서만 대기 요청을 취소하며 실제 Git 작업과 UI 상태가 어긋나지 않게 한다. 반복 입력을 조용히 버리는 `busy` 검사를 남기지 않는다.
   원격 브랜치를 눌러도 이동하지 못한다는 보고가 있다. `ReferenceExplorerView.ActivateTreeNodeAsync`가 현재 모든 원격 브랜치에 새 추적 브랜치 창을 열고 `TrackMenuRemoteAsync`는 `switch --track -c`만 시도하는 흐름을 고친다. 원격 참조를 추적하는 기존 로컬 브랜치가 있으면 그 브랜치로 전환하고, 이미 현재라면 그 상태를 알려 준다. 없을 때만 새 로컬 추적 브랜치 창을 연다. 이름만 같은 로컬 브랜치를 추적 중이라고 간주하지 않으며, 관계 조회는 브랜치마다 Git 프로세스를 실행하지 않고 일괄로 처리한다. 행 클릭·우클릭 메뉴의 결과가 일치해야 하며 성공 후 현재 브랜치 체크 표시와 상위 화면 상태를 갱신한다. [화면과 동작](GitClientWorkflow.md)을 따른다.
3. Git 실행 파일 자동 탐색, 직접 지정, 버전 검사와 저장을 구현한다. 현재 저장소/전역 `user.name`, `user.email`을 구분해 읽고 쓴다. 계정 화면에는 원격 인증 방식과 credential helper 상태를 보여 준다.
4. `Git references` 머리글에서 `Open in ▾`·`Console`·`Refresh` 버튼을 제거하고 제목과 현재 브랜치만 남긴다. 파일 탐색기 열기와 저장소 루트에서 콘솔 열기 동작을 작업자 3의 상단 도구막대가 호출할 수 있게 계약을 전달한다. 앱 내 대화형 터미널은 별도 후속 작업으로 설계 계약을 남긴다.
5. 기존 History의 BRANCH / TAG 칸을 정리한다. [화면과 동작](GitClientWorkflow.md)의 간결한 인라인 배지 기준에 맞춰 커밋 그래프 점 옆·메시지 앞에 대표 참조 1~2개를 표시한다. 나머지는 `+N` 전체 목록에서 확인하게 하고 현재 브랜치·로컬·원격·태그를 구분한다. 긴 이름 툴팁과 그래프 선 연결을 유지한다.
   커밋 목록의 실제 세로 스크롤이 끝에 가까워지면 `LoadMoreCommand`로 다음 묶음을 자동 요청한다. 정상 상태의 수동 `Load more commits` 버튼은 없애고 로딩·오류/다시 시도 상태를 목록 끝에 표시한다. `HistoryViewModel.LoadCoreAsync`가 현재 전체 `Commits`를 지우고 다시 넣는 방식 때문에 선택과 스크롤이 튈 수 있으므로 페이지 추가 시 목록·선택·상세를 보존한다. 중복 스크롤 이벤트, 진행 중 요청, 실패 뒤 무한 재시도, 저장소 전환 뒤 늦은 응답을 막는다.
   히스토리 머리글에 **전체 / 현재 브랜치** 범위 전환을 둔다. `GitHistoryService.GetHistoryAsync`의 기존 `git log --all`은 전체 범위에 유지하고, 현재 브랜치 범위는 현재 `HEAD`에서 도달 가능한 커밋을 조회한다. 병합된 커밋을 포함하며 첫 부모 경로로 제한하지 않는다. 범위 변경 시 `_limit`과 페이지 상태를 초기화하고, 자동 추가 로딩은 현재 범위에만 적용한다. 범위·저장소·브랜치 전환 이전의 늦은 응답이 새 목록에 섞이지 않게 한다. 브랜치가 바뀌면 현재 브랜치 범위의 목록을 새 `HEAD`로 갱신한다. [화면과 동작](GitClientWorkflow.md)을 따른다.
6. [커밋·브랜치 우클릭 동작](CommitActions.md)에 따라 커밋 체크아웃, 브랜치 생성·전환, 현재 브랜치 초기화 메뉴를 구현한다. Hard 초기화는 영향 경고와 두 번째 확인을 거쳐야 한다. 실제 저장소에서는 reset을 시험하지 않는다.
7. [원격 작업과 Stash](RemoteAndStash.md)에 따라 Fetch/Pull/Push와 upstream 상태를 구현한다. 상단의 자유 입력 `Remote branch` 칸을 제거하고 연결된 upstream은 읽기 전용으로 보여 준다. 기본 Pull·Push는 이 upstream을 대상으로 하며, Pull 대상 변경은 기존 원격 브랜치 선택 창, 첫 Push와 명시적인 Push 대상 변경은 대상·영향 확인 창에서 처리한다. Pull 기본은 Fast-forward only다. 상단의 상시 비활성 `Cancel` 버튼을 제거하고, 실행 중에는 작업 이름·대상·상태·**작업 중단**을 담은 원격 작업 다이얼로그를 연다. Pull에는 받는 원격/브랜치와 현재 단계, 실행 중 Git 전송 상태를 표시하고, 가져온 커밋·변경 파일 요약은 확인 가능한 시점에 표시한다. 현재 `GitCommandRunner.RunAsync`가 표준 출력과 오류 출력을 작업 종료까지 모으는 점을 고려해 진행 내용을 안전하게 스트리밍하는 계약을 마련한다. 성공·실패·중단 결과를 다이얼로그에서 확인할 수 있게 한다. Stashes 탐색 목록은 작업자 1의 Stash 서비스 계약을 사용한다.
   왼쪽 브랜치 트리에 현재 브랜치가 표시되므로 `RemoteOperationsView`의 맨 위 `CurrentBranchText` 중복 표시를 제거한다. upstream과 앞선/뒤처진 커밋 수만 간결히 남긴다. 현재 화면에 남은 자유 입력 `TargetBranch`는 위 대상 선택 창 설계에 맞게 제거한다. 원격 선택 콤보박스가 필요하면 Fetch 대상 선택에만 쓰고, Pull·Push 대상은 upstream 또는 명시적인 대상 선택 창에서 정한다.
   Fetch·Fetch all·Pull은 성공 및 후속 상태 갱신 완료 뒤 원격 작업 다이얼로그를 자동으로 닫는다. 실패·중단·부분 성공·후속 갱신 실패는 열린 채로 결과를 표시한다. `Func<Task>`가 예외 없이 끝났다는 사실만 성공 판정에 쓰지 말고 ViewModel의 명시적 완료 상태를 확인한다. Push의 수동 닫기는 유지한다.
   기본 Push 대상이 추적 중인 upstream이고 ahead가 `0`이면 명령과 진행 창을 열지 않고 **보낼 새 커밋 없음**을 표시한다. 수정·스테이징 파일 수로 Push 필요 여부를 판단하지 않는다. 첫 Push와 명시적으로 다른 대상에 보내는 Push는 이 조건으로 생략하지 않는다. UI 상태와 실제 실행 경로에서 모두 확인해 불필요한 Push를 막는다.
   이 항목에서 작업자 2는 `GitRemoteOperationService`와 `RemoteOperationsViewModel`의 실행·상태 판정·완료 결과를 맡는다. `RemoteOperationsView.axaml/.cs`와 `RemoteOperationWindow.axaml/.cs`의 표시·클릭·자동 닫기는 작업자 3이 맡는다. 특히 자동 닫기는 예외 없는 `Task` 완료 대신 명시적인 성공 결과를 쓸 수 있도록 작업자 2가 계약을 제공한다. 두 작업자는 파일 소유 변경을 서로 확인한 뒤 같은 파일을 동시에 수정하지 않는다.
8. 최종 연결에 필요한 View 생성 방식, ViewModel 생성자, 서비스 API를 작업자 3에게 전달한다.
9. [커밋 상세와 파일 탐색](CommitInspection.md)의 Commit·Changes·File Tree 탭, 파일별 diff, 파일 메뉴를 구현한다. HistoryView의 좌우 2열을 위쪽 커밋 그래프·목록과 아래쪽 상세 탭으로 바꾸고, 두 영역 사이에 실제 `GridSplitter`를 넣어 드래그로 높이를 조절한다. 목록·상세는 독립 스크롤하며 최소 높이를 지키고, 스플리터 조절 뒤 선택 커밋과 목록 위치를 유지한다. Commit 탭의 Expand all·Collapse all이 현재 ViewModel 상태만 바꾸고 실제 `Expander.IsExpanded`는 바꾸지 못하는 연결 누락을 고친다. Changes와 File Tree의 아래 파일 미리보기가 창 밖으로 늘어나지 않도록 높이를 제약하고, 목록·미리보기에 독립 스크롤과 높이 조절 분할선을 둔다. 긴 파일의 마지막 줄과 긴 줄의 끝까지 확인한다. 읽기 전용 조회는 작업자 1의 계약을 사용한다. 파일 메뉴에서 `Reset File to…`와 `Blame / Timeline`을 제거하고, `Save as…` 내보내기는 작업자 2가 맡는다. 데이터 서비스 소유 파일은 작업자 1과 조율한다.
   Commit 탭의 접힌 변경 파일 Expander는 [커밋 상세와 파일 탐색](CommitInspection.md)의 간결한 머리글 크기로 줄인다. `HistoryView.axaml`의 파일 패널만 대상으로 하며 긴 경로의 툴팁·펼침 화살표·우클릭 메뉴·Expand all/Collapse all 동작을 유지한다.
   [히스토리 작성자 아바타](AuthorAvatars.md)에 따라 커밋 목록에는 작은 아바타, Commit 상세 상단에는 더 큰 아바타를 배치한다. 작업자 1이 제공하는 GitHub 작성자·명시적 자기 계정·Gravatar·로컬 아이콘 순위와 사진 출처를 HistoryView/HistoryViewModel에 연결한다. Git 설정에 자기 GitHub 사용자명과 연결할 Git 작성자 이메일을 수정할 수 있는 로컬 설정을 제공한다. 외부 사진 끄기 설정은 모든 외부 조회에 적용하고 실제 OAuth 로그인 없이 'GitHub 계정 연동'이라고 표시하지 않는다. 작업자 1의 Controls/사진 서비스 파일은 수정하지 않는다.
   `External author photos` 체크박스가 작동하지 않는다는 보고를 확인한다. `HistoryView.axaml`의 체크 상태 양방향 바인딩과 목록·상세 `AuthorIdenticon.ExternalPhotosEnabled` 연결을 점검한다. 두 아바타에 커밋 해시와 GitHub 원격 주소가 현재 빠져 있으므로 `GitHubCommit` 조회 경로까지 전달한다. 설정을 껐을 때 이미 표시된 외부 사진의 즉시 제거와 재활성화, 저장 후 다시 열었을 때 상태 복원, 사진이 없는 작성자의 로컬 아이콘 유지가 [히스토리 작성자 아바타](AuthorAvatars.md)대로 동작하게 한다. 작업자 1의 Controls/사진 서비스 파일에서 발견한 문제는 해당 작업자에게 전달한다.
10. 상위 탐색·새로 고침·충돌 해결 창의 최종 연결에 필요한 이벤트와 명령 계약을 작업자 3에게 전달한다. `MainWindow.*`와 `MainWindowViewModel.cs`는 수정하지 않는다.
11. [저장소 전환 응답성](RepositorySwitchResponsiveness.md)에 따라 참조·원격 조회가 기본 화면 표시를 막지 않도록 영역별 로딩 계약을 제공한다. 태그마다 실행하는 `rev-parse`를 일괄 참조 조회로 바꾸고, 필요한 참조·원격 정보를 중복 읽지 않게 한다.
12. [GitHub 인증 계정 전환](GitHubAccountSwitching.md)을 `GitSettingsView`·`GitSettingsViewModel`의 Accounts 영역에 연결한다. 작업자 1의 새 서비스 계약으로 저장소별 GitHub HTTPS 계정 선택·추가 로그인·실패 표시를 구현한다. 현재 원격과 선택한 사용자명을 보여 주되 인증 확인 전에는 로그인 완료로 단정하지 않는다. `user.name`·`user.email` 및 히스토리 아바타 연결과 분리한다. GCM 미지원 또는 SSH 원격이면 이유를 안내한다. 원격 작업 실행 중 계정 전환을 막거나 다음 실행에만 적용하고, 저장소 전환의 늦은 응답을 무시한다. ViewModel 생성자 변경은 작업자 3에게 전달한다.
13. [화면 테마](AppearanceTheme.md)의 **화면 모양** 선택을 `GitSettingsView`·`GitSettingsViewModel`에 연결한다. 밝음/어두움/시스템 설정의 현재 선택이 표시되고 변경 즉시 앱 전체에 적용되도록 작업자 3의 테마 서비스 계약을 사용한다. `HistoryView`, `ReferenceExplorerView`, `GitActionDialogs`, 커밋 상세·그래프·상태 배지와 해당 ViewModel의 고정 색을 공통 팔레트로 바꾼다. 특히 현재 밝은 테마에서 History 전체가 어둡고 상세 탭·제목·SHA가 읽히지 않는 화면을 해소한다. `전체 / 현재 브랜치` 라디오, 탭, 버튼, 파일 Expander의 밝은 Fluent 면과 사용자 지정 패널을 같은 테마로 맞춘다. `HistoryView.axaml`·`GitSettingsView.axaml`의 16진수 색과 `HistoryReferenceItem`·`HistoryInspectionFileItem`·`HistoryViewModel`·`HistoryGraphControl`의 C# 고정 색을 함께 바꾸고, 실행 중 전환에도 기존 데이터·선택·스크롤을 유지한다. 커밋이 한두 개일 때 위 목록의 큰 빈 공간을 줄이고 상세가 더 넓게 보이는 초기 스플리터 높이를 적용하되 사용자의 드래그 선택은 보존한다. MainWindow·App·Local Changes 파일은 수정하지 않는다.

추후 안정화 검증 기준: 브랜치 전환 뒤 현재 브랜치와 History가 갱신될 수 있는 이벤트가 발생하고, 태그·서브모듈·빈 섹션이 올바르게 표시된다. 왼쪽 참조 트리는 브랜치·태그·원격·스태시 순서와 원격의 2단계 들여쓰기를 유지하며, 새 브랜치 버튼은 이름 입력 팝업을 연다. 시작점은 읽기 전용으로 보이고 `HEAD` 텍스트 입력칸과 트리의 상시 입력 폼은 없다. History에서 참조 3개 이상인 커밋은 인라인 배지 1~2개와 `+N`으로 보이고, 전체 목록에서 모든 참조를 확인할 수 있다. 커밋 우클릭 대상과 실제 명령 대상이 일치하며, Fetch/Pull/Push는 임시 bare 원격에서 성공·거부 상태를 보여 준다. 잘못된 Git 경로와 인증 미설정 상태가 설명된다. 상위 화면 연결 결과는 작업자 3의 완료 기준에서 검증한다.

## 작업자 3: 메인 화면 연결과 충돌 해결 창

[저장소별 Git 작업 큐](GitOperationQueue.md)의 조정자 계약과 DI Singleton 등록을 맡는다. `Dignus.Collections.ArrayQueue` 기반 단일 `async Task` 소비 루프를 저장소 루트마다 두고, 사용자 변경 명령 전체를 한 작업으로 받는다. 조정자 자체가 Git 명령이나 UI 새로 고침을 실행하지 않게 하고, 작업자 1·2에게 호출 계약을 먼저 전달한다. 메인 화면·충돌 해결 명령도 해당 계약에 연결한다.

소유 영역: `Bough.App/MainWindow.axaml`, `Bough.App/MainWindow.axaml.cs`, `Bough.App/ViewModels/MainWindowViewModel.cs`, 별도 충돌 해결 창 파일, `Bough.App/Views/RemoteOperationsView.axaml/.cs`와 `RemoteOperationWindow.axaml/.cs`. 작업자 1의 Local Changes·Git 서비스와 작업자 2의 ReferenceExplorer·History·설정·원격 작업 서비스·ViewModel은 수정하지 않는다. Design·Docs 문서는 총괄 PD가 관리한다.

왼쪽 저장소 목록의 경로 툴팁이 바로 아래 저장소 항목과 제거 버튼을 덮지 않도록 위치·지연·표시 조건을 조정한다. 전체 경로 확인 수단은 유지한다. 메인 상태 줄의 `해결되지 않은 충돌이 없습니다.` 같은 정상·빈 상태는 숨기고 줄이 빈 높이를 차지하지 않게 하되, 오류·진행·사용자 조치가 필요한 메시지는 유지한다.

1. 작업자 1·2의 ViewModel 생성자·서비스 API·이벤트 계약을 받아 Resolve를 제외한 상위 탐색, 저장소 전환과 새로 고침을 메인 화면에 연결한다. 두 작업자의 소유 파일에 변경이 필요하면 직접 고치지 않고 담당자에게 계약을 요청한다.
   작업자 1의 Stash 작업 결과 계약에 맞춰 `MainWindowViewModel`의 `LocalChanges.Stashes.WorktreeChanged += OnStashWorktreeChangedAsync` 구독과 이벤트를 통한 전체 새로고침을 없앤다. 호출부에서 Save·Apply·Pop·Drop별로 실제 필요한 Local Changes·Stashes·충돌 상태만 명시적으로 갱신한다. 동일한 작업 트리 상태를 연속으로 다시 읽지 않고, 저장소가 바뀐 뒤 늦게 끝난 작업 결과는 현재 저장소에 적용하지 않는다.
2. [화면과 동작](GitClientWorkflow.md)에 따라 `Open in ▾`·`Console`을 전체 상단 바 우측 끝에 한 번씩 배치하고 상단 Refresh 아이콘을 제거한다. 참조 탐색 머리글의 중복 버튼 제거는 작업자 2가 맡는다. 앱 창으로 돌아올 때 외부 변경을 다시 읽고, 중복·진행 중 새로 고침을 피하며, `F5` 수동 새로 고침을 유지한다. 저장소 미선택·좁은 창·키보드 접근성을 확인한다.
   작업자 1의 보관 창처럼 앱 내부 모달을 닫고 메인 창으로 돌아올 때는 활성화 이벤트만으로 새로고침하지 않는다. 보관 성공은 작업 자체의 갱신에 맡기고 Cancel·창 닫기에서는 갱신을 건너뛴다. 외부 앱에서 돌아온 경우의 새로고침은 유지한다.
3. [충돌 해결 창 진입](ConflictEntry.md)에 따라 메인 Resolve 탭과 빈 충돌 페이지를 없애고 기존 해결 UI를 저장소에 속한 별도 창으로 옮긴다. 실제 충돌을 감지할 때 한 번만 자동으로 열고 Local Changes의 선택 파일 진입을 연결한다. 창 중복·반복 자동 열기·저장소 전환·미저장 편집 닫기를 처리한다.
4. 지금은 메인 탐색·도구막대·충돌 창 연결을 마무리한다. 필요한 경우 컴파일 확인만 하고, 임시 저장소 시나리오 검증과 Stage All 성능 측정은 안정화 단계로 미룬다. 이미 확인된 빌드 문제는 담당 작업자에게 전달한다.
5. [저장소 전환 응답성](RepositorySwitchResponsiveness.md)에 따라 저장소 선택 직후 경로·로딩 상태를 보여 주고 기본 Local Changes 화면을 우선 표시한다. Stash·참조·원격·충돌 조회를 모두 직렬로 기다리는 현재 `OpenRepositoryAsync` 경로를 나누고, 로딩 중 재선택하면 마지막 저장소만 화면에 반영한다. 작업자 1·2의 영역별 로딩 계약을 사용한다.
6. [StringHelper의 Dignus DI 적용](StringHelperDependencyInjection.md)에 따라 앱 시작 지점에서 언어 값과 `StringHelper`를 등록·해석하고, MainWindow에서 `new StringHelper(...)`를 제거한다. 이 변경은 작업자 3 소유의 앱 구성 지점과 MainWindow에 한정하며 다른 작업자의 ViewModel 생성 코드는 그대로 둔다.
   `MainWindow.axaml`의 `AVLN3001`은 런타임 XAML 로더 사용 여부를 확인한 뒤, 불필요한 경고라면 해당 코드만 최소 범위에서 처리한다. 경고를 없애기 위한 무의미한 공개 기본 생성자는 추가하지 않는다.
7. 작업자 2의 원격 서비스·ViewModel 계약을 받아 [원격 작업과 Stash](RemoteAndStash.md)의 원격 작업 View·다이얼로그를 구현한다. 상단 중복 현재 브랜치와 자유 입력 대상 칸을 제거하고, Fetch·Fetch all·Pull 성공 시 자동 닫기, 기본 Push의 보낼 커밋 없음 표시, 실패·중단 시 결과 유지, Push의 수동 닫기를 담당한다. 내부 다이얼로그 종료 뒤 MainWindow 활성화로 중복 새로고침하지 않도록 연결한다. 작업자 2가 기존 View 파일 작업을 끝내고 소유권을 넘긴 뒤 수정한다.
   상단 원격 작업 영역은 **Fetch·Pull·Push 세 기본 버튼과 각 추가 동작 메뉴**로 간결하게 만든다. 현재 상시 노출된 `Fetch all`, `Pull from…`, `Push to…`, 조건부 Merge·Rebase 버튼, 원격 콤보박스, Prune 체크박스는 해당 작업 메뉴·대상 선택 창으로 옮긴다. 기본 작업과 기존 확인·진행 다이얼로그는 유지하고, 좁은 창에서도 버튼이 잘리지 않게 한다.
   [원격 작업과 Stash](RemoteAndStash.md)의 메뉴 표대로 세 개의 통합된 메뉴 버튼으로 표시한다. Fetch 메뉴의 원격 선택·Prune은 체크 상태가 남는 설정이고 Git 작업을 즉시 시작하지 않는다. Fetch all, Pull from…/Merge/Rebase, Push to…는 명시적 실행 경로다. 기본 Pull 클릭은 계속 Fast-forward only이며 메뉴의 Merge/Rebase를 영구 기본값으로 저장하지 않는다. 메뉴를 열어도 어떤 동작이 실행되고 어떤 항목이 설정만 바뀌는지 문구로 구분한다.
   Fetch 메뉴의 Prune 선택은 [원격 작업과 Stash](RemoteAndStash.md)의 문구대로 **삭제된 브랜치 정리**로 짧게 쓰고, 다음 Fetch 때만 적용되며 내 로컬 브랜치·작업 파일은 삭제하지 않는다는 전체 설명을 툴팁에 보여 준다. 선택 상태는 메뉴를 다시 열어도 확인 가능하게 한다.
   메뉴 항목이 `Push to…`처럼 잘려 보인다는 보고를 반영한다. [원격 작업과 Stash](RemoteAndStash.md)의 완결된 짧은 이름(**보낼 대상 선택**, **받을 브랜치 선택**, **병합해서 받기**, **재배치해서 받기** 등)으로 바꾼다. 메뉴 항목과 체크 표시를 자르지 않고 필요한 폭을 확보하며, 오른쪽 화면 경계에서는 메뉴가 화면 안에 온전히 표시되게 한다. 긴 설명은 툴팁에 두되 필수 동작 이름을 툴팁에만 숨기지 않는다.
8. [화면 테마](AppearanceTheme.md)에 따라 `App.axaml`의 고정 Dark를 제거하고 밝음을 기본으로 저장·복원하는 테마 서비스와 밝음/어두움 공통 리소스를 소유한다. 시스템 설정 선택과 실행 중 테마 변경도 지원한다. 사용자가 제공한 밝은 탐색기 화면의 연한 하늘색 상단·푸른 회색 보조 영역·거의 흰색 작업면을 기준으로 현재 녹색 위주의 밝은 팔레트를 조정한다. 선택·포커스는 차분한 파랑, 본문은 진한 회청색으로 하고 성공·추가·삭제의 의미 색은 구분한다. 리소스 이름·설정 API를 작업자 1·2에게 전달한다. `MainWindow`, `ConflictWindow`, 원격 작업 View·다이얼로그, `RemoteTargetDialogs`와 작업자 3 소유 팝업의 고정 색을 두 팔레트에 연결한다. 기존 메인 ViewModel/DI 연결은 작업자 3이 맡고, 다른 작업자 View 파일은 수정하지 않는다. 테마 전환만으로 Git 상태를 재조회하거나 화면을 재생성하지 않는다.
9. [메인 창 ViewModel 역할 분리](MainWindowViewModelRefactor.md)에 따라 약 1,939줄인 `MainWindowViewModel`에서 충돌 문서 편집·저장과 저장소 목록 관리를 전용 ViewModel/컴포넌트로 옮긴다. `ConflictWindow`는 메인 전체 대신 충돌 ViewModel을 바인딩하고, 메인은 저장소·화면 전환과 자식 화면의 명시적인 갱신 순서를 조정한다. 현재 진행 중인 테마·원격·Stash 연결 변경을 잃지 않도록 같은 파일의 최종 소유자인 작업자 3이 처리한다. 단순 `partial` 분할이나 범용 이벤트 버스로 줄 수만 낮추지 않는다.
10. `GitRepositoryService`와 `GitCommandRunner`의 수동 팩토리 등록을 Dignus `[Injectable]` 어트리뷰트 방식으로 정리한다. 사용자가 지정한 `GitCommandRunner`는 `[Injectable(LifeScope.Transient)]`, `GitRepositoryService`는 앱 수명 동안 하나를 쓰는 Singleton으로 등록한다. 앱에서 Core 어셈블리의 어트리뷰트 등록을 실행하고 같은 타입의 기존 수동 등록은 제거한다. 모든 Runner가 현재 Git 실행 파일 경로 변경을 즉시 공유하도록 `GitExecutableSettings.Default` 인스턴스를 DI에 명시적으로 등록해 생성자에 전달한다. 사용처가 없는 기본 생성자는 제거해 DI가 잘못된 생성자를 선택할 여지를 없앤다. `GitSettingsService`도 같은 설정 인스턴스를 계속 사용해야 한다. 서비스나 ViewModel에서 새 컨테이너·서비스 로케이터·독립 설정 객체를 만들지 않는다.
11. [Git 실행 오류 문구의 다국어 처리](GitErrorLocalization.md)에 따라 `GitCommandRunner`의 모든 실행 경로에 반복된 한국어 고정 실행 실패 문구와 영어 고정 종료 코드 문구를 오류 식별자·인수로 바꾼다. Core에서 App 문자열 도우미를 참조하지 말고 앱의 표시 경계에서 `Datas/String.json` 템플릿으로 번역한다. 작업자 3의 UI 오류 표시 경로를 먼저 연결하고, 작업자 1·2 소유 화면에 필요한 변환 계약을 전달한다.

추후 안정화 검증 기준: 모든 화면에서 `Open in`·`Console`이 상단에 한 번씩만 보이고 Refresh 아이콘은 보이지 않는다. 앱에서 실행한 Git 작업 뒤 관련 화면이 갱신되고, 외부에서 파일·브랜치를 바꾼 뒤 앱으로 돌아오거나 `F5`를 누르면 선택 저장소의 상태를 다시 읽는다. 충돌 없는 저장소에는 Resolve 페이지나 해결 창이 보이지 않는다. 실제 충돌을 만든 임시 저장소에서는 해결 창이 한 번 열리고, 닫은 뒤 Local Changes에서 다시 열 수 있다.

## 총괄 PD: 기획과 검증 기준

1. Design 문서를 갱신하고 작업자 간 서비스·화면 계약과 진행 상태를 조율한다. 앱 코드의 구현과 최종 연결은 작업자에게 지시한다.
2. 동일한 저장소에서 Local Changes → Stage → Commit → All Commits, Branch 선택 → History 이동, 커밋 선택 → 파일 diff·트리 탐색 흐름의 검증 기준을 관리한다.
3. 기능 구성이 안정되면 Windows와 macOS의 터미널 실행 경로, Git 부재, 빈 저장소, 한글 경로 등의 검증을 작업자에게 요청한다.
