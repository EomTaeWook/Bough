# 브랜치·태그 이름 변경

## 화면과 범위

Git 참조 트리의 로컬 브랜치와 태그 우클릭 메뉴에 각각 **브랜치 이름 변경**, **태그 이름 변경**을 둔다. 메뉴 문구에 말줄임표나 대상 개수를 넣지 않는다.

입력 창에는 기존 이름, 새 이름과 변경 범위를 표시하고 **이름 변경**, **취소** 버튼을 둔다. 현재 브랜치와 다른 로컬 브랜치 모두 이름을 바꿀 수 있다. 이번 기능은 로컬 참조를 변경하며 원격 브랜치·태그를 자동으로 바꾸지 않는다. 원격 이름 변경은 새 참조 전송과 기존 참조 삭제가 필요한 별도 작업이다.

태그 창에는 **태그 참조 이름만 변경하며 기존 주석·서명은 유지됩니다.**라는 안내를 표시한다. 주석 태그 객체 안에 기록된 원래 이름은 그대로 남는다.

## 실행 계약

- 메뉴를 열 때 저장소 루트, 원래 참조 이름과 객체 해시를 고정한다. 다른 행 선택이나 저장소 전환으로 요청 대상이 바뀌지 않게 한다.
- 이름 변경은 저장소별 GitOperationQueue의 FIFO로 실행한다. 실행 직전에 저장소·원래 참조·객체 해시와 새 이름을 확인한다. 대상이 바뀌었거나 새 이름이 유효하지 않으면 이유를 표시하고 실행하지 않는다.
- 기존 목적지 참조를 덮어쓰지 않는다. 동일 이름 입력은 변경 없이 처리하고, 취소하면 참조를 바꾸지 않는다.
- 브랜치는 명시적인 기존 이름과 새 이름으로 `git branch -m`을 실행한다. 강제 이름 변경을 사용하지 않으며 Git의 브랜치 설정·reflog 이동을 따른다. 작업 파일, 커밋과 기존 upstream은 임의로 바꾸지 않는다. 다른 worktree 등 Git이 거부하는 상태는 실패 이유를 표시한다.
- 태그는 원래 객체 해시를 유지한 새 참조 생성과 기존 참조 삭제를 `git update-ref --stdin`의 한 트랜잭션으로 실행한다. 새 참조가 없고 기존 참조 해시가 일치할 때만 둘 다 반영한다. 실패하면 기존 참조만 사라지는 중간 상태를 남기지 않는다.
- 주석·서명 태그는 커밋으로 풀린 해시가 아니라 태그 객체 자체의 해시를 유지한다. 태그 객체를 새로 만들거나 서명을 재작성하지 않는다.
- 성공하면 참조 트리, History 참조 배지와 현재 브랜치 표시를 갱신한다. 이전 저장소의 늦은 응답을 현재 화면에 적용하지 않는다. 사용자 요청 결과·오류는 공통 좌하단 상태 영역에 표시한다.

## 검증 기준

현재 사용자 지시에 따라 검증을 실행하지 않는다. 아래 기준은 사용자가 검증을 다시 명시적으로 요청할 때 적용한다.

- 임시 저장소에서 현재·비현재 브랜치를 바꾸고 HEAD, upstream, reflog, 커밋과 작업 파일이 유지되는지 확인한다.
- 일반·주석 태그의 이름 변경 후 원래 객체 해시가 유지되고 원격 태그는 바뀌지 않는지 확인한다.
- 목적지 중복과 확인 후 원본 변경을 거부하며 태그 트랜잭션 실패 때 기존 참조가 유지되는지 확인한다.
- 확인 취소, 메뉴 대상 보존, 큐 실행과 참조·History 갱신을 확인한다.
