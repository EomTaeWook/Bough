# Fetch · Pull · Push · Stash

## 화면 위치와 공통 상태

현재 저장소의 상단 작업 영역에는 기본 동작 **Fetch**, **Pull**, **Push** 세 개만 나란히 둔다. 각 버튼의 추가 동작은 화살표 메뉴에 넣고, `Fetch all`·`Pull from…`·`Push to…`·`Pull Merge`·`Pull Rebase`를 상시 별도 버튼으로 늘어놓지 않는다. Fetch 메뉴에는 전체 가져오기·원격 선택·Prune, Pull 메뉴에는 다른 원격 브랜치에서 받기와 Merge·Rebase, Push 메뉴에는 다른 대상으로 보내기를 둔다. 기본 Pull은 Fast-forward only이며 버튼이나 툴팁에서 이를 알 수 있게 한다. upstream이 없는 기본 Pull·Push는 기존 대상 선택 창을 연다. 왼쪽 **Stashes** 항목과 **Local Changes**에서 Stash를 열 수 있다. 현재 브랜치는 왼쪽 브랜치 트리의 선택 표시로 확인하므로 원격 작업 영역 맨 위에 이름을 다시 표시하지 않는다. 연결된 upstream과 앞선/뒤처진 커밋 수는 원격 동기화 상태로 간결하게 보여 준다. 원격이 없거나 detached HEAD인 경우 가능한 동작만 활성화하고 이유를 안내한다.

세 작업은 각각 **하나의 메뉴가 있는 버튼**으로 보이게 한다. 버튼 본문을 누르면 기본 동작을 실행하고 같은 버튼의 화살표를 누르면 아래 메뉴가 열린다. 본문과 화살표를 분리된 여섯 버튼처럼 띄어 놓지 않는다. 메뉴에서 옵션만 고르는 항목은 즉시 Git 작업을 시작하지 않으며, 선택 표시가 메뉴를 다시 열어도 유지된다. 실행 항목은 대상과 방법이 명확한 이름으로 표시하고 그 항목을 누를 때만 실행한다.

메뉴 항목은 `Push to…`처럼 문장을 중간에서 끊은 이름 대신 **짧고 완결된 동작 이름**을 쓴다. 메뉴가 화면 오른쪽 끝에서 열려도 항목의 글자와 선택 표시가 온전히 보이도록 필요한 폭을 확보하고 화면 안쪽에 배치한다. 긴 설명은 툴팁이나 대상 선택 창에 두되, 툴팁을 보기 전에도 메뉴 항목만으로 다음 동작을 알 수 있어야 한다. 공간 부족을 글자 잘림이나 `…` 표시로 처리하지 않는다.

| 버튼 | 기본 클릭 | 메뉴에서 선택·실행할 항목 |
| --- | --- | --- |
| Fetch | 현재 선택된 원격에서 Fetch | **원격 선택**: 등록된 원격 중 하나를 고르고 선택 표시를 유지한다. **삭제된 브랜치 정리**: 다음 Fetch/Fetch all에 적용할 Prune 옵션을 켜거나 끈다. **모든 원격 가져오기**: 모든 원격에서 바로 가져온다. |
| Pull | 현재 브랜치의 upstream에서 Fast-forward only | **받을 브랜치 선택**: 받을 원격 브랜치를 선택 창에서 확인한 뒤 실행한다. **병합해서 받기**, **재배치해서 받기**: 그 실행에만 Merge 또는 Rebase를 사용한다. 기본 클릭의 Fast-forward only는 바꾸지 않는다. |
| Push | 현재 브랜치를 upstream으로 Push | **보낼 대상 선택**: 보낼 원격과 대상 브랜치를 확인 창에서 정한 뒤 실행한다. |

원격 선택과 Prune은 Fetch의 설정이다. Pull의 받을 브랜치·Merge·Rebase와 Push의 보낼 대상은 한 번의 작업에 사용할 대상이나 방식을 정하는 실행 경로다. 메뉴를 열거나 Fetch 원격·Prune을 고르는 것만으로 Pull/Push 대상이나 upstream을 바꾸지 않는다.

연결된 upstream이 있으면 `origin/main`처럼 **원격/브랜치를 읽기 전용**으로 표시한다. 상단에 Pull의 원본과 Push의 목적지를 함께 바꾸는 자유 입력 `Remote branch` 칸은 두지 않는다. Fetch의 원격 선택이 필요할 때는 등록된 원격 목록에서 고른다. Pull 대상을 바꾸려면 명시적인 대상 선택 창에서 기존 원격 브랜치를 고르고, 실행 전에 현재 브랜치와 가져올 대상을 함께 보여 준다. 첫 Push나 명시적인 다른 대상으로 Push할 때만 별도 창에서 원격과 대상 브랜치 이름을 선택·입력하고 유효성을 검사한 뒤 확인받는다. 입력만으로 현재 upstream 설정을 바꾸지 않는다.

Fetch·Pull·Push를 실행하면 작업 이름, 대상 원격·브랜치, 진행 상태를 보여 주는 **원격 작업 다이얼로그**를 연다. 상단에는 상시 비활성 `Cancel` 버튼을 두지 않는다. 다이얼로그의 **작업 중단** 버튼은 실행 중인 Git 작업에 중단을 요청하고, 실제로 종료될 때까지 결과를 기다린다. 이미 완료된 원격 결과를 되돌리는 동작으로 설명하지 않는다. **Fetch·Fetch all·Pull은 Git 작업과 후속 상태 갱신까지 성공하면 다이얼로그를 바로 닫는다.** Pull의 Fast-forward only·Merge·Rebase 모두 같은 규칙을 따른다. 실패·중단·부분 성공 또는 후속 갱신 실패는 자동으로 닫지 않고 원인과 결과를 읽을 수 있게 둔다. Push 성공의 닫기 방식은 현재 수동 닫기를 유지한다. 인증은 설정에 연결된 Git credential helper 또는 SSH를 사용하고, 자격 증명은 명령 로그에 노출하지 않는다. 명령 성공 후 History, 브랜치 트리, Local Changes를 새로 고친다. 작업 세션이 이미 읽은 원격 상태는 현재 저장소의 상단 Fetch·Pull·Push 영역에 즉시 반영한다. 같은 상태를 다시 읽느라 upstream과 앞선·뒤처진 커밋 표시를 늦추지 않는다.

다이얼로그의 진행 내용은 Git 작업이 끝난 뒤 한꺼번에 채우지 않는다. Git이 출력하는 진행 정보가 있으면 실행 중에 갱신하고, 출력이 없으면 현재 단계와 경과 시간을 표시한다. 전송 객체의 진행률을 파일별 다운로드 진행률로 바꾸어 표시하지 않는다. 원격 URL이나 인증 정보가 포함된 원문 로그는 그대로 노출하지 않는다.

## Fetch

- 기본 Fetch는 현재 브랜치의 upstream 원격을 대상으로 한다. upstream이 없거나 원격이 여럿이면 대상 원격을 선택한다. **Fetch all**은 Fetch 메뉴의 별도 선택지로 둔다.
- 가져온 원격 추적 브랜치와 커밋·태그 변경을 History에 반영한다. 기본 Fetch는 현재 로컬 브랜치와 작업 파일을 이동시키지 않는다. 원격에서 삭제된 참조를 정리하는 Prune은 별도 선택으로 둔다. [Git fetch 문서](https://git-scm.com/docs/git-fetch)
- Fetch 메뉴의 **Prune**은 **삭제된 브랜치 정리**처럼 짧고 뜻이 드러나는 이름으로 표시하고, 툴팁에 전체 설명을 둔다: "원격에서 이미 삭제된 브랜치의 로컬 원격 추적 표시를 다음 Fetch 때 정리합니다. 내 로컬 브랜치와 작업 파일은 삭제하지 않습니다." 체크만으로 즉시 정리하지 않으며, 선택된 상태에서 Fetch 또는 Fetch all을 실행할 때 `--prune`을 적용한다. 선택 상태를 메뉴를 다시 열어도 알아볼 수 있게 표시한다.
- 결과에는 갱신된 참조와 실패한 원격을 구분해 표시한다.

## Pull

- Pull은 현재 브랜치의 upstream에서 가져온 뒤 현재 브랜치에 통합한다. upstream이 없으면 원격과 기존 원격 브랜치를 선택하게 한다. 추적 중인 브랜치가 있어도 다른 대상을 선택하려면 별도 동작으로 명시한다. [Git pull 문서](https://git-scm.com/docs/git-pull)
- Pull 다이얼로그에는 **받는 원격/브랜치 → 현재 브랜치**, `가져오는 중`·`브랜치에 반영 중` 등 현재 단계를 표시한다. 가져온 커밋 수와 커밋 제목, 변경 파일 요약은 Git에서 확인할 수 있는 시점에 보여 주고 완료 뒤에도 볼 수 있게 한다. 아직 확인하지 못한 목록을 예상 결과처럼 표시하지 않는다. 진행 중에는 Git이 실제로 보고하는 전송 상태를 보여 준다.
- 기본 버튼은 **Fast-forward only**로 실행한다. 분기된 이력에서는 실패 이유와 **Merge** 또는 **Rebase** 선택지를 보여 주며, 사용자 선택 없이 전략을 바꾸지 않는다.
- 작업 파일 때문에 진행할 수 없거나 충돌이 생기면 상태와 Git 오류를 보여 준다. 실제 미해결 충돌 파일이 생긴 경우에만 [충돌 해결 창](ConflictEntry.md)을 열어 이어서 처리한다. 자동 stash나 강제 초기화를 수행하지 않는다.

## Push

- 기본 Push는 현재 로컬 브랜치를 설정된 upstream으로 보낸다. 첫 Push에서 upstream이 없으면 별도 창에서 원격과 대상 브랜치를 확인하고 성공 시 추적 관계를 설정한다. 다른 원격 브랜치로 보내는 동작은 기본 Push와 구분해 대상과 영향 범위를 확인한다. [Git push 문서](https://git-scm.com/docs/git-push)
- 현재 브랜치가 upstream을 추적하고 **그 upstream으로 보내는 기본 Push**에서 앞선 커밋 수가 `0`이면 보낼 새 커밋이 없다. 이때 Git Push 명령과 진행 창을 건너뛰고 **보낼 새 커밋 없음**을 간결하게 표시한다. 작업 트리의 수정·스테이징 파일은 커밋 전까지 Push 대상이 아니다. 다른 목적지로 보내거나 첫 Push처럼 upstream이 없어서 앞선 커밋 수를 판단할 수 없는 경우에는 이 조건으로 건너뛰지 않고 기존 대상 확인 흐름을 따른다. 실행 직전 상태가 바뀔 수 있으므로 실행 경로에서도 조건을 확인한다.
- 거부된 Push는 원격 변경 또는 권한 오류를 그대로 설명한다. 기본 UI에는 강제 Push와 원격 브랜치 삭제를 넣지 않는다. 태그 Push는 별도의 명시적 동작으로 설계한다.
- 성공 후 ahead/behind와 원격 참조를 다시 읽는다.

## Stash

- **보관**: Local Changes 상단 작업 영역의 **Stash** 버튼에서 별도 입력 창을 연다. 창에서 메시지를 입력하고 보관한다. 기본은 추적 중인 변경만 포함하며, **미추적 파일 포함**은 명시적으로 선택한다. 보관 전에 포함 대상과 작업 트리에서 사라질 변경을 보여 준다. Cancel·창 닫기는 변경을 만들지 않고 창을 닫으며, 창을 닫고 메인 창으로 돌아오는 것만으로 작업 트리·Stashes·참조를 다시 읽지 않는다. 성공하면 창을 닫고 Local Changes와 Stashes를 한 번 갱신하며, 실패하면 창에서 오류를 보여 준다. 외부 콘솔·편집기에서 돌아온 경우의 상태 갱신은 유지한다.
- **목록과 미리보기**: Stashes에는 메시지, 만든 시점, 당시 브랜치, 변경 파일·diff를 표시한다. 항목이 없으면 빈 상태를 보여 준다.
- **Apply**: 선택한 Stash의 변경을 적용하고 항목을 유지한다. **Pop**: 적용에 성공하면 항목을 제거한다. 충돌로 Pop이 실패하면 항목이 남을 수 있으므로 결과를 다시 읽고, 실제 충돌 파일이 있으면 [충돌 해결 창](ConflictEntry.md)을 연다. [Git stash 문서](https://git-scm.com/docs/git-stash)
- **Drop**: 선택한 항목을 지우기 전에 이름과 메시지를 보여 주고 확인을 받는다. 전체 Stash 삭제는 첫 구현에 넣지 않는다.
- 목록 번호 `stash@{n}`은 새 보관 뒤 바뀔 수 있다. 실행 직전에 선택 항목의 해시가 같은지 확인한다. 작업 뒤에는 실제 영향이 있는 화면만 아래 기준대로 갱신한다.
- Stash 작업 뒤 갱신 대상은 작업 종류별로 **호출 경로에 명시**한다. Save 성공은 Stash 목록과 작업 트리, Apply/Pop은 적용 결과에 따라 작업 트리·충돌 상태와 Stash 목록을 갱신한다. Drop 성공은 Stash 목록만 갱신한다. 취소나 Git 변경 전 검증 실패는 갱신하지 않는다. `Func<Task>` 이벤트의 모든 구독자를 `GetInvocationList()`로 순회하거나 이름만 바꾼 범용 콜백으로 숨기지 않는다. 작업 결과를 호출부로 돌려주고 상위 조정자가 필요한 화면의 구체적 갱신 메서드를 호출한다. 한 작업의 같은 Git 상태를 Local Changes와 메인 창이 각각 다시 읽지 않도록 갱신을 한 번만 조정한다.

## 검증 기준

- 임시 로컬 bare 원격에서 Fetch, Fast-forward Pull, 분기된 Pull, 첫 Push의 upstream 설정, 거부된 Push를 검증한다. 실제 원격에 시험 Push하지 않는다.
- 임시 저장소에서 추적/미추적 변경의 Stash 보관, Apply, Pop, 충돌 시 항목 유지, Drop 확인을 검증한다. 사용자의 실제 저장소에서 Stash/Drop을 시험하지 않는다.
- Git 명령은 저장소 루트에서 인수 배열로 실행한다. 비동기 작업 완료 시 다른 저장소로 전환했다면 이전 결과를 현재 화면에 적용하지 않는다.
