# 원격 변경 자동 확인

> 관련 흐름: [Fetch·Pull·Push](RemoteAndStash.md), [설정](GitClientWorkflow.md#settings-git과-계정)

## 목적과 설정

현재 열린 저장소에 받을 새 커밋이 있는지 주기적으로 확인하고 Pull 근처에 알려 준다. 사용자가 설정에서 켠 경우에만 백그라운드 Fetch를 실행한다.

- 기본값은 **꺼짐**, 기본 주기는 **5분**이다. 확인 주기는 1·5·10·30분 중 선택한다.
- 설정은 앱 전체에 적용하며 기존 Git 실행 파일·기본 Pull 방식과 같은 사용자 설정 파일에 저장한다. 기존 파일에 새 값이 없으면 꺼짐·5분을 사용한다.
- 켜기와 주기 변경은 즉시 반영한다. 켜진 상태로 저장소에 진입하면 최초 한 번 확인하고 이후 설정 주기로 확인한다.
- 앱 내부의 Bough 릴리스 업데이트와 사용자가 연 Git 저장소의 원격 확인은 서로 다른 기능이다.

## 실행 대상과 범위

- 현재 열린 저장소 하나만 확인한다. 현재 로컬 브랜치의 upstream이 가리키는 등록 원격을 사용한다.
- 자동 Fetch의 명시적 refspec은 해당 upstream 브랜치의 원격 추적 참조만 갱신한다. 사용자 지정 Fetch 매핑으로 로컬 브랜치를 바꾸지 않으며 표준 upstream 매핑을 사용할 수 없으면 수동 Fetch를 안내한다.
- 원격·upstream이 없거나 detached HEAD이면 자동 실행하지 않는다. 수동 Fetch와 기존 대상 선택은 유지한다.
- Fetch로 원격 추적 참조와 커밋을 받아 온다. Prune·Pull·Merge·Rebase·Push·upstream 변경은 자동 실행하지 않는다. 작업 파일·스테이징·현재 로컬 브랜치도 바꾸지 않는다.
- 기존 저장소별 Git FIFO의 한 작업에서 Fetch와 필요한 상태 조회까지 기다린다. 동일 저장소가 사용자 작업·초기 조회로 바쁘면 해당 주기는 건너뛰고 자동 요청을 쌓지 않는다.
- 자동 확인은 한 번에 하나만 실행한다. 끄기·저장소 전환·창 종료에서 해당 예약·실행만 취소하고 실제 종료를 기다린다. 이미 접수된 사용자 명령을 취소하거나 버리지 않는다.
- 한 번의 자동 확인에는 60초 제한을 두고 종료를 기다린다. 제한 시간이 지나도 설정 주기 자체를 짧게 바꾸거나 자동 재시도 요청을 쌓지 않는다.
- 설정·저장소·요청 수명이 바뀌면 늦은 성공과 실패를 현재 화면에 적용하지 않는다. A→B→A 전환도 이전 A의 실행 결과를 새 A의 결과로 사용하지 않는다.

## 표시와 오류

- 기존 원격 상태의 현재 브랜치 `Behind`가 양수이면 Pull 근처에 **받을 새 커밋 N개**를 표시한다. 앞선 커밋이 함께 있어도 받을 수를 표시하며 통합 방식은 기존 Pull 흐름에서 정한다.
- 수동 Fetch·Pull·Push도 같은 원격 상태를 갱신한다. 자동 확인 결과를 위한 별도 커밋 수 캐시를 만들지 않는다.
- 자동 확인 중에는 진행 대화상자·툴팁·토스트를 열지 않는다. 기존 사용자 작업의 성공·오류를 자동 확인의 성공 문구로 덮지 않는다.
- 실패를 새 변경 없음으로 표시하지 않는다. 원래 오류를 보존하고 원격 영역에 현재 언어의 조용한 실패 안내와 수동 Fetch 방법을 표시한다. 오래된 커밋 수를 방금 서버에서 확인한 값으로 설명하지 않는다.
- 확인 뒤 참조와 History는 기존 조회·dirty 계약으로 반영한다. Fetch가 작업 파일을 바꾸지 않았는데 Local Changes·충돌·설정을 다시 바인딩하지 않는다.

## 인증과 종료 수명

- 기존 Git credential helper와 SSH 인증을 사용하되 백그라운드 확인에서 인증 창·브라우저·콘솔 입력을 요구하지 않는다. 자동 실행의 자식 프로세스에만 비대화형 옵션을 적용한다. 수동 명령·시스템 환경·사용자 Git 설정은 유지한다.
- 자격 증명이나 원문 원격 주소·민감 진단을 새 상태·로그에 넣지 않는다. 인증이나 SSH 실행이 자동 확인에 적합하지 않으면 수동 Fetch를 안내하며 자동으로 다른 SSH 실행 파일이나 host-key 정책을 강제하지 않는다.
- 정상 닫기와 앱 업데이트 종료에서 새 자동 예약을 중단하고 기존 닫기·미저장 초안·사용자 Git 작업 보호를 유지한다. 닫기가 거절되면 열린 앱의 자동 확인 수명을 복구한다.

Git의 비대화형 환경과 GCM의 상호작용 옵션은 [Git 실행 문서](https://git-scm.com/docs/git), [Git Credential Manager 설정](https://github.com/git-ecosystem/git-credential-manager/blob/main/docs/configuration.md)을 따른다.

## 구현 경계

설정 저장·표시는 기존 Git Settings가 맡고, 타이머·취소·실행 순서는 목적별 Presenter가 맡는다. Core의 기존 Fetch와 단일 Git 작업 큐를 사용하며 새 범용 완료 모델·작업 큐·설정 저장소를 도입하지 않는다. 실제 반영·배포·미검증 상태는 [구현 현황](../Docs/CurrentStatus.md)에 기록한다.
