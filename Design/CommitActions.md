# 커밋·브랜치 우클릭 동작

## 목표

**History**의 커밋 행을 우클릭하면 그 커밋을 대상으로 하는 메뉴를 연다. 브랜치 트리의 항목을 우클릭하면 그 브랜치를 대상으로 하는 메뉴를 연다. 메뉴를 열 때 대상 커밋 해시 또는 참조 이름을 고정해, 이후 선택이 바뀌어도 다른 대상에 명령이 실행되지 않게 한다.

## 커밋 행 메뉴

| 항목 | 동작 | 표시 조건 |
| --- | --- | --- |
| SHA 복사 | 전체 커밋 해시를 클립보드에 복사 | 항상 |
| 여기에서 브랜치 만들기… | 이름을 입력받아 선택한 커밋에서 로컬 브랜치를 만들고, 전환 여부를 선택. 시작 커밋은 읽기 전용으로 표시 | 유효한 커밋 |
| 여기에 태그 만들기… | 이름을 입력받아 선택한 커밋을 가리키는 로컬 태그를 만든다. 대상 커밋은 읽기 전용으로 표시 | 유효한 커밋 |
| 이 커밋 체크아웃… | 선택한 커밋으로 **detached HEAD** 전환. 브랜치에서 벗어난다는 안내를 먼저 표시 | 유효한 커밋 |
| 이 커밋 되돌리기… | 선택 커밋의 변경을 취소하는 새 커밋을 현재 브랜치에 만든다. 대상과 영향 범위를 먼저 확인 | 유효한 커밋 |
| 현재 브랜치를 이 커밋으로 초기화… | Soft/Mixed/Hard 선택 대화상자를 열고 영향 범위를 확인한 뒤 실행 | 로컬 브랜치에 붙어 있을 때 |

`git switch --detach <sha>`는 브랜치를 이동시키지 않고 특정 커밋을 살펴보는 동작이다. 브랜치를 만들면서 전환할 때는 `git switch -c <name> <sha>`를 쓴다. [Git switch 문서](https://git-scm.com/docs/git-switch)

## 커밋 되돌리기(Revert)

선택한 커밋의 변경을 취소하는 **새 커밋**을 현재 브랜치에 기록한다. 기존 커밋과 원격 참조는 유지한다. 확인 창에 메뉴 시점의 저장소·현재 브랜치·HEAD·대상 SHA와 메시지를 표시한다. 일반 커밋과 루트 커밋을 지원하며, 병합 커밋은 비교 기준으로 삼을 부모를 번호·SHA·메시지와 함께 선택한다. 병합 커밋의 되돌리기는 이후 병합에서 가져올 변경에도 영향을 줄 수 있음을 안내한다. [Git revert 문서](https://git-scm.com/docs/git-revert)

- 작업 트리·인덱스가 변경 중이거나 다른 Git 작업이 진행 중이면 이유를 표시하고 시작하지 않는다. 사용자 변경을 자동으로 버리거나 보관하지 않는다.
- 확인한 저장소·HEAD·커밋·기준 부모를 고정하고 기존 저장소 FIFO에서 실행 직전에 다시 확인한다. `git revert --no-edit`를 사용하며 병합 커밋에만 명시적인 `--mainline`을 전달한다.
- 충돌이나 커밋 실패로 Revert가 진행 중이면 상태를 유지한다. 기존 충돌 창에서 해결·저장·스테이징한 뒤 **되돌리기 계속**으로 이어서 처리한다. 앱을 다시 열거나 저장소를 다시 선택해도 진행 상태와 계속·중단 진입을 표시한다.
- **되돌리기 중단**은 진행 중인 Revert를 취소하고 시작 전 상태로 돌아가는 영향을 확인한 뒤 실행한다. 충돌 편집기의 미저장 초안과 명시적 버리기 확인, 창 수명 보호를 유지한다.
- 계속·중단도 같은 FIFO에 들어가며 실행 직전에 해당 Revert와 현재 상태를 확인한다. 현재 저장소·요청이 달라진 늦은 결과를 새 화면에 적용하지 않는다.
- 실제 Git 성공 뒤 조회 실패는 새 커밋 생성의 실패로 바꾸지 않는다. 기존 상태 표시·새로 고침과 참조/History dirty 연결을 사용하고 새 범용 완료 계층이나 재시도 UI는 추가하지 않는다.

## 브랜치 항목 메뉴

| 항목 | 동작 |
| --- | --- |
| 이 브랜치로 전환 | 로컬 브랜치에 `git switch <name>` 실행. 현재 브랜치에는 비활성화 |
| 원격 브랜치 체크아웃… | 새 로컬 추적 브랜치의 이름과 원격을 확인하고 전환 |
| 이 브랜치에서 새 브랜치 만들기… | 시작점을 해당 브랜치로 고정해 읽기 전용으로 표시하고 새 이름을 받음 |
| 이름 복사 | 참조 이름을 클립보드에 복사 |

변경 중인 파일 때문에 Git이 전환을 거부하면 오류를 보여 주고 작업 트리를 그대로 둔다. 자동으로 변경 사항을 버리거나 stash하지 않는다. [Git switch 문서](https://git-scm.com/docs/git-switch)

## 현재 브랜치 초기화 대화상자

메뉴를 누른 즉시 reset을 실행하지 않는다. 대화상자에 **현재 브랜치 이름**, **선택한 커밋의 짧은 해시·메시지 첫 줄**, **작업 트리·인덱스 상태**를 보여 준다. 대상이 현재 HEAD와 같거나 detached HEAD이면 실행할 수 없다. 대상이 현재 HEAD의 조상이 아니면 단순히 “여기까지 되돌림”으로 표현하지 않고 브랜치가 다른 커밋으로 이동한다는 사실을 보여 준다.

| 모드 | 브랜치 위치 | 스테이징 | 작업 파일 |
| --- | --- | --- | --- |
| Soft | 대상 커밋으로 이동 | 유지 | 유지 |
| Mixed | 대상 커밋으로 이동 | 대상 커밋에 맞춤 | 유지 |
| Hard | 대상 커밋으로 이동 | 대상 커밋에 맞춤 | 대상 커밋에 맞춤 |

Hard는 작업 파일을 덮어쓸 수 있다. **Hard**를 고른 경우 영향 경고와 두 번째 확인을 요구한다. 실행 직전에 현재 브랜치·HEAD·선택 커밋·작업 트리 상태를 다시 확인한다. 명령이 실패하면 Git의 오류를 보여 주고 성공으로 처리하지 않는다. [Git reset 문서](https://git-scm.com/docs/git-reset)

## 메뉴 범위와 갱신

- 첫 구현에는 표의 동작만 노출한다. 참고 이미지의 Merge, Rebase, Cherry-pick, Patch 생성은 후속 설계와 구현이 끝난 뒤 메뉴에 추가한다. 동작하지 않는 항목을 활성 메뉴처럼 표시하지 않는다.
- 태그 생성은 [화면과 동작](GitClientWorkflow.md)의 로컬 일반 태그 규칙을 따른다. 메뉴를 연 커밋 해시를 고정하고, 중복 이름을 강제로 덮어쓰지 않는다. 성공하면 참조 트리와 History의 태그 배지를 갱신한다.
- 명령 성공 후 현재 브랜치 표시, History, Local Changes, 충돌 목록을 새로 고친다. 저장소가 바뀌거나 메뉴를 연 대상이 사라지면 실행을 중단한다.
- Git 명령은 저장소 루트에서 인수 배열로 실행한다. 테스트는 임시 저장소에서 수행하며 사용자의 실제 저장소에서 reset을 시험하지 않는다.
