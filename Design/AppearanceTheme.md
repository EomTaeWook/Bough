# 화면 테마

## 선택과 적용

- Bough는 새 설치와 기존 설정 값이 없는 사용자에게 **밝은 테마**를 기본으로 보여 준다. Git 설정과 별도로 Settings의 **화면 모양**에서 **밝음 / 어두움 / 시스템 설정**을 선택할 수 있다. 선택 즉시 열린 메인 창과 모든 팝업·다이얼로그에 적용하고, 앱을 다시 열어도 선택을 유지한다. 시스템 설정을 고른 경우에는 운영체제 테마 변경을 따른다.
- 테마 선택은 앱의 사용자별 로컬 설정에 저장한다. Git 저장소·전역 Git 설정에는 기록하지 않는다. 테마만 바뀔 때 저장소 상태를 다시 읽거나 ViewModel·화면 전체를 새로 만들지 않는다. 선택값 읽기와 적용은 첫 창을 표시하기 전에 끝내 화면이 어두웠다가 밝아지는 전환을 피한다.
- 기존 어두운 테마는 선택할 수 있게 유지한다. 운영체제 테마나 GitHub 계정 설정과 혼동하지 않게 한다.
- 밝은 테마의 시각 기준은 사용자가 제공한 탐색기 화면이다. 연한 하늘색의 상단 띠(참고 `#A7C6DB`), 그보다 밝은 푸른 회색의 보조 영역(참고 `#C8DBE9`), 거의 흰색인 작업 영역(참고 `#F7FAFC`)을 기본으로 한다. 전체를 녹색으로 물들이지 않고, 본문 글자는 진한 회청색, 선택·포커스는 차분한 파란색으로 구분한다. 이 색값은 방향을 위한 참고이며 모든 컨트롤에 그대로 복사하지 않고 역할별 공통 팔레트로 조율한다.

## 색상 계약

- 화면 색을 XAML과 C# 곳곳의 고정된 16진수 값으로 계속 추가하지 않는다. 공통 의미의 테마 리소스에 밝음·어두움 팔레트를 두고 메인 창, Local Changes, History, 참조 탐색, Settings, 원격 작업, Stash, 충돌 해결, 새 브랜치·대상 선택·큰 파일·폐기 확인 창에 같은 역할의 색을 적용한다. 배경/패널/입력칸/테두리/기본·보조 글자/선택/강조/비활성/오류·경고·성공을 구분한다.
- 밝은 팔레트에는 상단 띠·보조 영역·작업 캔버스·패널·입력면의 깊이 차이를 따로 둔다. 현재 `App.axaml`의 연녹색 선택면·초록 강조·누런 inset을 참고 이미지의 하늘색·푸른 회색 계열로 조정한다. 성공/추가/삭제 같은 의미 색은 파랑으로 일괄 치환하지 않고 초록/빨강을 유지하되 밝은 배경에서도 대비를 확보한다. 어두운 테마는 별도 팔레트로 남긴다.
- 상단 원격 작업 띠와 아래 화면 제목 줄이 같은 `Subheader` 색으로 이어지면 화면 계층이 흐려진다. 원격 띠 아래에는 한 픽셀의 분명하지만 차분한 경계색을 두고, `로컬 변경` 같은 화면 제목 줄은 흰색에 가까운 `Surface` 면으로 분리한다. 같은 원칙을 History·Stash·Settings의 제목 줄에도 적용해 화면을 바꿀 때 경계가 흔들리지 않게 한다. 두 테마 모두 선과 면의 차이가 보이되 두꺼운 강조선이나 새 고정 색을 추가하지 않는다.
- diff의 추가·삭제·hunk, 브랜치 그래프, 스테이징 상태, 버튼의 활성·비활성, 포커스와 선택 표시는 두 테마에서 모두 읽혀야 한다. 밝은 화면에서 연한 회색 글자나 밝은 노랑 버튼 글자가 사라지지 않게 전경색과 배경색을 함께 조정한다. 색만으로 상태를 구분하지 않도록 기존 텍스트·아이콘도 유지한다.
- 새 설정 UI의 선택값과 공통 팔레트의 리소스 이름은 작업자 3이 먼저 정해 작업자 1·2에게 전달한다. 작업자별 파일 소유 범위에서 고정 색을 해당 리소스로 바꾸고, 한 화면만 밝고 다이얼로그는 어두운 혼합 상태가 남지 않게 한다. 첫 화면 성능을 위해 테마 전환 시 Git/네트워크 조회와 무거운 화면 재구성은 하지 않는다.
- 실제 밝은 테마 화면에서 상단 바·저장소 목록은 밝지만 History 목록·커밋 상세는 어두운 채 남고, `Commit / Changes / File Tree` 탭·커밋 제목·SHA 일부가 어두운 배경에 어두운 글자로 표시된다. `HistoryView.axaml`과 `GitSettingsView.axaml`의 고정 배경·전경·경계 색, `HistoryReferenceItem`의 배지 색, `HistoryInspectionFileItem`과 `HistoryViewModel`의 diff 색, `HistoryGraphControl`의 선·점 색, `GitActionDialogs`의 경고·오류 색을 두 팔레트에 맞춘다. 텍스트와 그 배경은 같은 테마의 리소스로 짝을 맞추고, 기본 Fluent 컨트롤의 전경색에만 기대지 않는다.
- 히스토리의 `전체 / 현재 브랜치` 라디오, `Commit / Changes / File Tree` 탭, 커밋 메시지·SHA, `Expand all / Collapse all` 버튼과 변경 파일 Expander는 같은 밝은 테마 면 위에서 읽히게 한다. 기본 Fluent 컨트롤의 흰색 탭 띠·버튼과 어두운 사용자 지정 패널이 섞이는 현상을 없애고 선택·호버·비활성 상태의 전경/배경도 함께 지정한다. 작은 글자와 날짜·파일 경로의 대비를 유지한다.
- 밝음·어두움·시스템 설정을 실행 중 전환해도 현재 History 선택, 펼친 파일 목록, 스크롤 위치와 저장소 상태를 유지하면서 화면 색이 즉시 따라야 한다. ViewModel에 한 번 만든 고정 `SolidColorBrush`가 이전 테마 색으로 남지 않도록 참조 배지·diff 행·그래프 등 바인딩 모델과 C# 그리기 경로도 테마 변경을 반영한다. 테마별 표시 가능 여부를 작은 글자, 비활성 컨트롤, 선택 행, 툴팁·팝업까지 확인한다.
