# 충돌 해결 창 진입 흐름

## 화면 위치

- 메인 탐색에는 **Local Changes**와 **All Commits**를 둔다. **Resolve는 상시 표시하는 메인 페이지나 탭으로 두지 않는다.** 충돌 해결기는 현재 저장소에 속한 별도의 크기 조절 가능한 창으로 연다.
- 기존의 충돌 파일 목록, 양쪽 변경, 선택 버튼, 최종 파일 미리보기와 저장·스테이징 동작은 해결 창 안에서 계속 사용한다. 비교와 직접 편집에 필요한 공간을 확보한다.
- 충돌 파일이 없는 평상시에는 충돌 해결 창과 빈 충돌 패널을 보여 주지 않는다. 저장소를 열었을 때 기본 화면은 Local Changes다.

## 자동 열기와 다시 열기

1. 저장소를 열거나 새로 고친 뒤 Git의 **미해결 충돌 파일이 실제로 있는지** 확인한다. Pull·Merge·Rebase·Cherry-pick·Stash 적용 등 작업 이후에도 같은 상태 검사를 사용한다. 단순한 명령 오류나 Fetch만으로 해결 창을 열지 않는다.
2. 충돌이 새로 감지되면 해당 저장소의 해결 창을 한 번 연다. 이미 열려 있다면 파일 목록만 갱신하고 창을 중복 생성하지 않는다. 사용자가 닫은 뒤 같은 충돌 목록으로 새로 고침해도 반복해서 자동으로 열지 않는다.
3. 창을 닫아도 미해결 파일은 그대로 둔다. Local Changes에는 충돌 파일 수와 파일 목록을 표시하고, 파일 선택 또는 **Resolve** 동작으로 해결 창을 다시 열 수 있게 한다. 충돌이 없는 경우 이 진입점은 숨기거나 비활성화한다.
4. 해결 창을 처음 열 때는 충돌 파일 목록과 첫 파일을 선택한다. Local Changes에서 특정 파일로 열면 그 파일을 선택한다. 저장소가 바뀌면 이전 저장소 창의 비동기 결과를 현재 화면에 적용하지 않는다.

## 닫기와 완료

- 결과를 저장·스테이징하기 전 창을 닫으면 Git 파일과 인덱스는 변경하지 않는다. 창 안에서 편집 중인 내용이 있으면 닫기 전에 버릴지 확인한다.
- 파일을 해결하고 저장·스테이징하면 충돌 목록과 Local Changes를 다시 읽는다. 남은 파일은 같은 창에서 이어서 선택할 수 있다. 모두 해결되면 완료 상태를 보여 주고 메인으로 돌아간다.
- 충돌 감지, 창 열기, 저장 실패는 상태와 오류를 명확히 보여 준다. 자동 열기에 실패해도 Local Changes의 다시 열기 동작은 남긴다.

## 검증 기준

- 충돌 없는 저장소와 Fetch 후에는 해결 창이 뜨지 않고 Local Changes가 기본 화면이다.
- 임시 저장소에서 실제 병합 충돌을 만들면 해결 창이 한 번 열리고, 닫아도 충돌이 보존되며 Local Changes에서 다시 열 수 있다. 같은 상태의 반복 새로 고침은 창을 다시 띄우지 않는다.
- 두 파일 이상 충돌했을 때 파일 선택과 저장·스테이징 후 목록이 갱신된다. 저장소 전환 중 이전 저장소 창이 새 저장소를 덮지 않는다.
