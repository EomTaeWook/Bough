# 태그 삭제

## 진입과 확인

Git 참조 트리의 태그 행 우클릭 메뉴에 **태그 삭제** 하나만 둔다. 메뉴를 열 때 저장소와 태그를 고정하며, 이후 다른 행을 선택해도 삭제 대상이 바뀌지 않는다.

삭제 대화상자에서 **로컬 태그** 또는 **원격 태그** 중 하나를 선택한다. 기본값은 로컬이며 두 범위를 동시에 삭제하지 않는다.

**로컬 태그**는 선택한 태그 이름과 영향 범위를 확인한 뒤 로컬 참조만 삭제한다. 원격 태그, 같은 이름의 브랜치, 작업 파일은 유지한다. 태그가 가리키던 커밋을 초기화하거나 작업 트리를 체크아웃하지 않는다.

**원격 태그**를 선택하면 등록된 원격 선택과 서버 영향 안내를 표시한다. 해당 원격의 정확한 태그를 조회한 뒤 같은 대화상자에서 원격 이름·태그 이름·확인한 대상과 다른 사용자에게 영향을 준다는 설명을 보여 준다. 조회한 대상을 확인해야 삭제할 수 있다. 원격 태그만 삭제하며 로컬 태그는 유지한다. 원격이나 태그가 없거나 조회에 실패하면 이유를 표시하고 삭제를 비활성화한다.

삭제 범위나 원격을 바꾸면 이전 조회의 확인 상태를 버린다. 늦게 끝난 조회 결과로 다른 원격을 삭제 대상으로 승인하지 않는다. 대화상자 진입이나 기본 로컬 선택만으로 원격을 조회하지 않는다.

확인 버튼은 **삭제**, 보조 버튼은 **취소**로 둔다. 메뉴 문구에 대상 개수나 말줄임표를 덧붙이지 않는다. 취소하면 참조를 바꾸지 않는다.

## 실행과 갱신

로컬·원격 태그 삭제 모두 현재 저장소의 GitOperationQueue에 넣어 FIFO로 실행한다. 대기 중 태그나 원격 설정이 바뀌면 확인한 대상을 임의로 바꾸지 않고 거부한다.

로컬 삭제는 정확한 `refs/tags/<이름>`과 확인한 객체 해시로 실행한다. 주석 태그는 대상 커밋으로 풀린 해시가 아니라 태그 참조 자체의 객체 해시를 사용하며, 삭제 시에도 이전 해시를 원자적으로 확인한다.

원격 삭제는 확인한 원격 주소와 태그 객체 해시를 다시 검사하고, 정확한 태그 refspec과 명시적 lease를 사용한다. 확인 이후 서버의 태그가 바뀌었다면 삭제하지 않는다. 같은 이름의 브랜치를 삭제하거나 다른 원격에 요청을 보내지 않는다.

원격 조회·확인·삭제에는 같은 push 주소를 사용한다. fetch 주소가 다르더라도 삭제 대상을 혼동하지 않으며, push 주소가 여러 개면 대상 선택을 지원하기 전까지 삭제를 거부한다. 실행 직전 원격 설정을 다시 확인한 뒤 고정한 주소로 요청한다.

성공 후 참조 트리와 History의 참조 배지를 다시 읽는다. 화면에서 저장소가 바뀌었으면 이전 저장소의 결과로 새 화면을 덮지 않는다. 실패 이유와 성공 결과는 기존 공통 상태 영역에 표시한다.

## 검증 기준

현재 사용자 지시에 따라 검증을 실행하지 않는다. 아래 기준은 사용자가 검증을 다시 명시적으로 요청할 때 적용한다.

- 임시 저장소의 일반 태그와 주석 태그를 삭제하고 같은 이름의 브랜치·작업 파일이 유지되는지 확인한다.
- 임시 bare 원격의 태그만 삭제하고 로컬 태그가 유지되는지 확인한다.
- 확인 뒤 로컬 또는 원격 태그를 다른 객체로 바꾸면 삭제가 거부되는지 확인한다.
- 메뉴 대상 보존, 확인 취소, 큐 실행과 성공 후 참조·History 갱신을 확인한다.
