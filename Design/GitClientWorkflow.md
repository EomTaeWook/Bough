# Git 클라이언트 화면과 동작

## 목적과 화면 구조

Bough의 상위 화면은 **Local Changes**, **All Commits**로 나눈다. 왼쪽에는 저장소 선택과 Git 참조 탐색을 둔다. 상단에서 현재 저장소, 현재 브랜치, Git 실행 파일 상태를 확인할 수 있다. 커밋 그래프와 상세 화면은 기존 History를 **All Commits** 항목으로 연결한다. 충돌 해결기는 실제 충돌이 있을 때 별도 창으로 열며 [충돌 해결 창 진입](ConflictEntry.md)을 따른다.

**가볍고 빠른 반응이 Bough의 우선 목표다.** 저장소를 고르면 기본 Local Changes 화면과 사용 가능한 파일 상태부터 보여 주고, History·Stash·계정·원격 상세는 필요한 화면을 열 때 읽는다. 한 번의 사용자 동작 때문에 같은 Git 상태를 여러 번 읽거나 파일마다 Git 프로세스를 반복 실행하지 않는다. 긴 Git 작업과 외부 사진·계정 조회는 화면 입력을 막지 않고, 보이는 항목부터 제한된 수로 요청한다. 저장소·브랜치·화면이 바뀌면 불필요한 이전 요청을 취소하거나 결과를 버린다. 완료 뒤에는 영향을 받은 영역만 갱신한다. 기능이 안정되면 [저장소 전환 응답성](RepositorySwitchResponsiveness.md)을 포함해 체감 지연을 측정한다.

앱의 **전체 상단 바 우측 끝**에 참고 화면처럼 작은 아이콘과 짧은 레이블로 된 저장소 도구막대를 둔다. `Git references` 영역의 머리글에는 제목과 현재 브랜치만 남긴다. 탐색 화면을 바꿔도 도구막대는 같은 위치에 보인다.

| 상단 도구막대 동작 | 표시와 실행 |
| --- | --- |
| Open in ▾ | 바깥으로 여는 아이콘과 `Open in` 레이블. 메뉴에서 현재 저장소 루트를 파일 탐색기로 연다. 설정된 외부 앱이 생기면 그때 메뉴에 추가한다. |
| Console | 콘솔 아이콘과 `Console` 레이블. 현재 저장소 루트에서 터미널을 연다. 기존 Terminal 명령과 같은 동작이다. |

저장소가 선택되지 않았을 때는 두 동작을 비활성화한다. 키보드 포커스와 툴팁을 제공한다. 상단 공간이 좁으면 저장소 이름을 줄임표로 처리하거나 탐색 버튼 배치를 조정하되 도구막대가 가려지지 않게 한다. 같은 `Open in`·`Console` 버튼을 참조 탐색 머리글과 상단 바에 중복 배치하지 않는다.

상단의 **Refresh 아이콘은 제거**한다. Fetch는 원격 참조를 가져오는 동작이므로 로컬 파일·브랜치 상태를 다시 읽는 Refresh와 구분한다. 앱에서 실행한 Git 작업 뒤에는 관련 화면을 자동 갱신한다. 외부 에디터나 콘솔에서 바뀐 상태는 앱 창으로 돌아올 때 다시 읽되, 연속 활성화와 진행 중인 Git 작업으로 중복 갱신하지 않는다. 누락된 상태를 사용자가 직접 다시 읽을 수 있도록 `F5` 수동 새로 고침을 유지한다.

참고 이미지에서 가져올 요소는 왼쪽 탐색 항목, 브랜치 트리, 스테이징 전후 목록, 아래쪽 커밋 입력 영역이다. 색상과 픽셀 배치는 현재 Bough 테마에 맞춘다.

```text
저장소 / 설정
├─ Local Changes (기본 화면)
├─ All Commits
├─ Branches
│  ├─ 현재 브랜치 ✓
│  └─ 다른 로컬 브랜치
├─ Tags
├─ Remotes
│  └─ 원격별 추적 브랜치
├─ Stashes
└─ Submodules (있는 저장소에서만)
```

### 왼쪽 참조 탐색 트리

- 참고 화면처럼 **브랜치 → 태그 → 원격 → 스태시** 순서의 조밀한 접이식 트리로 표시한다. 각 섹션에는 펼침 화살표와 종류를 알아볼 수 있는 작은 아이콘을 둔다. 색상은 현재 Bough 테마에 맞추고, 글자 크기·간격·들여쓰기는 한눈에 계층이 읽히는 정도로 맞춘다.
- 브랜치와 태그는 섹션 바로 아래에 한 줄씩 둔다. 현재 브랜치는 굵은 글씨와 별도 표시로 구분한다. 원격은 `origin` 같은 원격 이름을 한 단계 아래에, 추적 브랜치를 그 아래에 둔다. 스태시는 비어 있어도 섹션 머리글을 보여 주며 펼쳤을 때 빈 상태를 알린다.
- 머리글의 화살표는 접기·펼치기, 항목의 클릭과 우클릭은 기존 탐색·명령 흐름을 따른다. 긴 이름은 줄임표와 전체 이름 툴팁을 제공한다. 키보드로 섹션과 항목을 이동하고 펼치거나 접을 수 있어야 한다.
- **브랜치** 섹션 머리글에 `+` 또는 `New branch` 버튼을 둔다. 버튼을 누르면 새 브랜치 입력 팝업을 열고, 트리 아래에 상시 표시된 이름·시작점·`Create and switch` 입력 폼은 제거한다. 브랜치 항목의 `이 브랜치에서 새 브랜치 만들기…` 메뉴도 같은 팝업을 연다. 원격 추적 브랜치 이름을 적는 상시 입력 폼 역시 해당 원격 브랜치 동작에서 열리는 대화상자로 옮긴다.
- 섹션 접힘 상태는 저장소별로 기억한다. Submodules는 있는 저장소에서만 같은 트리 규칙으로 표시한다. 화면 문구는 앱의 문자열 리소스를 사용한다.

## Local Changes

- 화면 본문은 **왼쪽 파일 목록 + 오른쪽 변경 코드 미리보기** 두 영역으로 둔다. 현재 오른쪽에 고정된 커밋·Stash 열을 없애고 그 너비를 코드 미리보기에 돌린다. 파일을 선택해 변경 내용을 읽을 때 코드가 가로로 충분히 보여야 한다.
- **커밋 영역**을 Local Changes 전체 너비의 하단에 둔다. 기본은 낮은 높이로 표시해 코드 미리보기 공간을 확보하고, 높이를 조절하거나 접을 수 있게 한다. 한 개의 여러 줄 커밋 메시지 칸, Amend, Commit을 표시한다. 접거나 파일 선택·탭을 바꿔도 작성 중인 메시지는 보존한다.
- Local Changes 상단 작업 영역에 **Stash** 버튼을 둔다. 누르면 메시지, 미추적 파일 포함 선택, 보관 대상 요약, 실행·취소가 있는 별도 입력 창을 연다. 기존의 상시 Stash 입력 폼은 제거한다. Stashes 탐색 목록과 Apply/Pop/Drop 화면은 유지한다. 참고 화면의 배치 방향을 따르되 다른 도구막대 기능이나 모양을 그대로 복제하지 않는다.
- Unstaged·Staged·충돌 파일이 있는 왼쪽 목록과 가운데 변경 미리보기 사이에 **드래그 가능한 세로 분할선**을 둔다. 현재처럼 파일 목록 폭을 `310`으로 고정하지 않는다. 사용자는 긴 경로를 읽기 위해 목록을 넓히거나 diff 공간을 확보하기 위해 좁힐 수 있다.
- 분할선에 크기 조절 커서와 키보드 조작을 제공한다. 목록·미리보기의 최소 폭을 지키고, 창 크기를 줄여도 내용이나 버튼이 잘려 사용할 수 없는 상태가 되지 않게 한다. 사용자가 조절한 폭은 화면 전환과 앱 재시작 후에도 복원한다.
- 좁은 목록에서 파일 경로를 줄임표로 표시하면 전체 경로를 툴팁으로 확인할 수 있어야 한다. Stage/Unstage 버튼은 목록 폭에 맞춰 배치하여 가로로 잘리지 않게 한다.
- 왼쪽 저장소 목록의 전체 경로는 필요할 때 확인할 수 있게 하되, 항목에 마우스를 옮기는 동안 툴팁이 바로 다음 저장소 행과 `×` 제거 버튼을 덮어 클릭을 방해하지 않게 한다. 길게 머문 뒤에만 표시하거나 현재 항목 바깥쪽으로 띄우는 등 목록을 연속해서 선택할 수 있는 배치를 쓴다.
- Git 작업의 상태 메시지와 진행 막대는 **왼쪽 사이드바 하단의 한 영역**에 표시한다. 브랜치 작업 중 문구를 참조 탐색 아래와 창 전체 하단에 중복 표시하지 않는다. 대기·진행·오류·사용자 조치가 필요한 메시지의 우선순위를 정해 같은 영역에서 보여 주고, 긴 문구는 툴팁이나 줄바꿈으로 확인할 수 있게 한다. 창 전체 폭을 쓰는 별도 하단 상태 줄은 두지 않는다.
- 상단 Fetch/Pull/Push 원격 작업 줄과 아래 화면 제목 줄은 같은 면으로 이어 보이지 않게 한다. 원격 작업 줄 하단에 얇은 경계를 두고, `로컬 변경` 등 화면 제목은 별도의 밝은 패널 면에 표시한다. 좌측 저장소 영역과 우측 내용의 시작선이 자연스럽게 이어져야 한다. [화면 테마](AppearanceTheme.md)를 따른다.
- 왼쪽 파일 목록은 위쪽에 **Staged**, 아래쪽에 **Unstaged**를 표시한다. Stage를 누른 파일은 위 목록으로, Unstage를 누른 파일은 아래 목록으로 이동해 선택 상태와 변경 미리보기를 이어서 확인할 수 있어야 한다. Staged가 비어 있으면 상단의 빈 목록이 절반 높이를 차지하지 않게 머리글만 간결히 표시하고 Unstaged에 공간을 준다. 충돌 파일이 있을 때만 별도 목록과 파일 수를 보여 주고, 선택한 파일의 해결 창을 열 수 있다. 충돌이 없으면 빈 충돌 패널은 숨긴다. [충돌 해결 창 진입](ConflictEntry.md)
- **Staged와 Unstaged 목록 사이**에는 드래그 가능한 가로 분할선을 둔다. 사용자는 위아래 파일 목록의 높이를 조절하고 각 목록을 독립적으로 스크롤할 수 있다. 두 목록에 파일이 있을 때는 각각 머리글과 최소한의 파일 행이 보이도록 최소 높이를 지킨다. 한쪽 목록이 비면 빈 영역은 머리글만 남겨 다른 목록에 공간을 주고, 파일이 다시 생기면 사용자가 조절한 비율이나 높이를 복원한다. `Staged` 목록의 고정 `MaxHeight` 때문에 드래그 범위가 막히지 않게 한다. 충돌 목록과 하단 커밋 영역, 좌우 분할선의 기존 조절 동작은 유지한다.
- **Staged 머리글 오른쪽**에 스테이징 해제 동작을 배치한다. 현재 목록 아래에 별도 줄로 있는 **선택 파일 스테이징 해제**와 **모두 스테이징 해제** 버튼을 머리글의 짧은 버튼으로 옮겨 파일 목록의 세로 공간을 확보한다. 선택 파일이 없으면 선택 해제만 비활성화하고, 스테이징된 파일이 없으면 두 동작을 숨기거나 비활성화한다.
- **Unstaged 머리글 오른쪽**에도 같은 방식으로 현재 목록 아래의 **선택 파일 스테이징**과 **모두 스테이징** 버튼을 옮긴다. 선택 파일이 없으면 선택 스테이징만 비활성화하고, 대상 파일이 없으면 두 동작을 숨기거나 비활성화한다. 두 머리글 모두 좁은 목록에서 제목과 버튼이 겹치거나 잘리지 않도록 짧은 표기와 전체 동작 설명 툴팁을 사용한다. 기존 명령과 실행 후 목록·미리보기 갱신 동작은 유지한다.
- **Unstaged 목록에서 여러 파일을 Ctrl/Shift 클릭이나 Ctrl+A로 선택**하고 `변경 폐기…`를 한 번에 실행할 수 있다. 단일 파일 선택도 같은 동작을 쓴다. 머리글 오른쪽에는 `↑` 선택 스테이징, `↑↑` 모두 스테이징, `X` 선택 폐기 버튼을 **세 개 모두 직접 표시**한다. `⋯` 메뉴로 스테이징 동작을 숨기지 않는다. 파일 우클릭 메뉴에도 같은 폐기 동작을 추가한다. 두 폐기 진입점은 같은 선택 집합과 확인 절차를 사용하며, 선택 수를 툴팁·확인 창에 명확하게 보여 준다. 좁은 파일 목록에서는 제목을 줄임표로 처리하고 버튼 폭·간격을 조절해 세 버튼의 클릭 영역이 겹치거나 잘리지 않게 한다. 각 아이콘의 전체 동작 이름을 툴팁과 접근성 이름으로 제공한다.
- Staged 파일 행의 우클릭 메뉴에는 해당 파일의 `스테이징 해제`를 제공한다. 우클릭한 행과 실제 명령 대상이 같아야 하며, 메뉴 이름이 비어 있는 항목이나 동작 없는 하위 메뉴를 보여 주지 않는다. Unstaged 파일 행의 우클릭 메뉴에는 `변경 폐기…`와 `무시`를 제공한다. 이미 선택된 행을 우클릭하면 다중 선택을 유지하고 그 집합을 대상으로 하며, 선택되지 않은 행을 우클릭하면 그 행 하나를 대상으로 한다. 메뉴를 연 시점의 경로 집합을 실행 대상으로 고정해 이후 선택 변화가 다른 파일에 영향을 주지 않게 한다. 폐기는 위의 확인 절차를 그대로 사용한다.
- `무시`는 **미추적 파일에만** 제공하고, `저장소에서 무시(.gitignore)`와 `이 컴퓨터에서만 무시(.git/info/exclude)`를 구분한다. 각 선택 파일의 저장소 상대 경로를 정확히 가리키는 규칙을 쓰며, 경로의 Git ignore 특수 문자를 이스케이프해 같은 이름의 다른 파일이나 폴더까지 무시하지 않는다. 여러 파일을 선택했다면 대상 경로와 규칙을 한 번 확인하고 한 번에 추가한다. 취소 시에는 파일·무시 규칙·화면 상태를 바꾸지 않는다. 성공하면 목록을 한 번만 갱신한다. 무시는 파일을 삭제하거나 자동 스테이징하지 않으며, `.gitignore`에 추가한 경우 그 파일의 변경은 일반 작업 변경으로 나타난다. 추적 중인 파일에는 무시가 적용되지 않으므로 해당 메뉴를 비활성화하고, 이 메뉴에서 인덱스의 추적 상태를 바꾸지 않는다. [Git ignore 문서](https://git-scm.com/docs/gitignore)
- 폐기 확인 창에는 **선택한 모든 저장소 상대 경로를 스크롤 가능한 목록**으로 보여 주고 추적 파일의 작업 파일 변경 복원과 미추적 파일 삭제를 개수·효과별로 구분한다. 확인은 전체 선택 집합에 대해 한 번만 받는다. 추적 중인 파일은 **스테이징되지 않은 작업 파일 변경만** 인덱스 상태로 되돌리고 이미 스테이징한 내용은 보존한다. 미추적 파일은 Git으로 복원할 수 없으므로 **파일 삭제**라고 명시한다. 충돌 파일은 대상에서 제외한다. 취소하면 Git·파일 상태를 바꾸거나 새로고침하지 않는다. 실행 직전 모든 대상의 상태·파일 내용·저장소 경계를 다시 확인하고 하나라도 달라졌으면 전체 실행을 중단하며 해당 경로를 표시한다. 실행 도중 실패해 일부만 처리됐으면 처리된 범위와 실패 경로를 알리고 상태·미리보기를 한 번 갱신한다. 성공 후에도 한 번만 갱신한다. 선택하지 않은 파일·폴더로 범위를 넓히지 않는다.
- 파일 선택 시 상태와 변경 내용을 보여 준다. 텍스트 diff의 **추가 줄은 초록색**, **삭제 줄은 빨간색**, 문맥 줄은 기본색, hunk 머리글은 별도 강조색으로 구분한다. `+++`·`---` 파일 머리글은 추가·삭제 내용 줄로 오인하지 않는다. 미추적 파일의 원문 미리보기는 줄이 `+`나 `-`로 시작해도 diff 색을 적용하지 않는다. 색을 적용해도 긴 줄의 가로 스크롤과 텍스트 선택·복사를 유지한다. 바이너리 파일은 변경 사실과 크기 등 확인 가능한 정보만 보여 준다. 새 파일, 삭제, 이름 변경, 부분 스테이징 여부도 구분한다.
- 파일별 Stage/Unstage와 전체 Stage/Unstage를 제공한다. **모두 스테이징**은 대상 파일을 모아 일괄 처리한다. 파일마다 `git add` 프로세스를 하나씩 순서대로 실행하지 않는다. 미해결 충돌 파일은 제외하고, 한글·공백·특수 문자 경로와 삭제·이름 변경 파일의 기존 동작을 유지한다. 작업이 끝나면 두 목록과 선택한 파일의 diff를 한 번 갱신하고, 진행 중 상태와 Git 오류를 해당 화면에 표시한다. [Git add 문서](https://git-scm.com/docs/git-add)
- 새로 버전 관리에 추가할 파일 중 **10 MiB 이상**인 파일이 있으면 선택 파일 스테이징과 모두 스테이징 전에 큰 파일 확인 창을 연다. 대상 파일의 저장소 상대 경로·크기를 목록으로 보여 주고, **계속 스테이징** 또는 **취소**를 고르게 한다. 모두 스테이징에서는 큰 파일들을 한 창에 모아 한 번만 확인한다. 확인 전에는 어떤 대상에도 `git add`를 실행하지 않으며, 취소하면 기존 인덱스를 포함한 Git 상태가 그대로 남는다. 이미 추적 중인 파일의 수정·삭제에는 새 파일 추가 경고를 반복하지 않는다. 목록이 길면 창 안에서 스크롤하고 한글 경로를 온전히 표시한다.
- 하단 커밋 영역에는 소스트리처럼 여러 줄을 입력할 수 있는 **커밋 메시지 칸 하나**, **Amend** 선택, Commit 버튼을 둔다. 별도의 커밋 제목·설명 입력칸은 두지 않는다. 메시지의 첫 줄은 히스토리의 요약으로 표시하고, 빈 줄 뒤의 내용도 같은 입력칸에 적는다. 메시지가 비어 있거나 스테이징된 변경이 없으면 Commit을 비활성화한다. Amend는 사용자가 직접 선택할 때만 수행하며 기존 커밋의 전체 메시지를 편집할 수 있게 한다.
- 커밋 영역의 상태 안내 문구와 Amend·Commit 컨트롤은 창이나 스플리터 폭이 줄어도 잘리지 않아야 한다. 안내 문구를 고정 폭의 좁은 버튼 열에 가두거나 높이를 제한해 문장 끝을 숨기지 않는다. 필요한 경우 입력칸 아래 전체 폭에 안내를 배치하고, 좁은 창에서는 컨트롤을 다음 줄로 보내며 영역 내부에서 스크롤할 수 있게 한다.
- 하단 커밋 패널의 **스플리터를 허용된 최소 높이까지 올려도** `이전 커밋 수정`과 `커밋` 버튼의 전체 높이와 클릭 영역을 항상 볼 수 있어야 한다. 버튼을 메시지 입력칸과 함께 스크롤 영역 아래로 밀어 넣지 말고, 머리글과 실행 컨트롤은 패널 안에 남긴다. 줄어드는 공간은 메시지 입력칸이 우선 사용하며 입력 내용은 칸 안에서 스크롤한다. 안내 문구가 여러 줄이거나 창 너비가 좁아지는 경우에는 필요한 최소 높이를 확보하거나 안내 문구 쪽을 독립적으로 스크롤해 실행 컨트롤이 잘리지 않게 한다. 저장된 패널 높이가 새 최소 높이보다 작아도 다시 열 때 올바르게 보정한다.
- 목록은 Git의 기계 판독용 `status --porcelain=v1 -z`를 기준으로 읽는다. 이름 변경의 두 경로, 공백·한글 경로, 미추적 파일을 처리한다. [Git status 문서](https://git-scm.com/docs/git-status)
- 모든 Git 작업은 저장소 루트에서 인수 배열로 실행한다. 명령 문자열을 셸에 이어 붙이지 않는다.

## All Commits와 참조

- All Commits 본문은 현재의 **좌우 2열** 대신 **위쪽 커밋 그래프·목록, 아래쪽 선택 커밋 상세**로 배치한다. 두 영역 사이에는 실제 **스플릿 패널(GridSplitter)**을 넣어 드래그로 양쪽 높이를 조절한다. 장식용 경계선이나 고정 높이 두 칸으로 대체하지 않는다. 창 크기가 작아도 두 영역의 최소 높이를 지키고 각각 독립적으로 세로 스크롤한다. 커밋 목록은 화면 너비를 사용해 그래프·참조·메시지를 읽기 쉽게 표시하고, 아래 상세의 Commit·Changes·File Tree 탭과 긴 diff는 창 바깥으로 늘어나지 않게 한다. 선택한 커밋과 목록 스크롤 위치는 스플리터 조절·탭 전환 뒤에도 유지한다.
- 기존 히스토리 그래프를 유지한다. 참조는 스크린샷처럼 **해당 커밋의 그래프 점 옆, 메시지 앞**에 작은 배지로 표시한다. 넓은 BRANCH / TAG 전용 칸이나 여러 줄로 쌓인 칩은 필요하지 않다. 기본 행에는 대표 참조 1~2개만 표시하고 나머지는 `+N`을 눌러 전체 목록을 본다. 현재 브랜치는 체크 표시, 로컬 브랜치·원격 브랜치·태그는 작은 아이콘/색으로 구분한다. `origin/HEAD` 같은 중복 심볼릭 참조는 기본 행에서 생략하되 전체 목록과 상세에서는 확인할 수 있다. 긴 이름은 줄임표와 전체 이름 툴팁을 제공한다. 참조가 많은 행도 그래프 선과 메시지 정렬이 유지되어야 한다.
- 히스토리 머리글에서 **전체**와 **현재 브랜치**를 전환할 수 있게 한다. 전체는 기존처럼 모든 참조의 커밋을 보여 주고, 현재 브랜치는 현재 `HEAD`에서 도달 가능한 커밋만 보여 준다. 병합된 커밋은 포함하고 다른 브랜치에만 있는 커밋은 제외한다. 선택한 범위가 눈에 보이게 표시되며, 범위를 바꾸면 첫 묶음부터 다시 읽고 목록·스크롤·선택 상태를 새 결과에 맞게 갱신한다. 브랜치를 전환했을 때 현재 브랜치 범위를 보고 있었다면 새 `HEAD` 기준으로 다시 읽는다. 커밋이 없는 브랜치에서는 오류 대신 빈 상태를 보여 준다.
- 커밋 목록은 사용자가 **아래쪽 끝에 가까이 스크롤하면 다음 묶음을 자동으로 불러온다.** 평상시의 `Load more commits` 버튼은 제거하고, 로딩 중에는 목록 아래에 간결한 진행 표시를 둔다. 더 불러올 커밋이 없거나 이미 로딩 중이면 추가 요청하지 않는다. 새 커밋을 붙일 때 현재 스크롤 위치·선택 커밋·상세 내용을 유지하고 첫 행으로 튀지 않게 한다. 실패하면 같은 위치에 오류와 **다시 시도**를 보여 주며 실패 상태에서 자동 재시도를 반복하지 않는다. 저장소를 바꾸거나 목록을 새로 읽으면 이전 저장소의 지연 응답을 적용하지 않는다.
- 히스토리 행에는 커밋 메시지의 첫 줄과 작은 작성자 아바타를 표시한다. 커밋 선택 시 상세 상단에 더 큰 아바타와 전체 메시지·작성자·날짜·해시·변경 파일을 표시한다. 사진이 없어도 로컬 식별 아이콘을 보여 주며 동작과 출처는 [히스토리 작성자 아바타](AuthorAvatars.md)를 따른다. 상세 텍스트는 선택해 복사할 수 있고 해시에는 **Copy hash** 버튼을 둔다. **Copy message** 버튼은 두지 않는다.
- 선택 커밋의 **Commit·Changes·File Tree** 탭에서 파일별 diff, 변경 파일 검색, 해당 커밋의 파일 트리와 파일 우클릭 메뉴를 제공한다. 상세 동작은 [커밋 상세와 파일 탐색](CommitInspection.md)을 따른다.
- 커밋이 없는 저장소에는 빈 상태를, 읽기 실패에는 실제 오류를 표시한다. 저장소를 바꾸면 이전 저장소의 선택과 기록을 지운다.
- 커밋 행과 브랜치 항목의 우클릭 메뉴에는 체크아웃·브랜치 생성·현재 브랜치 초기화 흐름을 제공한다. 동작과 확인 절차는 [커밋·브랜치 우클릭 동작](CommitActions.md)을 따른다.

## Branches, Remotes, Tags, Stashes

- **Branches**에는 현재 브랜치 표시와 로컬 브랜치 전환을 둔다. 로컬·원격 브랜치 행을 **한 번 왼쪽 클릭하면 선택만** 하고 Git 명령을 실행하지 않는다. **더블클릭, 우클릭 메뉴의 전환 항목, 선택 후 Enter**에서 체크아웃을 실행한다. 로컬 브랜치가 이미 현재라면 Git을 다시 실행하지 않는다. 더블클릭 때문에 같은 명령이 중복 실행되거나 잘못된 `작업 중` 오류가 나타나지 않게 한다. 원격 브랜치는 더블클릭·우클릭 메뉴에서 기존 추적 로컬 브랜치로 전환하거나 새 로컬 추적 브랜치 창을 연다. 전환 성공 후 현재 브랜치 체크 표시, 저장소 상태와 History를 새로 고친다. 변경 사항 때문에 Git이 거부하면 내용을 보존하고 실패 이유를 브랜치 영역에 보여 준다. 강제 전환은 기본 동작에 넣지 않는다. [Git switch 문서](https://git-scm.com/docs/git-switch)
- 브랜치 행의 파란 선택 강조는 탐색 포커스이며 실제 체크아웃 성공을 뜻하지 않는다. 현재 브랜치의 체크 표시는 Git이 확인한 브랜치에만 붙인다. 전환 동작을 실행했는데 실패하면 선택 강조만 남겨 성공처럼 보이지 않게 하고, 해당 브랜치 근처에 실패 이유와 현재 브랜치를 분명히 알린다. 변경 파일·미해결 충돌·진행 중 작업 때문에 거부되면 Git의 이유를 표시하고 사용자 동의 없이 stash·discard·강제 전환하지 않는다. 전환 성공 후에는 브랜치 체크 표시, History, Local Changes, 원격 상태를 같은 저장소 상태로 갱신한다.
- 전환 명령이 실행·새로 고침 중일 때 사용자가 다시 더블클릭하거나 우클릭 메뉴에서 다른 로컬 브랜치로 전환을 요청하면 `다른 Git 작업이 진행 중`이라는 오류만 표시하고 요청을 버리지 않는다. 전환 중에도 메뉴의 전환 항목은 입력을 받을 수 있어야 한다. **요청한 순서대로 FIFO 큐에 넣고 명시적으로 취소하지 않은 요청은 모두 처리한다.** `A→B→A`도 세 요청이다. 실행 차례에 이미 현재 브랜치라면 불필요한 Git 전환 명령을 생략할 수 있다. 대기 상태는 화면에서 확인할 수 있게 표시한다. 실제 Git 명령은 한 번에 하나만 실행하며 선택 강조를 체크아웃 성공으로 취급하지 않는다.
- 참조 트리에서 세로 스크롤바가 나타나도 행 오른쪽의 현재 브랜치 체크 표시와 브랜치 추가 `+` 버튼을 가리지 않는다. 우측 표시 영역은 스크롤바와 분리하고, 좁은 왼쪽 패널에서는 브랜치 이름만 줄임표로 줄인다. 전체 이름은 툴팁으로 확인할 수 있다.
- 새 브랜치 팝업에서 **입력 가능한 항목은 브랜치 이름만** 둔다. 시작점은 버튼에서 열면 현재 `HEAD`, 특정 브랜치나 커밋 메뉴에서 열면 선택한 항목으로 정하고 **읽기 전용 안내 문구**로 표시한다. `HEAD`를 수정할 수 있는 텍스트 입력칸은 두지 않는다. 팝업에는 **Create and switch**, **Cancel**을 두고 열릴 때 이름 칸에 초점을 준다. 빈 이름이면 생성 버튼을 비활성화하고, 기존 이름 충돌·유효하지 않은 이름·Git의 전환 거부는 팝업 안에서 설명한다. 성공 시 팝업을 닫고 브랜치 트리·현재 브랜치·History·Local Changes를 갱신한다. Cancel이나 닫기는 Git 상태를 바꾸지 않는다.
- **Remotes**는 원격 이름과 추적 브랜치를 계층적으로 보여 준다. 원격 추적 브랜치는 로컬 작업 브랜치가 아니므로 선택만으로 원격 참조 자체를 체크아웃하거나 이동시키지 않는다. 원격 브랜치를 활성화하면 해당 원격을 **실제로 추적 중인 로컬 브랜치**가 있는지 확인한다. 하나로 분명하면 그 로컬 브랜치로 전환하고, 이미 현재 브랜치라면 현재 상태임을 알린다. 예를 들어 로컬 `main`이 `origin/main`을 추적 중인 경우 `origin/main`에서 `main`을 중복 생성하지 않는다. 추적 중인 로컬 브랜치가 없으면 원격 브랜치를 시작점으로 새 로컬 추적 브랜치 생성 창을 연다. 입력 창에는 원격 브랜치를 읽기 전용으로, 입력칸은 **새 로컬 브랜치 이름**, 실행 버튼은 **만들고 전환**으로 표시한다. 추적 관계는 짧은 설명과 시작점에서 전달하고 버튼 문구에 중복하지 않는다. 실행 버튼을 주요 동작으로 시각적으로 구분하고 긴 브랜치 이름에서도 버튼을 온전히 표시한다. 제안 이름과 같은 로컬 브랜치가 이미 있어도 추적 관계를 확인하기 전에는 같은 브랜치로 단정하거나 덮어쓰지 않는다. 관계가 다르면 다른 이름을 제안하거나 기존 브랜치를 명시적으로 선택하게 한다. 브랜치 전환이 Git에 의해 거부되면 원래 작업 트리를 보존하고 오류를 보여 준다. 취소하면 브랜치와 작업 파일은 그대로 둔다.
- **Tags**는 태그 이름과 대상 커밋을 표시하고, 선택하면 해당 커밋으로 History를 이동한다. 태그 선택만으로 작업 트리를 바꾸지 않는다. 태그 섹션 오른쪽의 `+`와 섹션 우클릭 메뉴에서 현재 `HEAD`에 로컬 태그를 만든다. History 커밋 행의 `여기에 태그 만들기…`에서는 그 커밋을 대상으로 한다. 입력 창에는 **태그 이름**만 입력하고 대상은 읽기 전용으로 표시하며, 실행 버튼은 **태그 만들기**로 짧게 쓴다. 첫 구현은 메시지 없는 일반 태그로 하며 기존 태그를 덮어쓰거나 `-f`로 이동시키지 않는다. 이름이 비었거나 유효하지 않거나 중복되면 Git의 이유를 창 안에 표시한다. 성공하면 태그 트리와 History의 참조 배지를 갱신하고 로컬에만 생성됐음을 알려 준다. 생성·취소 모두 현재 브랜치와 작업 파일을 바꾸지 않는다.
- **Stashes**는 보관 목록과 변경 미리보기, Apply/Pop/Drop을 제공한다. 각 동작 뒤 작업 트리와 목록을 다시 읽는다.
- Fetch/Pull/Push와 Stash 보관·적용·삭제의 화면과 실행 조건은 [원격 작업과 Stash](RemoteAndStash.md)를 따른다.
- 섹션이 비어 있으면 빈 상태를 표시한다. 트리의 접힘 상태는 저장소별로 기억할 수 있다.

## Submodules

서브모듈은 **상위 저장소 안에 배치된 별도 Git 저장소**다. 상위 저장소는 서브모듈의 특정 커밋을 가리킨다. `.gitmodules`에는 경로와 URL이 기록된다. [Git submodules 설명](https://git-scm.com/docs/gitsubmodules)

- 서브모듈이 있을 때만 Submodules 섹션을 표시한다. 경로, URL, 상위 저장소가 기대하는 커밋, 현재 체크아웃 상태를 보여 준다.
- 미초기화 상태는 명확히 표시한다. 초기화·업데이트 같은 쓰기 작업은 별도 명령과 사용자 확인을 거친다.
- 서브모듈을 로컬 브랜치나 일반 폴더와 같은 것으로 표시하지 않는다.

## Settings: Git과 계정

- **화면 모양**에서는 [화면 테마](AppearanceTheme.md)에 따라 **밝음 / 어두움 / 시스템 설정**을 고른다. 기본은 밝음이며 변경은 즉시 모든 창에 적용되고 앱을 다시 열어도 유지된다.
- Git 실행 파일은 먼저 시스템 `PATH`에서 찾는다. 설정에서 실행 파일 경로를 직접 선택하고 **Test Git**으로 경로와 버전을 확인할 수 있다. 선택 결과와 오류를 보여 준다.
- 커밋 작성자의 `user.name`과 `user.email`은 현재 저장소 값과 전역 값을 구분해 표시한다. 저장 범위를 사용자가 선택한다. 값이 없으면 커밋 전에 안내한다. [Git config 문서](https://git-scm.com/docs/git-config)
- **Accounts**는 원격 URL, HTTPS 자격 증명 도우미 또는 SSH 인증 방식을 안내한다. 초기 구현은 Git의 기존 credential helper와 SSH를 사용한다. Bough 설정 파일에 암호·토큰을 직접 저장하지 않는다. [Git credentials 문서](https://git-scm.com/docs/gitcredentials)
- GitHub HTTPS 원격과 Git Credential Manager가 있으면 [GitHub 인증 계정 전환](GitHubAccountSwitching.md)에 따라 **현재 저장소에서 쓸 GitHub 계정**을 선택하거나 추가할 수 있게 한다. 커밋 작성자 설정과 인증 계정은 별도로 표시한다. GitLab 계정 연결과 SSH 키 전환 UI는 제공자별 방식이 정해진 뒤 추가한다. 계정 연결이 없어도 로컬 저장소 작업은 가능하다.

## Terminal

- 현재 저장소에서 상단 도구막대의 **Console**을 누르면 작업 디렉터리를 저장소 루트로 설정한다. 사용자가 명령을 입력하고 출력·오류·종료 상태를 볼 수 있어야 한다.
- 최종 목표는 앱 안의 대화형 터미널이다. Windows의 ConPTY, macOS/Linux의 PTY가 필요한 명령도 고려한다. 첫 구현은 운영체제 터미널을 저장소 루트에서 여는 동작으로 시작할 수 있다.
- 앱이 자동으로 명령을 입력하거나 임의의 Git 변경 작업을 실행하지 않는다. 터미널에서 돌아오면 저장소 상태를 새로 고칠 수 있다.
